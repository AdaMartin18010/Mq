## 2.15.1 压缩算法对比

### 算法特性

| 算法 | 压缩比 | 速度 | CPU消耗 | 适用场景 |
| ------ | -------- | ------ | --------- | --------- |
| **gzip** | 高 | 慢 | 高 | 高压缩比需求 |
| **snappy** | 中 | 快 | 低 | 实时场景 |
| **lz4** | 中 | 很快 | 很低 | 高性能场景 |
| **zstd** | 很高 | 快 | 中 | 平衡场景 |

---

## 2.15.2 Kafka压缩

### Producer压缩

```properties
# 启用LZ4压缩
compression.type=lz4

# 批量大小
batch.size=131072
```

### 压缩效果

- **LZ4**：压缩比约2-3倍，CPU消耗低
- **Snappy**：压缩比约2倍，速度较快
- **Gzip**：压缩比约3-4倍，CPU消耗高
- **Zstd**：压缩比与速度的平衡，逐渐成为生产首选

## 2.15.3 NATS压缩

### 消息压缩

```go
// NATS本身不提供压缩
// 可在应用层压缩
compressed := compress(data)
nc.Publish("topic", compressed)
```

### 建议

- 应用层压缩
- 使用LZ4或Snappy
- 大消息才压缩

## 2.15.4 RabbitMQ压缩

### 消息压缩

```python
import gzip

# 压缩消息
compressed = gzip.compress(message.encode())
channel.basic_publish(
    exchange='',
    routing_key='queue',
    body=compressed,
    properties=pika.BasicProperties(
        content_encoding='gzip'
    )
)
```

## 2.15.5 压缩选择指南

### 选择建议

1. **高吞吐量场景**
   - 使用LZ4
   - 低CPU消耗
   - 快速压缩

2. **高压缩比场景**
   - 使用Gzip或Zstd
   - 节省存储
   - 网络传输

3. **实时场景**
   - 使用Snappy
   - 平衡压缩和速度

---

## 2.15.6 压缩策略决策矩阵

### 决策表

| 场景 | 推荐算法 | 压缩位置 | 主要收益 |
| --- | --- | --- | --- |
| Kafka 高吞吐日志 | lz4 / zstd | Producer 端 + Broker 透传 | 降低网络/存储成本 |
| 实时在线服务 | snappy / lz4 | Producer 端 | 低延迟 |
| 冷存归档 | gzip / zstd | 应用层或后处理 | 最大化压缩比 |
| NATS 微服务消息 | lz4 | 应用层 | 小消息也受益 |
| RabbitMQ 大消息 | gzip / lz4 | 应用层 + content_encoding 标记 | 兼容性好 |
| 跨地域复制 | zstd | Broker/网络层 | 节省带宽 |
| 边缘到云窄带 | zstd / gzip | 应用层 | 降低流量成本 |

## 2.15.7 生产配置示例

### Kafka压缩配置

```properties
# 引用 config-templates/compression-config.properties / kafka-producer-config.properties
compression.type=lz4
batch.size=131072
linger.ms=50
buffer.memory=268435456
```

### NATS应用层压缩

```go
// 引用 config-templates/compression-config.properties 理念
import "github.com/pierrec/lz4/v4"

compressed := make([]byte, lz4.CompressBlockBound(len(data)))
n, err := lz4.CompressBlock(data, compressed, nil)
if err == nil {
    msg := nats.NewMsg("orders")
    msg.Header.Set("Content-Encoding", "lz4")
    msg.Data = compressed[:n]
    nc.PublishMsg(msg)
}
```

### RabbitMQ应用层压缩

```python
# 引用 config-templates/compression-config.properties 理念
import gzip

compressed = gzip.compress(json.dumps(payload).encode())
channel.basic_publish(
    exchange='',
    routing_key='orders',
    body=compressed,
    properties=pika.BasicProperties(
        content_type='application/json',
        content_encoding='gzip',
        delivery_mode=2
    )
)
```

## 2.15.8 压缩策略与性能调优

### 压缩与批处理协同

压缩收益与批量大小密切相关。Kafka Producer 的 `batch.size` 与 `linger.ms` 共同决定批次填充程度，批次越大，压缩比通常越高，但延迟也越大。性能调优时应在吞吐、延迟、CPU 之间做帕累托权衡。

```properties
# 引用 config-templates/performance-tune-config.properties 理念
kafka.producer.compression.type=zstd
kafka.producer.batch.size=262144
kafka.producer.linger.ms=20
kafka.producer.buffer.memory=536870912
```

在窄带或边缘场景，压缩可显著降低出口流量，与 [01-51-多云与边缘消息联邦技术](../01-基础概念与对比分析/01-51-多云与边缘消息联邦技术.md) 中的联邦设计形成互补。
