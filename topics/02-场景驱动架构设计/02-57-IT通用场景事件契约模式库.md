## 2.57.1 微服务命令/事件/查询三消息契约

同一领域对象常同时存在命令、事件、查询三种消息语义，混用是常见设计债务。

| 消息类型 | 语义 | 核心字段 | correlationId 用法 | 幂等键 |
| ---------- | ------ | ---------- | -------------------- | -------- |
| **Command** | 请求执行动作 | `commandType`、`payload` | 关联业务请求链路 | header.idempotency-key |
| **Event** | 已发生事实 | `eventType`、`subject`、`data` | 关联上游命令/事件 | CloudEvents `id` |
| **Query** | 请求读取状态 | `queryType`、`replyTo` | 关联查询与响应 | 请求端生成 |

```yaml
messages:
  PlaceOrderCommand:
    type: command
    headers:
      required: [trace-id, idempotency-key, correlation-id]
    payload:
      required: [commandType, orderRequest]
      properties:
        commandType: { const: PlaceOrder }
  OrderCreatedEvent:
    type: event
    headers:
      required: [trace-id, idempotency-key, occurred-at]
    payload:
      required: [eventType, subject, data]
      properties:
        eventType: { const: dev.acme.order.OrderCreated.v1 }
  GetOrderQuery:
    type: query
    headers:
      required: [trace-id, correlation-id, reply-to]
      reply-to: { description: 响应地址 }
    payload:
      required: [queryType, orderId]
```

**设计陷阱**：命令误用祈使式命名当事件；correlationId 在每次服务调用后重置；事件 payload 携带命令意图字段。

## 2.57.2 CDC 数据管道契约

CDC 事件是数据库行级变更的机器可读镜像。Debezium 的 envelope 字段已被下游流处理、湖仓、审计广泛消费【论证】。

| 字段 | 取值 | 含义 | 消费侧注意 |
| ------ | ------ | ------ | ------------ |
| `op` | c/u/d/r | create/update/delete/read | d 时 `after` 为 null |
| `before` | Object/null | 变更前行状态 | 需 `REPLICA IDENTITY FULL` 才有完整旧值 |
| `after` | Object/null | 变更后行状态 | c/r 时 `before` 为 null |
| `source` | Object | 连接器、库、表、LSN、txId 元数据 | 用于幂等、排序、血缘 |
| `ts_ms` | Long | Debezium 处理时间戳 | 排序优先用 `source.ts_ms` |
| `transaction` | Object（可选） | 事务 ID、total_order | 需 `provide.transaction.metadata=true` |

```yaml
cdcEvent:
  op: u
  before: { order_id: ORD-001, status: PENDING }
  after: { order_id: ORD-001, status: PAID }
  source:
    version: 3.1.0.Final
    connector: postgresql
    name: orders-db
    db: orders
    schema: public
    table: orders
    lsn: 123456789
    txId: 5521
    ts_ms: 1763467200123
  ts_ms: 1763467200456
  schemaVersion: orders.v2
  schemaChangeStrategy: forward_compatible
```

**设计陷阱**：用 `ts_ms` 当业务时间；UPDATE 忽视 `before` 不完整；schema 变更后消费者缺乏感知机制。

## 2.57.3 告警/通知契约

告警事件是“需要立即知晓的状态转换”，与业务事件在生命周期和扇出范围上不同。

| 字段 | 说明 | CloudEvents 映射 |
| ------ | ------ | ------------------ |
| `type` | 告警类型，反向 DNS | `type` |
| `severity` | critical/warning/info/resolved | extension |
| `source` | 产生告警的系统 | `source` |
| `subject` | 受影响实体 | `subject` |
| `alertBody` | 指标、阈值、建议动作 | `data` |

```yaml
alertEvent:
  specversion: "1.0"
  type: com.acme.alert.payment_latency_high.v1
  source: /acme/monitoring/prometheus
  id: a1b2c3d4-1234-5678-90ab-cdef12345678
  time: "2026-11-18T09:30:00Z"
  severity: critical
  subject: service/payment-api
  data:
    metric: http_request_duration_seconds_p99
    threshold: 500
    currentValue: 892
    suggestedAction: 扩容 payment-api 副本
```

**设计陷阱**：每条业务失败都发 critical；告警缺少 resolved 状态；告警 topic 与业务事件 topic 合并。

## 2.57.4 审计日志契约

审计事件的核心是“事后不可抵赖”，契约优先保证不可变性与可验证性。

| 字段 | 说明 | 与 02-50 衔接 |
| ------ | ------ | --------------- |
| `who` | 操作主体 | 避免明文 PII，可写主体键 |
| `when` | 业务发生时间 | 与 header.occurred-at 一致 |
| `what` | 对象、动作、结果 | 敏感值用加密引用 |
| `integrityHash` | 关键字段签名/哈希 | 支撑审计链完整性 |

```yaml
auditEvent:
  metadata:
    type: com.acme.audit.order_viewed.v1
    source: /acme/order-service
    id: aud-uuid-001
    time: "2026-11-18T09:30:00Z"
  who:
    principalType: user
    principalId: u-12345
  what:
    action: READ
    resourceType: order
    resourceId: ORD-001
    outcome: success
  integrity:
    algorithm: HMAC-SHA256
    hash: "sha256:abcdef..."
    keyId: kms-audit-key-2026-11
```

**设计陷阱**：审计事件含明文 PII；缺少完整性校验；审计 topic 使用普通短保留期。

## 2.57.5 任务队列 envelope

任务消息与事件消息的区别在于：任务有执行责任、截止时间、重试预算和幂等要求。

| 字段 | 说明 | 与 02-16 衔接 |
| ------ | ------ | --------------- |
| `task_id` | 全局唯一任务标识 | 兼作幂等键，重试时不变 |
| `task_type` | 任务类型 | 决定执行器与重试策略 |
| `deadline` | 最晚执行时间 | 过期转死信 |
| `retry_budget` | 剩余可重试次数 | 每次失败递减 |

```yaml
taskEnvelope:
  metadata:
    task_id: task-uuid-001
    task_type: send-email
    trace_id: trace-abc-123
  scheduling:
    created_at: "2026-11-18T09:30:00Z"
    deadline: "2026-11-18T09:35:00Z"
    priority: normal
  retry:
    max_attempts: 5
    remaining: 3
    backoff_strategy: exponential
    initial_interval_ms: 1000
    max_interval_ms: 30000
  payload:
    template_id: welcome-v1
    to: user@example.com
```

**设计陷阱**：业务 ID 直接替代 task_id；重试时不携带剩余预算；任务 payload 在重试间被修改。

## 2.57.6 Webhook 交付契约

Webhook 是推送式事件交付的常见形态。CloudEvents HTTP Webhook 规范定义了交付方法、授权模型与滥用防护握手【定理】。

| 关注点 | 设计项 | 说明 |
| -------- | -------- | ------ |
| 订阅注册 | callback URL、事件筛选、secret | 注册时完成验证握手 |
| 交付重试 | 指数退避、最大重试、410 终止 | 2xx 成功；410 Gone 表示废弃 |
| 签名验证 | HMAC-SHA256 签名头 | 接收方用 secret 校验 body |
| 终止策略 | 连续失败阈值 / 410 / 手动禁用 | 避免对失效端点无限重试 |

```yaml
webhookDelivery:
  subscription:
    id: sub-uuid-001
    callback_url: https://partner.example.com/events
    events: [order.created, order.cancelled]
    secret: ${WEBHOOK_SECRET_SUB_001}
  delivery:
    method: POST
    content_type: application/cloudevents+json
    headers:
      WebHook-Request-Origin: events.acme.com
  signature:
    algorithm: HMAC-SHA256
    header_name: X-Webhook-Signature-256
    payload_format: "sha256={hex_digest}"
  retry:
    max_attempts: 10
    initial_interval_ms: 1000
    terminal_http_codes: [410]
    circuit_breaker_failure_threshold: 5
```

**与 OpenAPI webhook 对照**：OpenAPI 3.x 的 webhooks 字段用于描述“有哪些回调”，不强制 HTTPS、无原生握手与签名；CloudEvents HTTP Webhook 则是跨组织交付的协议规范，强制 HTTPS 并定义 WebHook-Request-Origin/Allowed-Origin 握手。

**设计陷阱**：使用 HTTP 明文交付；签名只签 header 不签 body；收到 410 后继续重试。

## 2.57.7 模式库选型速查

| 场景 | 推荐模式 | 关键字段 | 参考 |
| ------ | ---------- | ---------- | ------ |
| 微服务命令 | 命令消息 | `commandType`、`idempotencyKey` | 02-54 |
| 微服务事件 | CloudEvents 信封 | `type`、`source`、`subject`、`data` | 01-30 |
| 微服务查询 | 请求-回复 | `queryType`、`replyTo` | 本模式库 |
| CDC 数据管道 | Debezium envelope | `op`、`before`、`after`、`source` | 01-31 |
| 告警/通知 | CloudEvents + severity | `type`、`severity`、`subject` | 本模式库 |
| 审计日志 | 不可变审计事件 | `who`、`when`、`what`、`integrityHash` | 02-50 |
| 任务队列 | 任务 envelope | `task_id`、`deadline`、`retry_budget` | 02-16 |
| Webhook 交付 | 订阅 + HMAC | `callback_url`、`secret`、`signature` | 本模式库 |
