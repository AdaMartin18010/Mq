## 2.14.1 去重场景

### 常见场景

1. **网络重传**
   - 网络故障导致重传
   - 需要去重处理

2. **系统重试**
   - 业务逻辑重试
   - 避免重复处理

3. **幂等性保证**
   - 确保操作幂等
   - 防止重复执行

---

## 2.14.2 去重方法

### 去重策略

1. **消息ID去重**
   - 使用唯一消息ID
   - 基于ID判断重复

2. **业务键去重**
   - 使用业务唯一键
   - 基于业务键判断

3. **时间窗口去重**
   - 时间窗口内去重
   - 过期自动清理

## 2.14.3 Kafka去重

### 幂等Producer

```java
// 启用幂等Producer
Properties props = new Properties();
props.put("enable.idempotence", true);
props.put("acks", "all");
props.put("retries", Integer.MAX_VALUE);

// 相同消息ID不会重复
producer.send(new ProducerRecord<>("topic", key, value));
```

### 消费者去重

```java
// 使用Redis存储已处理消息ID
Set<String> processedIds = redis.get("processed:ids");
if (!processedIds.contains(messageId)) {
    process(message);
    redis.sadd("processed:ids", messageId);
}
```

## 2.14.4 NATS去重

### 消息去重

```go
// 使用消息头存储唯一ID
msg := nats.NewMsg("orders")
msg.Header.Set("Message-ID", generateUUID())

// 消费者去重
processedIDs := make(map[string]bool)
if !processedIDs[msg.Header.Get("Message-ID")] {
    process(msg)
    processedIDs[msg.Header.Get("Message-ID")] = true
}
```

## 2.14.5 RabbitMQ去重

### 消息去重

```python
# 使用消息属性存储唯一ID
properties = pika.BasicProperties(
    message_id=str(uuid.uuid4()),
    delivery_mode=2
)
channel.basic_publish(
    exchange='',
    routing_key='orders',
    body=message,
    properties=properties
)

# 消费者去重
processed_ids = set()
if message_id not in processed_ids:
    process(message)
    processed_ids.add(message_id)
```

## 2.14.6 去重最佳实践

### 设计建议

1. **消息ID设计**
   - 全局唯一
   - 包含时间戳
   - 易于生成

2. **存储选择**
   - 内存：快速但易丢失
   - Redis：快速且持久
   - 数据库：可靠但较慢

3. **过期策略**
   - 设置TTL
   - 定期清理
   - 避免内存泄漏

## 2.14.7 去重策略决策矩阵

### 决策表

| 去重层级 | 适用场景 | 实现方式 | 可靠性 |
| --- | --- | --- | --- |
| Broker 原生幂等 | Kafka Producer 重试 | enable.idempotence=true | 高，Broker 维护 PID-Seq |
| 消息头 Message-ID | NATS / RabbitMQ | 应用层检查 Header/Property | 中，依赖存储 |
| 业务键幂等 | 数据库写入、支付扣款 | 唯一约束/状态机 | 高，业务级 |
| 时间窗口布隆过滤 | 高流量埋点 | Bloom Filter + TTL | 中，存在误判 |
| 事件溯源快照 | 聚合根状态恢复 | 版本号/快照 | 高，领域驱动 |

## 2.14.9 去重策略与幂等契约

### 幂等键设计

去重不仅是技术问题，也是契约问题。建议在事件契约中显式定义 `idempotencyKey` 字段，并在 AsyncAPI / OpenAPI 中声明其唯一性约束，使生产者和消费者对去重语义达成共识。

```yaml
# 引用 config-templates/event-contract-template.yaml 理念
components:
  schemas:
    OrderCreated:
      type: object
      required:
        - idempotencyKey
      properties:
        idempotencyKey:
          type: string
          format: uuid
          description: 用于消费者端去重的业务幂等键
```

幂等契约与 DSL 表达力边界密切相关，复杂去重规则可通过状态机形式化描述，详见 [01-44-DSL表达力边界与等价转换策略](../01-基础概念与对比分析/01-44-DSL表达力边界与等价转换策略.md)。
