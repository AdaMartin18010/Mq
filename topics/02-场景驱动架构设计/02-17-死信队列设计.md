## 2.17.1 死信队列概念

### 死信队列作用

1. **错误处理**
   - 收集处理失败的消息
   - 避免消息丢失
   - 便于问题排查

2. **重试管理**
   - 超过重试次数后进入死信队列
   - 避免无限重试
   - 人工介入处理

3. **监控告警**
   - 监控死信队列大小
   - 告警异常情况
   - 及时处理

## 2.17.2 Kafka死信队列

### 实现方式

```java
// 创建死信Topic
String dlqTopic = "dlq-" + originalTopic;

// 处理失败后发送到死信队列
try {
    process(record);
    consumer.commitSync();
} catch (Exception e) {
    // 发送到死信队列
    producer.send(new ProducerRecord<>(dlqTopic, record.key(), record.value()));
    consumer.commitSync();
}
```

### 配置建议

- 独立Topic存储死信
- 设置保留策略
- 监控死信数量

## 2.17.3 NATS死信队列

### JetStream死信

```go
// 配置死信主题
js.AddStream(&nats.StreamConfig{
    Name: "ORDERS",
    Subjects: []string{"orders.*"},
    MaxDeliver: 3,  // 最大重试次数
})

// 超过重试次数后自动进入死信
js.Subscribe("orders.*", func(msg *nats.Msg) {
    if err := process(msg); err != nil {
        msg.Nak() // 触发重试
    }
}, nats.MaxDeliver(3))
```

## 2.17.4 RabbitMQ死信队列

### 死信Exchange配置

```python
# 声明死信Exchange
channel.exchange_declare(exchange='dlx', exchange_type='direct')

# 声明死信队列
channel.queue_declare(queue='dlq', durable=True)

# 绑定死信队列
channel.queue_bind(exchange='dlx', queue='dlq', routing_key='error')

# 主队列配置死信Exchange
channel.queue_declare(
    queue='orders',
    durable=True,
    arguments={
        'x-dead-letter-exchange': 'dlx',
        'x-dead-letter-routing-key': 'error',
        'x-message-ttl': 60000  # 消息TTL
    }
)
```

## 2.17.5 死信队列最佳实践

### 设计建议

1. **死信队列设计**
   - 独立队列/Topic
   - 持久化存储
   - 设置保留策略

2. **监控告警**
   - 监控死信数量
   - 设置告警阈值
   - 及时处理

3. **处理流程**
   - 定期检查死信
   - 分析失败原因
   - 修复后重新处理

## 2.17.6 死信队列决策矩阵

### 决策表

| 触发条件 | 推荐系统/模式 | 关键配置 | 处理建议 |
| --- | --- | --- | --- |
| 消费失败超次数 | Kafka 独立 DLQ Topic | kafka.dlq.topic.prefix=dlq- | 人工复核后补发 |
| 消息超时未处理 | RabbitMQ DLX + TTL | x-message-ttl, x-dead-letter-exchange | 自动转储分析 |
| JetStream 达到最大投递 | NATS DLQ Subject | nats.dlq.max.deliver=3 | 自动进入死信流 |
| poison message | Kafka + 应用层过滤 | 错误类型白名单 | 隔离后告警 |
| 业务规则明确失败 | RabbitMQ DLX | requeue=false | 直接入死信 |
| 跨地域复制失败 | MirrorMaker 2 DLQ | 独立副本因子 | 延迟重放 |

## 2.17.7 生产配置示例

### Kafka死信Topic配置

```properties
# 引用 config-templates/dlq-config.properties
kafka.dlq.topic.prefix=dlq-
kafka.dlq.retention.ms=604800000
kafka.dlq.replication.factor=3
kafka.dlq.partitions=1
```

### NATS JetStream死信配置

```properties
# 引用 config-templates/dlq-config.properties
nats.dlq.enabled=true
nats.dlq.max.deliver=3
nats.dlq.subject.pattern=dlq.{original_subject}
```

### RabbitMQ死信Exchange配置

```properties
# 引用 config-templates/dlq-config.properties
rabbitmq.dlq.exchange.name=dlx
rabbitmq.dlq.exchange.type=direct
rabbitmq.dlq.queue.name=dlq
rabbitmq.dlq.queue.durable=true
rabbitmq.dlq.routing.key=error
```

## 2.17.8 死信队列与可观测性

### 死信监控设计

死信队列是系统健康的反向指标。应将其纳入统一可观测体系，包括死信数量、增长率、消息来源 Topic/队列、错误类型分布等维度。

```yaml
# 引用 config-templates/monitor-alert-config.properties 理念
alerts:
  - name: DLQHighRate
    expr: rate(dlq_messages_total[5m]) > 0.1
    for: 2m
    labels:
      severity: warning
    annotations:
      summary: 死信队列消息增长过快
```

死信队列设计需与可观测性体系、SLO 错误预算联动，详见 [01-33-可观测性与自治运维能力体系分析](../01-基础概念与对比分析/01-33-可观测性与自治运维能力体系分析.md)。
