## 2.23.1 追踪场景

### 常见场景

1. **问题排查**
   - 消息流向追踪
   - 性能瓶颈定位
   - 错误根因分析

2. **业务监控**
   - 业务流程追踪
   - 端到端延迟
   - 消息处理链路

3. **合规审计**
   - 消息审计日志
   - 操作追踪
   - 合规要求

### 追踪信息模型

【论证】消息追踪至少需要三类信息：

- **Trace ID**：全局链路标识
- **Span ID**：当前操作单元标识
- **Parent Span ID**：父子关系标识

在 MQ 场景下，还需要补充 **Topic/Queue/Subject**、**Partition**、**Offset/Seq** 等消息系统上下文，才能将分布式追踪与消息偏移关联起来。

## 2.23.2 追踪方案选型

### 方案对比决策表

| 方案 | 侵入性 | 精度 | 性能开销 | 适用阶段 | 推荐系统 |
| ---- | ------ | ---- | -------- | -------- | -------- |
| 自定义消息头 | 高 | 中 | 低 | 小型系统、定制需求 | 所有 MQ |
| APM Agent 自动埋点 | 低 | 高 | 中 | 生产环境全链路 | Kafka、RabbitMQ |
| OpenTelemetry 语义约定 | 中 | 高 | 中 | 云原生、多语言栈 | 所有 MQ |
| 日志关联（Trace ID 打日志） | 中 | 低 | 低 | 预算受限、审计为主 | 所有 MQ |

【论证】对于新系统，优先采用 OpenTelemetry 语义约定（见 01-50），可统一跨语言、跨中间件的语义；对于已有 APM 投入的系统，APM Agent 自动埋点落地最快；自定义消息头方案适合对字段、采样策略有特殊要求的场景。

### 采样策略决策表

| 采样策略 | 实现复杂度 | 优点 | 缺点 | 适用场景 |
| -------- | ---------- | ---- | ---- | -------- |
| 概率采样 | 低 | 实现简单，成本可控 | 可能漏掉尾部错误 | 高吞吐常规链路 |
| 速率限制采样 | 中 | 控制最大 span 数 | 突发流量下仍可能丢关键 trace | 入口网关 |
| 头部采样 | 低 | 决策早，开销小 | 无法感知尾部错误 | 通用默认 |
| 尾部采样 | 高 | 保留错误/慢 trace | 需要 Collector 缓冲，延迟增加 | 关键业务兜底 |

【论证】消息系统吞吐高，100% 采样通常不可持续；建议关键 topic 100% 采样，普通 topic 1%-10% 采样，错误路径通过 tail-based 兜底。

追踪配置优先引用 `topics/config-templates/trace-config.properties`：

```properties
# 消息追踪配置模板（引用 topics/config-templates/trace-config.properties）
trace.id.generator=uuid
trace.id.format=hex
trace.id.length=32

trace.sampling.enabled=true
trace.sampling.rate=0.01
trace.sampling.strategy=probabilistic

kafka.trace.enabled=true
kafka.trace.header.prefix=trace-
kafka.trace.headers=trace-id,span-id,parent-span-id

trace.tool=jaeger
trace.tool.endpoint=http://localhost:14268/api/traces
trace.storage.retention.days=7
```

## 2.23.3 追踪上下文注入与提取

### W3C Trace Context 注入

【论证】OpenTelemetry 推荐通过 W3C `traceparent`/`tracestate` 在消息头中传递追踪上下文，broker 不解析语义只负责透传，因此只要协议支持自定义 header/属性即可跨系统链路。

```java
// Kafka ProducerInterceptor 注入 trace context
public class TracingProducerInterceptor implements ProducerInterceptor<String, String> {
    private final W3CTraceContextPropagator propagator = W3CTraceContextPropagator.getInstance();

    @Override
    public ProducerRecord<String, String> onSend(ProducerRecord<String, String> record) {
        Map<String, String> carrier = new HashMap<>();
        propagator.inject(Context.current(), carrier, Map::put);
        carrier.forEach((k, v) -> record.headers().add(k, v.getBytes(StandardCharsets.UTF_8)));
        return record;
    }
}
```

### 六系统注入点决策表

| 系统 | 注入/提取位置 | 字段/Header 名 | 关键限制与说明 |
| ---- | -------------- | -------------- | -------------- |
| Kafka | `RecordHeader` | `traceparent`（也可带 `tracestate`） | 0.11+ 支持 headers；header 总大小受 `max.request.size` 与 broker `message.max.bytes` 限制 |
| RabbitMQ | AMQP `headers` | `traceparent`、`tracestate` | header 大小受 AMQP 帧限制（默认 131072 字节）；header 键需为字符串 |
| NATS | `nats.Header` | `traceparent` | NATS 2.x / nats.go 支持 headers；JetStream 透传 headers |
| Pulsar | `Message.properties` | `traceparent` | properties 为 `Map<String,String>`，值必须为字符串；大小受 broker 配置约束 |
| MQTT 5.0 | `User Properties` | `traceparent` | MQTT 5.0 原生支持；MQTT 3.1.1 无用户属性，需降级到 payload 前缀/主题后缀/外部关联表 |
| Redis Streams | Stream field | `traceparent` | 作为 `XADD` 的一个 field-value 对携带；消费端 `XREADGROUP` 后从 fields 提取 |

## 2.23.4 Kafka 消息追踪

### 实现方式

```java
// 添加追踪头
ProducerRecord<String, String> record = new ProducerRecord<>("orders", key, value);
record.headers().add("trace-id", traceId.getBytes());
record.headers().add("span-id", spanId.getBytes());
producer.send(record);

// Consumer 读取追踪头
for (ConsumerRecord<String, String> record : records) {
    String traceId = new String(record.headers().lastHeader("trace-id").value());
    String spanId = new String(record.headers().lastHeader("span-id").value());
    // 处理消息并传递追踪信息
}
```

### 集成 OpenTelemetry

```java
// 使用 OpenTelemetry 语义约定
Tracer tracer = GlobalOpenTelemetry.getTracer("kafka-producer");
Span span = tracer.spanBuilder("orders send")
    .setSpanKind(SpanKind.PRODUCER)
    .setAttribute("messaging.system.name", "kafka")
    .setAttribute("messaging.destination.name", "orders")
    .startSpan();
try (Scope scope = span.makeCurrent()) {
    producer.send(record);
} finally {
    span.end();
}
```
