## 2.29.1 监控场景与分层

### 常见场景

1. **性能监控**
   - 吞吐量、生产/消费速率、端到端延迟。
   - 发现瓶颈阶段：生产、网络、Broker、消费、业务处理。

2. **健康监控**
   - Broker 进程存活、集群元数据一致性、分区同步状态。
   - 磁盘、内存、连接数等资源饱和度。

3. **业务监控**
   - 关键 topic/队列消息量、Consumer Lag、业务处理成功率。
   - 端到端 SLA：P99 延迟、消息丢失率、重复率。

### 监控分层

【论证】消息系统可观测性应覆盖三层：

- **基础设施层**：CPU、内存、磁盘、网络。
- **中间件层**：Broker 指标、Topic/Queue/Stream 指标、连接数。
- **应用层**：消息处理延迟、业务处理成功率、端到端链路。

## 2.29.2 监控体系选型

### 体系对比决策表

| 体系 | 指标能力 | 链路能力 | 日志能力 | 上手成本 | 推荐场景 |
| ---- | -------- | -------- | -------- | -------- | -------- |
| Prometheus + Grafana | 强 | 弱 | 中 | 低 | 中小型集群、指标驱动 |
| OpenTelemetry + 后端 | 强 | 强 | 强 | 中 | 云原生、全链路可观测 |
| ELK Stack | 中 | 弱 | 强 | 中 | 日志审计、故障排查 |
| 商业 APM | 强 | 强 | 强 | 低 | 企业级、预算充足 |

### 可观测性三支柱

| 支柱 | MQ 场景落点 | 典型工具 |
| ---- | ------------ | -------- |
| Metrics | 黄金信号 + MQ 语义指标 | Prometheus + exporter |
| Traces | Producer→Broker→Consumer 链路 | OpenTelemetry / Jaeger |
| Logs | Broker 审计日志、应用消费日志 | Loki / ELK |

【论证】对于开源消息栈，推荐 Prometheus + Grafana 作为指标基座，OpenTelemetry 补齐分布式追踪；对于已有 ELK 投入的组织，可先将 MQ 日志接入 ELK，再逐步引入指标与链路。参见 [1.33 可观测性与自治运维能力体系分析](../01-基础概念与对比分析/01-33-可观测性与自治运维能力体系分析.md)。

## 2.29.3 核心指标与告警分级

### 核心指标

| 指标类别 | Kafka | RabbitMQ | NATS |
| -------- | ------ | -------- | ---- |
| 吞吐 | MessagesInPerSec / BytesIn/Out | publish / deliver rate | msgs_received / msgs_sent |
| 延迟 | request-latency-avg / 端到端 | queue deliver latency | RTT / consumer ack floor 滞后 |
| 积压 | consumer lag | messages_ready + unack | AckFloor 与 Delivered 差 |
| 健康 | UnderReplicatedPartitions / Offline | 节点状态 / 镜像队列同步 | /healthz / 集群节点数 |
| 资源 | CPU / 内存 / 磁盘 / 网络 | fd / 内存 / 磁盘 alarm | JetStream 存储/内存 |

### 告警分级

| 级别 | 判据示例 | 响应时限 | 示例场景 |
| ---- | -------- | -------- | -------- |
| P0 | 数据丢失/集群不可用 | 立即 | offline partitions、quorum 丢失 |
| P1 | 有损降级 | 30 分钟 | URP>0 超 10 分钟、consumer 全断 |
| P2 | 容量预警 | 工作日 | 磁盘 75%、backlog 增速 > 消费增速 |
| P3 | 趋势与卫生 | 排期 | ISR 频繁伸缩、证书 30 天到期 |

## 2.29.4 Kafka 监控

Kafka 通过 JMX 与 Kafka Exporter 暴露指标：

```java
// JMX 关键指标
kafka.server:type=BrokerTopicMetrics,name=MessagesInPerSec
kafka.server:type=BrokerTopicMetrics,name=BytesInPerSec
kafka.server:type=BrokerTopicMetrics,name=BytesOutPerSec
kafka.network:type=RequestMetrics,name=TotalTimeMs
kafka.log:type=Log,name=Size,topic=orders,partition=0
```

Prometheus scrape 配置：

```yaml
scrape_configs:
  - job_name: 'kafka-exporter'
    static_configs:
      - targets: ['localhost:9308']
```

## 2.29.5 NATS 监控

NATS 通过 `/varz`、`/connz`、`/jsz` 等 HTTP 端点自暴露指标：

```go
// NATS 监控端点
http://localhost:8222/varz   // 变量信息
http://localhost:8222/connz  // 连接信息
http://localhost:8222/jsz    // JetStream 统计
```

Prometheus 可直接 scrape `localhost:8222`（需启用 `-m` 参数）。

## 2.29.6 RabbitMQ 监控

RabbitMQ 通过管理 API 与 Prometheus Plugin 暴露指标：

```python
import requests

# 队列监控
r = requests.get('http://localhost:15672/api/queues', auth=('guest', 'guest'))
queues = r.json()

# Prometheus 端点
# http://localhost:15692/metrics
```

Quorum Queue 还需关注 Raft 日志同步状态与 GC 指标。

## 2.29.7 OpenTelemetry 与全链路追踪

OpenTelemetry 消息语义约定定义了消息系统的 span、metrics 与 trace context 传播方式。参见 [1.50 OpenTelemetry 消息语义约定与全链路追踪](../01-基础概念与对比分析/01-50-OpenTelemetry消息语义约定与全链路追踪.md)。

| 角色 | SpanKind | 典型命名 |
| ---- | -------- | -------- |
| Producer | PRODUCER | `orders send` |
| Consumer Receive | CONSUMER | `orders receive` |
| Consumer Process | CONSUMER/INTERNAL | `orders process` |

Trace context 通过消息 header 透传：Kafka 用 `RecordHeader`，RabbitMQ 用 AMQP `headers`，NATS 用 `nats.Header`，MQTT 5.0 用 `User Properties`。

```java
// Kafka ProducerInterceptor 注入 traceparent
propagator.inject(Context.current(), carrier, Map::put);
carrier.forEach((k, v) -> record.headers().add(k, v.getBytes(StandardCharsets.UTF_8)));
```

## 2.29.8 监控最佳实践

### 设计建议

1. **指标基线**
   - 基线取自过去 7 天同时间段均值，避免固定阈值误报。
   - 按 topic/queue、consumer group、region 聚合，控制基数。

2. **告警治理**
   - 每条告警必须关联 runbook。
   - 父级故障抑制子级告警；静默必须带到期时间与 owner。
   - 使用 SLO 燃尽告警替代固定阈值。

3. **三支柱联动**
   - Metrics 触发告警后，5 分钟内能定位到 Trace 与日志。
   - 日志中注入 `trace_id`/`span_id`，实现一键跳转。

### 配置模板引用

监控配置统一引用 `topics/config-templates/monitor-config.properties`：

```properties
# 消息监控配置模板（引用 topics/config-templates/monitor-config.properties）
prometheus.enabled=true
prometheus.port=9090
prometheus.scrape.interval=15s
prometheus.scrape.timeout=10s

kafka.monitor.enabled=true
kafka.exporter.enabled=true
kafka.exporter.port=9308
kafka.monitor.metrics=throughput,latency,error_rate,lag,connections

nats.monitor.enabled=true
nats.exporter.enabled=true
nats.exporter.port=7777
nats.monitor.metrics=throughput,latency,error_rate,connections,subscriptions

rabbitmq.monitor.enabled=true
rabbitmq.exporter.enabled=true
rabbitmq.exporter.port=9419
rabbitmq.monitor.metrics=throughput,latency,error_rate,queue_length,connections

monitor.metrics.throughput.enabled=true
monitor.metrics.latency.enabled=true
monitor.metrics.error_rate.enabled=true
monitor.metrics.resource.enabled=true
monitor.metrics.business.enabled=true

alert.enabled=true
alert.manager.url=http://alertmanager:9093
alert.rules.file=/etc/prometheus/alert_rules.yml
alert.notification.channels=email,dingtalk,wechat

alert.rule.latency.threshold=1000
alert.rule.error_rate.threshold=0.01
alert.rule.lag.threshold=10000
alert.rule.cpu.threshold=0.8
alert.rule.memory.threshold=0.8
alert.rule.disk.threshold=0.8

monitor.retention.metrics.days=30
monitor.retention.logs.days=7
monitor.retention.traces.days=3
monitor.sample.rate=1.0
```
