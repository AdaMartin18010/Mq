## 2.12.1 路由模式

### 常见路由模式

1. **直接路由**
   - 一对一映射
   - 简单高效
   - 适用：固定路由

2. **主题路由**
   - 基于主题匹配
   - 灵活性强
   - 适用：动态路由

3. **广播路由**
   - 一对多分发
   - 消息复制
   - 适用：通知场景

## 2.12.2 Kafka路由策略

### 分区路由

```java
// 自定义分区器
public class CustomPartitioner implements Partitioner {
    @Override
    public int partition(String topic, Object key, byte[] keyBytes,
                        Object value, byte[] valueBytes, Cluster cluster) {
        // 根据业务逻辑选择分区
        return key.hashCode() % cluster.partitionCountForTopic(topic);
    }
}
```

### 路由策略

- **Key路由**：相同Key路由到同一分区，保证分区顺序
- **轮询路由**：无Key时轮询分配，均衡负载
- **自定义路由**：实现Partitioner接口，按业务字段分区

## 2.12.3 NATS路由策略

### Subject路由

```go
// 通配符路由
sub, _ := nc.Subscribe("orders.*.created", func(msg *nats.Msg) {
    // 处理订单创建消息
})

// 队列组路由（负载均衡）
sub, _ := nc.QueueSubscribe("orders.process", "workers", func(msg *nats.Msg) {
    // 负载均衡处理
})
```

### 路由特性

- **通配符支持**：`*`（单级）、`>`（多级）
- **队列组**：负载均衡路由
- **请求/回复**：自动路由回复

## 2.12.4 RabbitMQ路由策略

### Exchange路由

```python
# Direct Exchange（直接路由）
channel.exchange_declare(exchange='direct_logs', exchange_type='direct')
channel.basic_publish(exchange='direct_logs', routing_key='error', body=message)

# Topic Exchange（主题路由）
channel.exchange_declare(exchange='topic_logs', exchange_type='topic')
channel.basic_publish(exchange='topic_logs', routing_key='order.created', body=message)

# Fanout Exchange（广播路由）
channel.exchange_declare(exchange='fanout_logs', exchange_type='fanout')
channel.basic_publish(exchange='fanout_logs', routing_key='', body=message)
```

## 2.12.5 路由选择指南

### 选择建议

| 场景 | 推荐路由 | 系统 |
| ------ | --------- | ------ |
| **固定路由** | 直接路由 | Kafka分区、RabbitMQ Direct |
| **动态路由** | 主题路由 | NATS Subject、RabbitMQ Topic |
| **广播通知** | 广播路由 | RabbitMQ Fanout、NATS Pub/Sub |
| **负载均衡** | 队列组 | NATS Queue Group、RabbitMQ Queue |

---

## 2.12.6 路由策略决策矩阵

### 决策表

| 业务诉求 | 推荐模式 | 适用系统 | 关键考量 |
| --- | --- | --- | --- |
| 按业务键保序路由 | Key-Hash 分区 | Kafka | 避免热点，需合理分片 |
| 按地域/动作动态分发 | Topic/Subject 通配符 | NATS、RabbitMQ Topic | 命名规范需统一 |
| 广播通知所有消费者 | Fanout / Pub-Sub | RabbitMQ、NATS Core | 无持久化时可能丢失 |
| 同组内负载均衡 | Queue Group / Consumer Group | NATS、Kafka、RabbitMQ | 注意重平衡成本 |
| 多条件组合过滤 | Headers Exchange | RabbitMQ | 规则复杂时性能下降 |
| 事件契约驱动路由 | AsyncAPI + Schema 路由 | 通用 | 需配合 DSL 设计 |

## 2.12.7 生产配置示例

### Kafka自定义分区器

```properties
# 引用 config-templates/routing-config.properties / partition-config.properties
partitioner.class=com.example.CustomPartitioner
kafka.routing.strategy=key-hash
kafka.routing.key.field=id
kafka.routing.partition.count=6
```

### NATS Subject路由

```conf
# 引用 config-templates/routing-config.properties
nats.routing.strategy=subject
nats.routing.subject.pattern=orders.{region}.{priority}
nats.routing.queue.group.enabled=true
nats.routing.queue.group.name=workers
```

### RabbitMQ Exchange路由

```python
# Topic Exchange 生产级声明
channel.exchange_declare(
    exchange='orders',
    exchange_type='topic',
    durable=True,
    auto_delete=False
)

channel.queue_declare(queue='orders-asia-high', durable=True)
channel.queue_bind(
    exchange='orders',
    queue='orders-asia-high',
    routing_key='orders.asia.high.*'
)
```

## 2.12.8 路由策略与DSL契约

### 事件契约驱动路由

在事件驱动架构中，路由键不应仅由实现方便决定，而应由事件契约统一约定。AsyncAPI 或内部 DSL 可显式声明通道、绑定与路由规则，使路由策略成为可审查、可演化的设计资产。

```yaml
# 引用 config-templates/asyncapi-contract-skeleton.yaml 理念
asyncapi: '2.6.0'
channels:
  orders.{region}.{priority}:
    parameters:
      region:
        schema:
          type: string
          enum: [asia, eu, na]
      priority:
        schema:
          type: string
          enum: [high, normal, low]
    subscribe:
      message:
        payload:
          $ref: '#/components/schemas/OrderEvent'
```

将路由策略与 DSL 契约对齐，可避免硬编码路由键导致的命名混乱，并支持自动化校验与文档生成，详见 [01-43-设计到DSL的转换方法论](../01-基础概念与对比分析/01-43-设计到DSL的转换方法论.md)。
