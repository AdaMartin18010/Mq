## 2.60.1 消息结构的设计基线

面向演化的消息设计五条基线【论证】：

1. **信封与载荷分离**：信封（id/type/time/trace/版本号）由基础设施管，载荷由领域管——信封稳定、载荷演化；
2. **必填最小化**：新消息必填字段 ≤3 个【估算】，其余给默认值——为将来新增字段留"非破坏空间"；
3. **never 复用语义**：已发布字段的含义不可改变（字段名不变但语义变了是最危险的破坏）；
4. **显式版本**：信封带 schema 版本（Avro 的 writer/reader schema 机制天然支持【定理】；JSON 用 `$schema` 或版本头）；
5. **时间戳双写**：事件发生时间与消息产生时间分离（02-57 envelope 已含，IoT 弱网场景必备）。

```yaml
# 演化友好消息骨架（与 Testing/06-契约语义测试/03-业务场景 contract.yaml 对齐）
envelope:
  messageId: { type: string, required: true }
  schemaVersion: { type: string, required: true }   # MAJOR.MINOR，演化治理主键
  occurredAt: { type: timestamp, required: true }   # 领域时间
  traceId: { type: string }
payload: { $ref: './schemas/order.v3.schema.json' } # 载荷按版本独立文件
```

## 2.60.2 兼容性矩阵与六种变更分类

Schema Registry 官方兼容性模式【定理，以 Confluent/Apicurio 文档为准】：BACKWARD（新读旧）/FORWARD（旧读新）/FULL/TRANSITIVE 变体。

| 变更 | Avro | Protobuf | JSON Schema | 兼容模式建议 |
| ---- | ---- | ---- | ---- | ---- |
| 新增字段（有默认值） | ✅ 双向兼容 | ✅（reserved 号管理） | ✅ | BACKWARD |
| 删除字段 | ❌ | ❌（reserved） | ❌ | 仅 MAJOR |
| 改字段类型 | ❌ | ❌ | ❌（部分放宽） | 仅 MAJOR |
| 改字段名（不动类型） | ⚠️（Avro 按名匹配，等于删+增） | ❌（按号匹配，可改名） | ⚠️ | Protobuf 可 MINOR，Avro 仅 MAJOR |
| 新增枚举值 | ⚠️（旧 reader 遇到未知值报错——除非 union 兜底） | ⚠️ | ⚠️ | 需显式未知值兜底设计 |
| 放宽约束（必填→可选/扩大范围） | ✅ | ✅ | ✅ | FORWARD |

**JSON 的陷阱**【论证】：无 reader schema 匹配机制，"兼容"完全靠生产-消费双方自律——JSON 契约必须配显式兼容性检查（Spectral 规则或 ODCS quality 断言），否则兼容矩阵无从谈起。

## 2.60.3 演化模式目录

| 模式 | 场景 | 机制 | 代价 |
| ---- | ---- | ---- | ---- |
| 并行双写 | 大版本切换 | 生产者同时写 v1/v2 topic（或同 topic 双版本头），消费侧切流后停 v1 | 双写成本 2-4 周窗口 |
| schema 演进+灰度 | 小步变更 | Registry 注册新版，消费者滚动升级 reader，再放开 producer writer | 依赖兼容模式正确配置 |
| 加新不弃旧 | 长期共存 | 新能力新消息类型（ORDER_V2_CREATED），旧类型冻结——与"修改"绝缘 | 消息类型膨胀，需目录治理（EventCatalog） |
| 载荷包裹升级 | 结构剧变 | 新载荷整体包进 wrapper 字段，旧字段标记 deprecated 置空 | 消息体积临时增大 |
| topic 版本后缀 | 边界清晰 | orders.v1/orders.v2 物理隔离，桥接任务回放 | 桥接一致性责任重（01-63 EOS 语义） |

选择判据【论证】：变更频率低+消费方少→直接 MAJOR 切断；高扇出（>5 消费方【估算】）→并行双写或加新不弃旧。

## 2.60.4 演化红线与治理门禁

红线（触发即 MAJOR 版本并走变更评审）【论证】：

1. 已发布字段语义变更（名存实亡）；
2. 删除枚举值或收窄类型；
3. 消息键（分区键）结构变更——顺序性基础被破坏（TEST-14 顺序性维度）；
4. envelope 结构变更（所有消费方受影响）。

治理门禁（与 契约语义测试 governance-tools.md 合成一链）：

```text
contract.yaml 字段变更
  → asyncapi diff 破坏面报告
  → Registry 兼容性检查（BACKWARD 默认）
  → ODCS quality 断言更新（not_null/acceptedValues）
  → 受影响消费方清单（hermes-task-gen --drift）
  → CHANGELOG 记条目
```
