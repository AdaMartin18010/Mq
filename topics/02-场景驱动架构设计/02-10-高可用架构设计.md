## 2.10.1 高可用设计原则

### 设计原则

1. **冗余设计**
   - 多节点部署，避免单点故障
   - 多副本存储，确保数据可恢复
   - 多路径访问，提供备用接入地址

2. **故障隔离**
   - 故障域隔离：机架、可用区、地域分层
   - 资源隔离：CPU、内存、磁盘独立配额
   - 网络隔离：控制面与数据面分离

3. **自动恢复**
   - 自动故障检测：心跳、健康检查、元数据监控
   - 自动故障转移：Leader 选举、节点切换
   - 自动数据恢复：副本补全、日志同步

## 2.10.2 Kafka高可用架构

### 架构设计

```text
┌─────────┐  ┌─────────┐  ┌─────────┐
│Broker 1 │  │Broker 2 │  │Broker 3 │
│(Leader) │  │(Follower)│ │(Follower)│
└─────────┘  └─────────┘  └─────────┘
     │             │             │
     └─────────────┴─────────────┘
              │
        ┌─────┴─────┐
        │  Client   │
        └───────────┘
```

Kafka 4.0 全面进入 KRaft 模式，不再依赖 ZooKeeper，元数据一致性由 Raft 协议保证【定理】。KRaft 简化了部署拓扑，同时缩短了 Controller failover 时间【论证】。在 KRaft 模式下，Controller 节点同时承担 Broker 角色，推荐至少 3 节点以形成多数派。

### 高可用配置

```properties
# 至少3个Broker
replication.factor=3
min.insync.replicas=2

# 自动Leader选举
unclean.leader.election.enable=false
```

## 2.10.3 NATS高可用架构

### 集群架构

```text
┌─────────┐  ┌─────────┐  ┌─────────┐
│ NATS 1  │◄─┤ NATS 2  │◄─┤ NATS 3  │
└─────────┘  └─────────┘  └─────────┘
     │             │             │
     └─────────────┴─────────────┘
```

### 高可用配置

```conf
# 集群配置
cluster {
  routes = [
    "nats://nats-2:6222",
    "nats://nats-3:6222"
  ]
}
```

NATS 2.x 配合 JetStream 提供持久化、复制与自动故障转移能力，适合边缘到云的统一消息层【论证】。在跨地域场景下，可通过网关（Gateway）与 leaf node 实现联邦部署。

## 2.10.4 RabbitMQ高可用架构

### 镜像队列架构

```text
┌─────────┐  ┌─────────┐  ┌─────────┐
│ Node 1  │  │ Node 2  │  │ Node 3  │
│(Master) │  │(Mirror) │  │(Mirror) │
└─────────┘  └─────────┘  └─────────┘
```

### 高可用配置

```bash
# 设置镜像队列策略
rabbitmqctl set_policy ha-all "^" '{"ha-mode":"all"}'
```

新版 RabbitMQ 推荐使用 Quorum Queue 替代经典镜像队列，以 Raft 共识协议提供更高的一致性和故障恢复能力【论证】。

## 2.10.5 多活架构设计

### 跨地域多活

- **主-主模式**：双活数据中心同时写入，冲突在业务层解决
- **主-备模式**：主数据中心 + 备用数据中心，故障时切换
- **多活模式**：多个数据中心同时服务，就近读写

### 数据同步

- **同步复制**：强一致性，高延迟，适用于同城双活
- **异步复制**：最终一致性，低延迟，适用于跨地域容灾
- **混合模式**：关键数据同步，其他异步

## 2.10.6 高可用架构决策矩阵

### 决策表

| 场景特征 | 推荐方案 | 副本/节点策略 | 主要权衡 |
| --- | --- | --- | --- |
| 高吞吐日志流 | Kafka KRaft 3 Broker | replication.factor=3, min.insync.replicas=2 | 部署复杂，吞吐高 |
| 低延迟微服务 | NATS Cluster + JetStream | 3 节点集群，Stream Replicas=3 | 延迟低，持久化可选 |
| 企业事务消息 | RabbitMQ Quorum Queue | 3-5 节点，镜像队列/仲裁队列 | 原生 HA，单节点吞吐受限 |
| 跨地域容灾 | Kafka MirrorMaker 2 / NATS 多集群 | 单地域 3 副本 + 跨地域异步复制 | RPO>0，网络成本高 |
| 边缘到云联邦 | NATS 网关 + leaf node | 边缘单节点，云端 3 副本 | 断网续传，配置复杂 |
| 强一致元数据服务 | Kafka KRaft / RabbitMQ Quorum | 3/5 节点多数派 | 写入延迟增加 |

## 2.10.7 生产配置示例

### Kafka集群配置

```properties
# 引用 config-templates/kafka-server.properties.template 核心参数
broker.id=1
listeners=PLAINTEXT://localhost:9092
log.dirs=/data/kafka-logs
num.network.threads=8
num.io.threads=8

# 高可用关键参数
default.replication.factor=3
min.insync.replicas=2
unclean.leader.election.enable=false
auto.create.topics.enable=false
replica.lag.time.max.ms=10000
```

### NATS集群配置

```conf
# 引用 config-templates/nats-server.conf.template 核心参数
server_name: "nats-server-1"
port: 4222
http_port: 8222

cluster {
  port: 6222
  routes = [
    nats://nats-server-2:6222
    nats://nats-server-3:6222
  ]
}

jetstream {
  store_dir: "/data/jetstream"
  max_mem_store: 2GB
  max_file_store: 10GB
}
```

### RabbitMQ集群配置

```conf
# 引用 config-templates/rabbitmq.conf.template 核心参数
listeners.tcp.default = 5672
management.tcp.port = 15672

cluster_formation.peer_discovery_backend = classic_config
cluster_formation.classic_config.nodes.1 = rabbit@node1
cluster_formation.classic_config.nodes.2 = rabbit@node2
cluster_formation.classic_config.nodes.3 = rabbit@node3

vm_memory_high_watermark.relative = 0.4
disk_free_limit.absolute = 2GB
queue_master_locator = min-masters
```

## 2.10.8 高可用与客户端容灾

### 客户端高可用模式

客户端侧的高可用同样影响整体 RTO。常见模式包括：

- **多地址发现**：客户端配置多个 Broker/节点地址，故障时自动切换
- **连接池预热**：维护冗余连接，避免故障时新建连接耗时
- **本地缓存降级**：断网时本地缓存消息，恢复后补发

```java
// Kafka 客户端多地址配置示例
props.put("bootstrap.servers", "kafka-1:9092,kafka-2:9092,kafka-3:9092");
props.put("metadata.max.age.ms", "300000");
props.put("reconnect.backoff.ms", "100");
props.put("reconnect.backoff.max.ms", "10000");
```

不同客户端对重连、重试、退避的实现存在差异，选型时需结合 SDK 成熟度与语言生态，详见 [01-52-多语言客户端生态与编程模型](../01-基础概念与对比分析/01-52-多语言客户端生态与编程模型.md)。
