## 2.34.2 Kafka桥接

### 桥接实现

```java
// Kafka Connect桥接
// Kafka到RabbitMQ桥接
{
  "name": "kafka-rabbitmq-bridge",
  "config": {
    "connector.class": "com.example.KafkaRabbitMQBridge",
    "kafka.bootstrap.servers": "localhost:9092",
    "kafka.topics": "orders",
    "rabbitmq.host": "localhost",
    "rabbitmq.port": "5672",
    "rabbitmq.exchange": "orders",
    "rabbitmq.routing.key": "orders"
  }
}

// Kafka Streams桥接
KStream<String, String> kafkaStream = builder.stream("kafka-topic");
kafkaStream.foreach((key, value) -> {
    // 发布到其他系统
    rabbitMQClient.publish("rabbitmq-exchange", value);
});
```

## 2.34.3 NATS桥接

### 桥接实现

```go
// NATS到Kafka桥接
nc.Subscribe("nats.subject", func(msg *nats.Msg) {
    // 转换消息格式
    kafkaMessage := convertToKafka(msg.Data)

    // 发布到Kafka
    kafkaProducer.SendMessage(kafkaMessage)
})

// NATS到RabbitMQ桥接
nc.Subscribe("nats.subject", func(msg *nats.Msg) {
    // 发布到RabbitMQ
    rabbitMQChannel.Publish(
        "rabbitmq-exchange",
        "routing-key",
        false,
        false,
        amqp.Publishing{
            Body: msg.Data,
        },
    )
})
```

## 2.34.4 RabbitMQ桥接

### 桥接实现

```python
# RabbitMQ到Kafka桥接
def bridge_to_kafka(ch, method, properties, body):
    # 转换消息格式
    kafka_message = convert_to_kafka(body)

    # 发布到Kafka
    kafka_producer.send('kafka-topic', kafka_message)
    ch.basic_ack(delivery_tag=method.delivery_tag)

# 绑定桥接
channel.queue_bind(
    exchange='rabbitmq-exchange',
    queue='bridge-queue',
    routing_key='orders'
)
channel.basic_consume(queue='bridge-queue', on_message_callback=bridge_to_kafka)
```

## 2.34.6 桥接模式选型决策表

【论证】桥接模式的选择取决于一致性要求、吞吐需求、是否需要跨地域复制以及运维团队对中间件的熟悉度。下表给出四种典型模式的取舍：

| 桥接模式 | 代表实现 | 适用场景 | 顺序保证 | 主要限制 |
| -------- | -------- | -------- | -------- | -------- |
| **Kafka Connect 连接器** | Kafka Connect + 社区 Sink/Source | Kafka 与外部系统单向/双向同步 | 依赖连接器实现，通常分区有序 | 生态成熟度参差不齐，自定义开发成本高 |
| **Kafka MirrorMaker 2 / Cluster Linking** | MM2、Confluent Cluster Linking | 跨集群、跨地域 Kafka 联邦 | 分区级顺序 | 仅 Kafka 生态，跨云网络成本高 |
| **NATS 桥接 / Gateway / Leafnode** | NATS 官方 bridge、Supercluster、Leafnode | 边缘到云端、NATS 与异构系统 | subject 级顺序 | 需统一 NATS 语义，复杂转换能力弱 |
| **RabbitMQ Shovel / Federation** | RabbitMQ Shovel、Federation plugin | AMQP 跨节点/跨机房路由 | 队列级顺序 | 吞吐受单队列限制，适合企业内网 |
| **自定义桥接服务** | 应用层消费者+生产者 | 协议差异大、需要复杂转换 | 由应用保证 | 需要自行处理幂等、重试、监控 |

选型建议：

- 纯 Kafka 跨地域复制优先使用 MM2 或 Cluster Linking，参考 [1.51 多云与边缘消息联邦技术](../01-基础概念与对比分析/01-51-多云与边缘消息联邦技术.md) 的方案对比。
- 边缘侧 MQTT/NATS 上行到云端 Kafka，建议采用 NATS Leafnode 或自定义桥接，并在 [03-50-消息桥接与集成实践指南](../03-架构与运维实践/03-50-消息桥接与集成实践指南.md) 中配置批量与错误处理。
- 金融、医疗等产业域集成时，需要先把 ISO 20022 / FHIR 等标准映射到 CloudEvents 信封，见 [1.45 产业领域消息标准纵览](../01-基础概念与对比分析/01-45-产业领域消息标准纵览.md) 与 [2.54 事件契约模板库与命名规范](02-54-事件契约模板库与命名规范.md)。

### 桥接配置示例

以下配置来自 `config-templates/bridge-config.properties`，展示通用桥接参数：

```properties
# 通用桥接配置
bridge.enabled=true
bridge.async.enabled=true
bridge.batch.enabled=true
bridge.batch.size=100
bridge.batch.timeout.ms=1000

# 消息转换配置
bridge.transform.enabled=true
bridge.transform.format.from=json
bridge.transform.format.to=json
bridge.transform.field.mapping.enabled=true
bridge.transform.field.mapping.file=/etc/mq/bridge-field-mapping.json

# 错误处理配置
bridge.error.handling.enabled=true
bridge.error.handling.strategy=dlq
bridge.error.handling.dlq.topic=bridge-dlq
bridge.error.handling.retry.max.attempts=3
bridge.error.handling.retry.backoff.ms=1000

# 可靠性配置
bridge.reliability.enabled=true
bridge.reliability.ack.mode=all
bridge.reliability.idempotency.enabled=true
bridge.reliability.order.guarantee.enabled=false
```

## 2.34.7 跨域集成与契约对齐

消息桥接不仅是协议转换，更是事件契约的跨系统对齐。【论证】在 IoT、多云联邦或 Serverless 场景下，桥接层需要解决三个问题：

1. **命名空间映射**：MQTT 主题 `factory/line1/temperature` 如何映射到 Kafka topic `iot.telemetry.line1`？建议在 [2.54 事件契约模板库与命名规范](02-54-事件契约模板库与命名规范.md) 中定义统一的主题映射表。
2. **载荷格式转换**：工业现场常用 Protobuf/Sparkplug，互联网服务多用 JSON/CloudEvents。桥接层应通过 `bridge.transform.field.mapping.file` 声明字段映射，避免硬编码。
3. **语义保真**：QoS、offset、delivery tag 的语义无法一一对应，需要在契约中显式声明至少一次/恰好一次的降级策略。

| 源系统 | 目标系统 | 关键映射点 | 推荐参考文档 |

| MQTT/Sparkplug（工业 IoT） | Kafka | 主题命名、出生/死亡证书、Protobuf→JSON | [1.46 IoT 与互联网领域消息标准纵览](../01-基础概念与对比分析/01-46-IoT与互联网领域消息标准纵览.md) |
