## 2.13.1 顺序保证级别

### 顺序级别

1. **全局顺序**
   - 所有消息全局有序
   - 性能最低，扩展性最差
   - 适用：严格顺序场景

2. **分区顺序**
   - 同一分区内有序，分区间无序
   - 性能中等，可水平扩展
   - 适用：大部分场景

3. **无顺序保证**
   - 不保证顺序
   - 性能最高
   - 适用：顺序无关场景

## 2.13.2 Kafka顺序保证

### 分区内顺序

```java
// 单分区Producer（保证顺序）
Properties props = new Properties();
props.put("max.in.flight.requests.per.connection", 1);
props.put("retries", Integer.MAX_VALUE);
props.put("acks", "all");

// 相同Key路由到同一分区
producer.send(new ProducerRecord<>("topic", key, value));
```

### 顺序保证策略

- **单分区**：同一分区内有序
- **单Producer**：max.in.flight.requests=1，避免重试乱序
- **单Consumer**：单线程消费，避免并行处理破坏顺序

## 2.13.4 RabbitMQ顺序保证

### 单队列顺序

```python
# 单队列单消费者（保证顺序）
channel.queue_declare(queue='orders', durable=True)
channel.basic_qos(prefetch_count=1)  # 一次处理一条
channel.basic_consume(queue='orders', on_message_callback=callback)
```

### 顺序保证限制

- **单队列单消费者**：保证顺序
- **多消费者**：不保证顺序
- **镜像队列**：可能乱序，建议使用仲裁队列

## 2.13.5 顺序保证最佳实践

### 设计建议

1. **业务设计**
   - 避免全局顺序需求
   - 使用分区/分片
   - 业务层补偿

2. **技术实现**
   - 单分区/单队列
   - 单线程消费
   - 幂等处理

3. **性能权衡**
   - 顺序 vs 性能
   - 根据场景选择
   - 监控顺序性

## 2.13.6 顺序保证决策矩阵

### 决策表

| 顺序需求 | 推荐方案 | 系统/模式 | 性能影响 |
| --- | --- | --- | --- |
| 全局严格顺序 | 单 Topic 单分区 + 单生产者 | Kafka | 吞吐最低 |
| 按业务键局部顺序 | Key-Hash 分区 | Kafka | 中等，可水平扩展 |
| 单流顺序 + 持久化 | Ordered Consumer | NATS JetStream | 中等 |
| 单队列顺序 | 单队列 + 单消费者 | RabbitMQ | 中等 |
| 可乱序但需幂等 | 多分区 + 幂等消费 | 通用 | 最高 |
| 事件溯源顺序 | 聚合根作为分区键 | Kafka / Pulsar | 中等 |

## 2.13.7 生产配置示例

### Kafka顺序配置

```properties
# 引用 config-templates/partition-config.properties / kafka-producer-config.properties
kafka.partition.strategy=key-hash
partition.key.field=orderId
max.in.flight.requests.per.connection=1
retries=2147483647
acks=all
enable.idempotence=true
```

### NATS JetStream Ordered Consumer

```go
// 引用 config-templates/nats-client-config.conf 理念
js.Subscribe("ORDERS", func(msg *nats.Msg) {
    process(msg)
    msg.Ack()
}, nats.OrderedConsumer(), nats.Durable("order-consumer"))
```

### RabbitMQ单消费者配置

```python
# 引用 config-templates/rabbitmq-client-config.properties 理念
channel.queue_declare(queue='orders', durable=True)
channel.basic_qos(prefetch_count=1)
channel.basic_consume(
    queue='orders',
    on_message_callback=callback,
    auto_ack=False
)
```

## 2.13.8 顺序保证与客户端编程模型

### SDK 顺序语义差异

不同客户端 SDK 对顺序保证的默认行为不同。Kafka Java Producer 默认在同一分区按发送顺序写入；NATS JetStream 的 Ordered Consumer 在重新连接时会自动重建一致视角；RabbitMQ 客户端 prefetch 设置直接影响顺序消费。选型时需验证 SDK 是否暴露 `max.in.flight`、`OrderedConsumer`、`prefetch` 等参数。

```java
// 通过配置显式约束顺序相关参数
props.put("max.in.flight.requests.per.connection", 1);
props.put("enable.idempotence", true);
props.put("retries", Integer.MAX_VALUE);
```

客户端生态差异对顺序方案落地至关重要，详见 [01-52-多语言客户端生态与编程模型](../01-基础概念与对比分析/01-52-多语言客户端生态与编程模型.md)。
