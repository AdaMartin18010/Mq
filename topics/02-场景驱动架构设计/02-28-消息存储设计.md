## 2.28.1 存储场景与设计维度

### 常见场景

1. **持久化存储**
   - 核心交易消息必须落盘，避免 Broker 重启导致数据丢失。
   - 金融/订单类场景建议消息保留时间 ≥ 7 天。

2. **存储优化**
   - 通过压缩、冷热分层、对象存储卸载降低存储成本。
   - 平衡本地盘延迟与对象存储成本。

3. **数据管理**
   - 按时间、大小、消息数设置保留策略。
   - 长期归档与合规审计需求。

### 存储设计维度

【论证】消息存储设计需在成本、可靠性、查询能力之间取舍：

- **保留时长**：业务需要回溯多久？事件溯源可能需要数年。
- **副本因子**：可容忍多少节点故障？生产环境通常 3 副本。
- **冷热分层**：历史数据是否迁移到对象存储？
- **压缩策略**：是否启用日志压缩以保留最新状态？
- **备份恢复**：RTO/RPO 目标是什么？

## 2.28.2 存储策略选型

### 策略对比决策表

| 策略 | 成本 | 可靠性 | 查询能力 | 适用系统 | 典型场景 |
| ---- | ---- | ------ | -------- | -------- | -------- |
| 本地日志文件 | 中 | 依赖副本 | 弱 | Kafka、Pulsar | 高吞吐流处理 |
| 内存 + 持久化 Journal | 中 | 高 | 弱 | NATS JetStream | 低延迟、中等规模 |
| Mnesia/ETS | 中 | 中 | 中 | RabbitMQ | 传统消息队列 |
| 分层存储（本地+S3） | 低 | 高 | 中 | Kafka 4.0、Pulsar | 长期保留、合规 |
| S3 解耦主存储 | 最低 | 高 | 弱 | WarpStream、AutoMQ | 成本敏感、可接受 33–250ms 延迟 |

【论证】Kafka 采用追加日志文件实现高吞吐顺序写入，适合事件溯源与流处理；NATS JetStream 的 FileStorage 提供轻量级持久化；RabbitMQ 的 Mnesia 存储适合传统队列场景；云原生趋势是将冷数据或全部数据卸载到对象存储。

### 保留策略对比

| 策略 | 触发条件 | 适用系统 | 注意点 |
| ---- | -------- | -------- | ------ |
| 时间保留 | 超过 `log.retention.hours` | Kafka、RabbitMQ、NATS | 长周期需大容量 |
| 大小保留 | 超过 `log.retention.bytes` | Kafka、RabbitMQ | 按 partition/queue 生效 |
| 数量保留 | 超过 `MaxMsgs` | NATS JetStream、Redis Stream | 控制条目数 |
| 日志压缩 | 保留每个 key 最新值 | Kafka | 适合状态变更类 topic |
| 归档清理 | 过期 segment 转对象存储 | Kafka、Pulsar | 需管理对象存储生命周期 |

## 2.28.3 Kafka 存储

### 本地日志与分层存储

Kafka 使用追加日志文件存储消息，通过 segment 与索引文件实现高吞吐顺序读写：

```properties
# server.properties
log.dirs=/var/kafka-logs
log.retention.hours=168
log.retention.bytes=1073741824
log.segment.bytes=1073741824
log.cleanup.policy=delete
compression.type=snappy
```

Kafka 4.0 引入分层存储（KIP-405），热数据保留在本地盘，冷数据异步转储到 S3 等对象存储，兼顾成本与性能。

### S3 解耦趋势

【论证】云原生场景下，对象存储单价约为块存储的 1/30，且可消除跨 AZ 复制流量。代表方案包括：

- **Kafka KIP-405 分层存储**：本地热盘 + S3 冷存。
- **WarpStream**：完全无磁盘，数据直写 S3，协议兼容 Kafka。
- **AutoMQ**：Shared Storage 架构，S3 为主存储，WAL 缓冲写入。
- **Pulsar 分层存储**：BookKeeper 热数据 + S3 冷存。

参见 [1.29 S3 解耦存储消息系统分析](../01-基础概念与对比分析/01-29-S3解耦存储消息系统分析.md)。

| 方案 | 主存储 | 延迟 | 适用场景 |
| ---- | -------- | ---- | -------- |
| 本地盘 Kafka | 本地盘/EBS | 1–10 ms | 延迟敏感、强事务 |
| Kafka 分层存储 | 本地 + S3 | 热数据 ms 级 | 冷热分明、长期保留 |
| WarpStream | S3 | 33–250 ms | 成本敏感、日志/指标 |
| AutoMQ | S3 + WAL | 个位数~数十 ms | 希望无状态 Broker 但仍低延迟 |

## 2.28.4 NATS 存储

NATS Core 默认内存存储，不持久化；JetStream 提供 FileStorage 与 MemoryStorage 两种模式：

```go
js.AddStream(&nats.StreamConfig{
    Name:     "ORDERS",
    Storage:  nats.FileStorage,   // 文件持久化
    Replicas: 3,
    MaxAge:   24 * time.Hour,
    MaxBytes: 1024 * 1024 * 1024, // 1GB
    MaxMsgs:  1000000,
})
```

生产环境必须使用 `FileStorage` 并挂载持久化卷到 `nats.jetstream.store.dir`。

## 2.28.5 RabbitMQ 存储

RabbitMQ 消息持久化依赖队列与消息双重声明：

```python
channel.queue_declare(queue='orders', durable=True)
channel.basic_publish(
    exchange='',
    routing_key='orders',
    body=message,
    properties=pika.BasicProperties(delivery_mode=2)
)
```

Quorum Queue 使用 Raft 日志实现三副本持久化，适合高可用场景；Classic Queue 依赖 Mnesia 与磁盘文件。

## 2.28.6 事件溯源与长期存储

事件溯源要求事件不可变、长期保留，甚至永久保留。Kafka 等消息队列的 retention 机制可能导致旧事件丢失，因此强审计场景应考虑专用事件存储（如 KurrentDB/EventStoreDB）或将 Kafka 与对象存储结合。参见 [1.47 事件溯源核心机制与存储选型](../01-基础概念与对比分析/01-47-事件溯源核心机制与存储选型.md)。

| 需求 | 推荐方案 |
| ---- | -------- |
| 短期事件日志（天~周） | Kafka + 分层存储 |
| 长期审计（月~年） | Kafka → S3 归档 + 对象存储生命周期 |
| 永久事件真相源 | KurrentDB / PostgreSQL 事件表 |
| 快照与投影 | 外部数据库维护快照，事件流长期保留 |

## 2.28.7 存储最佳实践

### 设计建议

1. **保留策略**
   - 交易类 topic 保留 ≥ 7 天；日志/埋点类可按 1~3 天。
   - 长周期保留优先启用分层存储或归档到对象存储。

2. **副本与高可用**
   - Kafka `replication.factor=3`、`min.insync.replicas=2`。
   - NATS JetStream `Replicas=3`。
   - RabbitMQ Quorum Queue 默认 3 副本。

3. **成本优化**
   - 启用压缩：`snappy` 平衡 CPU 与压缩率；归档用 `zstd`。
   - 冷热分层：热数据本地盘，冷数据 S3。
   - 监控磁盘使用率，阈值 80% 告警。

### 配置模板引用

存储配置统一引用 `topics/config-templates/storage-config.properties`：

```properties
# 消息存储配置模板（引用 topics/config-templates/storage-config.properties）
kafka.log.dirs=/var/kafka-logs
kafka.log.retention.hours=168
kafka.log.retention.bytes=1073741824
kafka.log.segment.bytes=1073741824
kafka.log.cleanup.policy=delete
kafka.log.compression.type=snappy

nats.core.storage=memory
nats.jetstream.storage=file
nats.jetstream.store.dir=/var/nats-jetstream
nats.jetstream.max.age=86400
nats.jetstream.max.bytes=1073741824
nats.jetstream.max.msgs=1000000

rabbitmq.data.dir=/var/lib/rabbitmq/mnesia
rabbitmq.queue.durable=true
rabbitmq.message.durable=true
rabbitmq.message.ttl=86400000
rabbitmq.queue.max.length=1000000
rabbitmq.queue.max.bytes=1073741824

storage.retention.policy=time
storage.retention.time.hours=168
storage.retention.size.bytes=1073741824
storage.retention.count=1000000

storage.compression.enabled=true
storage.compression.type=snappy
storage.compression.level=1

storage.backup.enabled=true
storage.backup.type=full
storage.backup.schedule=0 0 * * *
storage.backup.dir=/var/backups
storage.backup.retention.days=30

storage.monitor.enabled=true
storage.monitor.metrics=storage_size,storage_usage,storage_growth,storage_cleanup_count
storage.monitor.alert.threshold.usage=0.8
storage.monitor.alert.threshold.growth=0.1
```
