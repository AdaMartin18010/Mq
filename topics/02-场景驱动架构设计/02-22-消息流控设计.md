## 2.22.1 流控场景

### 常见场景

1. **流量保护**
   - 防止突发流量压垮后端服务
   - 保护下游数据库、缓存等依赖
   - 平滑流量波动，避免级联故障

2. **资源控制**
   - CPU 使用率控制
   - 内存使用控制
   - 网络带宽控制

3. **限流策略**
   - 固定速率限流
   - 令牌桶限流
   - 滑动窗口限流

### 流控目标与约束

【论证】消息流控的核心目标是在吞吐量、延迟与稳定性之间取得平衡。过度流控会导致延迟升高、吞吐下降；流控不足则可能在突发流量下触发 OOM、连接中断或级联雪崩。设计时应先明确：

- **保护对象**：Broker、Consumer、下游服务还是网络带宽？
- **触发位置**：Producer 端、Broker 端、Consumer 端或网关层？
- **控制粒度**：全局级、用户级、Topic 级、分区级还是连接级？

## 2.22.2 流控策略选型

### 策略对比决策表

| 策略 | 突发容忍 | 实现复杂度 | 适用场景 | 主要风险 |
| ---- | -------- | ---------- | -------- | -------- |
| 固定速率 | 低 | 低 | 匀速任务、内部系统 | 突发流量易触发拒绝 |
| 令牌桶 | 高 | 中 | 网关入口、API 限流 | 桶参数调优不当会抖动 |
| 滑动窗口 | 中 | 中 | 精确计数场景 | 窗口粒度影响精度与内存 |
| 背压（Backpressure） | 高 | 高 | 流处理管道、Consumer 限速 | 延迟传播明显 |

【论证】对于消息队列系统，Producer 侧通常采用令牌桶或固定速率做入口限流；Broker 侧依赖协议原生背压（如 Kafka `max.in.flight.requests`、RabbitMQ flow control）；Consumer 侧则通过拉取速率、预取数或背压 API 实现限速。

### 流控位置决策表

| 位置 | 控制粒度 | 生效速度 | 对应用侵入性 | 典型风险 |
| ---- | -------- | -------- | ------------ | -------- |
| 网关/入口 | 全局/租户 | 快 | 低 | 误伤正常流量 |
| Producer 客户端 | 进程级 | 快 | 中 | 多进程叠加仍可能超限 |
| Broker 服务端 | Topic/分区/用户 | 中 | 低 | 配置复杂，需配额体系 |
| Consumer 客户端 | 消费组/实例 | 慢（滞后于生产） | 中 | 仅保护下游，不保护 Broker |

【论证】生产环境推荐**分层流控**：网关做粗粒度兜底，Producer 做令牌桶入口限流，Broker 做用户/Topic 配额，Consumer 通过 `prefetch` 或背压 API 做自我保护。

流控参数优先引用 `config-templates/flow-control-config.properties` 中的真实配置项：

```properties
# 消息流控配置模板（引用 topics/config-templates/flow-control-config.properties）
flow.control.strategy=token-bucket
flow.control.rate.per.second=1000
flow.control.burst.size=100
flow.control.monitor.enabled=true
flow.control.monitor.metrics=throttled_count,throttled_duration,throughput
flow.control.alert.threshold=80
flow.control.alert.channels=email,dingtalk
```

## 2.22.3 流控位置与纵深

### Producer 侧入口限流

Producer 侧限流是成本最低的防护层，可在消息进入网络前削峰。常见实现包括应用层令牌桶、发送缓冲区阈值与批量发送参数。

```java
// Guava RateLimiter 应用层限流示例
RateLimiter rateLimiter = RateLimiter.create(1000.0); // 每秒 1000 条
for (String msg : messages) {
    rateLimiter.acquire();
    producer.send(new ProducerRecord<>("orders", msg));
}
```

### Broker 侧协议背压

Broker 背压由协议或实现层提供：Kafka 通过 `max.in.flight.requests`、发送缓冲区与 quota 限制客户端；RabbitMQ 在内存/磁盘达到阈值时向连接发送 `connection.blocked` 通知；NATS 通过 slow consumer 检测断开超压订阅。

### Consumer 侧拉取限速

Consumer 侧限速保护下游业务系统，常用手段包括减少单次拉取量、降低预取数、使用背压 API 或手动控制 poll 频率。

## 2.22.4 Kafka 流控

### Producer 流控

```java
// 配置 Producer 流控
Properties props = new Properties();
props.put("max.in.flight.requests.per.connection", 5);
props.put("buffer.memory", 33554432);
props.put("batch.size", 16384);
props.put("linger.ms", 10);

// 使用 Kafka Streams 限流
streamsConfiguration.put(
    StreamsConfig.MAX_TASK_IDLE_MS_CONFIG,
    5000  // 最大空闲时间
);
```

### Consumer 流控

```java
// 配置 Consumer 流控
Properties props = new Properties();
props.put("max.poll.records", 500);
props.put("fetch.min.bytes", 1);
props.put("fetch.max.wait.ms", 500);
```

## 2.22.5 NATS 流控

### 连接流控

```go
// 配置连接流控
opts := nats.Options{
    MaxReconnects: 10,
    ReconnectWait: time.Second * 2,
    SubChanLen:    1000,  // 订阅通道长度
}

nc, _ := nats.Connect("nats://localhost:4222", opts)

// 订阅限流
sub, _ := nc.Subscribe("orders", func(msg *nats.Msg) {
    // 处理消息
    time.Sleep(10 * time.Millisecond)  // 限流
})

// 设置订阅待处理上限
sub.SetPendingLimits(1000, 10*1024*1024) // 1000 条或 10 MB
```

## 2.22.7 背压与流协议协同

### Reactive Streams 与 MQ 背压互补

【论证】MQ 的背压通常基于分区容量、队列长度或消费者拉取速率，而 Reactive Streams 的 `request(n)` 提供了应用层细粒度背压契约。二者可组合使用：MQ 负责可靠投递与削峰，Reactor/RxJava 负责在消费端按处理能力逐条请求数据。

| 背压来源 | 控制机制 | 适用场景 |
| -------- | -------- | -------- |
| MQ 协议背压 | Kafka quota、RabbitMQ flow control、NATS slow consumer | 保护 Broker 与网络 |
| Reactive Streams | `Subscription.request(n)` | 保护应用线程与下游资源 |
| 应用层背压 | 暂停 poll、sleep、丢弃/死信 | 业务自定义降级 |

当系统同时暴露实时流接口（如 WebSocket/SSE）时，建议 MQ 消费者用 Reactive Streams 控制向客户端推送的速率，避免在线连接被下游慢消费拖垮。详见 [01-40-应用层流协议与交互标准](../01-基础概念与对比分析/01-40-应用层流协议与交互标准.md)。

## 2.22.8 流控最佳实践

### 设计建议

1. **流控策略**
   - 多级流控：网关 → Broker → Consumer 分层防护
   - 动态调整：根据监控指标自动调节阈值
   - 监控告警：关注流控触发率、排队延迟、拒绝率

2. **性能考虑**
   - 评估流控计算开销，避免限流本身成为瓶颈
   - 权衡延迟影响，设置合理的排队上限
   - 在吞吐与稳定性之间保留安全余量

3. **监控告警**
   - 流控触发监控
   - 性能影响监控
   - 告警阈值设置
