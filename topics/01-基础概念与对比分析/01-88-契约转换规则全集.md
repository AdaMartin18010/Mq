## 1.88.1 规则表述形式

每条规则五元组：**`RULE-<链>-<NN>`｜源模式｜目标模式｜适用条件｜损耗声明**。规则执行纪律：①条件不满足→规则不适用（不得勉强转换）；②损耗非 none→产物必须带 `x-loss` 注记；③两条规则冲突→按 TSV 中 priority 取小者并记录冲突。

## 1.88.2 R1：contract.yaml → AsyncAPI

| 规则 | 源模式 | 目标模式 | 适用条件 | 损耗 |
|------|--------|----------|----------|------|
| R1-01 | `messages.{X}.type=command` | operation(action=send)+message 于 channel `{scenario}.cmds` | 无 | none |
| R1-02 | `messages.{X}.type=event` | operation(action=send)+message 于 channel `{scenario}.events` | 无 | none |
| R1-03 | `messages.{X}.fields` | message.payload=$ref contract.yaml#/messages/{X}/fields | 字段无嵌套对象 | **字段描述截断**（desc 超 80 字符截断，x-loss:desc-truncated） |
| R1-04 | `stateMachine` | `x-state-machine` 扩展（components.customProperties） | 状态机 ≤20 态 | none（登记簿已有 x- 治理） |
| R1-05 | `quality[]` | payload 层 JSON Schema 约束（required/not_null） | quality.type ∈ {not_null, freshness} | freshness 的时间语义降级为静态约束（x-loss:temporal-static） |
| R1-06 | `sla` | **不转换**——入 ODCS 链（R3），AsyncAPI 侧仅存 `x-sla-ref` 指针 | 无 | none（指针非冗余，防双源） |
| R1-07 | 消息 required 字段 | payload.required[] | 字段类型可映射（string/number/integer/array） | 自定义类型→string+physicalType 注记（x-loss:type-erasure） |
| R1-08 | `headers` 约定（trace-id/idempotency-key） | message.headers.schema | 无 | none |

## 1.88.3 R2：AsyncAPI → 代码

| 规则 | 源模式 | 目标模式 | 适用条件 | 损耗 |
|------|--------|----------|----------|------|
| R2-01 | payload $ref（JSON Schema） | 语言类型（modelina 模板） | schema 无递归引用 | none |
| R2-02 | operation(action) | 客户端方法骨架（produce/consume） | 无 | **binding 信息不进入签名**（x-loss:binding-not-in-signature） |
| R2-03 | `x-jetstream`/`x-redis` 等扩展 | 配置注释块（非可执行代码） | 生成器无该扩展的模板钩子 | 语义降为注释（x-loss:extension-comment） |
| R2-04 | channel.parameters | 方法参数/路由模板 | 参数有 schema 定义 | none |
| R2-05 | correlationId | 客户端上下文参数（如有模板支持） | 模板支持 | 部分语言缺失→降级忽略（x-loss:corr-optional） |
| R2-06 | 多消息 oneOf channel | 判别联合类型 | 有 discriminator 或可判别字段 | 无判别器→生成 enum+手动分发（x-loss:manual-dispatch） |

## 1.88.4 R3：contract.yaml → ODCS

实现者 `contract-to-odcs.py`；规则即其映射表（odcs-alignment.md §二），补两条纪律：

| 规则 | 内容 | 损耗 |
|------|------|------|
| R3-01 | x-semantics 十二维度→customProperties.x-semantics（原样数组） | none |
| R3-02 | invariants→customProperties.x-invariants（断言原文，不做逻辑变换） | **判定语义依赖 kg-query**，ODCS 消费方不可独立判定（x-loss:judg-dependency） |

## 1.88.5 R4：binding → 部署配置

01-82 速查表的形式化（示例三条，全集见 TSV）：

| 规则 | 源模式 | 目标模式 | 条件 | 损耗 |
|------|--------|----------|------|------|
| R4-01 | kafka.binding.partitions=N | broker `num.partitions`（默认）或 topic 创建参数 | 无 | none |
| R4-02 | x-jetstream.maxAckPending=N | 客户端 MaxAckPending + 审计断言输入 | 无 | none（T3 三层一致性见 01-82） |
| R4-03 | mqtt.binding（operation 级）qos | broker listener ACL 不含 qos（qos 是客户端语义） | **防误配**：qos 不得写入 broker 配置 | 误配即冲突（contract-binding-check 兜底） |

## 1.88.6 R5：代码 → AsyncAPI（逆向）

| 规则 | 源模式 | 目标模式 | 条件 | 损耗 |
|------|--------|----------|------|------|
| R5-01 | 注解/装饰器标记的 handler | channel+operation(action=receive) | 注解元数据完整（springwolf 类） | **运行时行为不可见**（重试/超时需人工补，x-loss:behavior-opaque） |
| R5-02 | DTO/POJO 类 | message.payload schema | 类无泛型擦除歧义 | 继承层次展开失真（x-loss:inheritance-flatten） |
| R5-03 | 无注解代码 | **不逆向**——返回"需人工建模"结论 | — | —（纪律：禁止猜测生成） |

逆向质量判据：R5 产物必须通过 L3 语义层校验 + 人工标注 x-loss 清单后方可入库（K3 准入）。

## 1.88.7 信息损耗总矩阵

| 损耗类 | 出现规则 | 处置 |
|--------|----------|------|
| desc-truncated | R1-03 | 全文检索以 contract.yaml 为准 |
| temporal-static | R1-05 | freshness 判定走 kg/TEST-C2，不走 ODCS |
| type-erasure | R1-07/R5-02 | physicalType 注记保留原类型 |
| binding-not-in-signature | R2-02 | 配置层补（R4 链） |
| extension-comment | R2-03 | 登记簿+人工核对 |
| judg-dependency | R3-02 | kg-query 为唯一判定入口 |
| behavior-opaque | R5-01 | 人工补全+复审 |

**治理规则**：x-loss 注记是 K3 准入必填项——无 x-loss 声明的产物默认声称"无损"，审计发现隐性损耗按一致性事故处理（K1 §4）。
