## 3.20.1 容量规划输入

容量规划前必须收集以下输入：

| 输入项 | 单位 | 示例 | 说明 |
| -------- | ------ | ------ | ------ |
| **峰值消息速率** | msg/s | 100,000 | 取业务峰值，非均值 |
| **平均消息大小** | KB | 1 | 含序列化开销 |
| **保留时长** | 天 | 7 | 合规与业务回放需求 |
| **副本数** | 个 | 3 | Kafka/Pulsar 必填 |
| **峰值倍数** | 倍 | 2 | 突发流量缓冲 |
| **压缩率** | 比例 | 0.5 | snappy/lz4 后估算 |

## 3.20.2 存储容量计算

### 公式

```text
日存储 = 消息速率(msg/s) × 平均消息大小(B) × 86400(s) × 副本数 × 压缩率
总存储 = 日存储 × 保留天数 × 峰值倍数
```

### 示例

```text
输入：
- 消息速率：100,000 msg/s
- 消息大小：1KB = 1024B
- 副本数：3
- 保留天数：7
- 峰值倍数：2
- 压缩率：0.5（snappy）

计算：
日存储 = 100,000 × 1024 × 86400 × 3 × 0.5 = 12,441,600,000,000 B ≈ 11.3 TB
总存储 = 11.3 TB × 7 × 2 ≈ 158 TB
```

### Kafka 存储配置

```properties
# 参考 config-templates/capacity-plan-config.properties
log.retention.hours=168
default.replication.factor=3
log.segment.bytes=1073741824
```

## 3.20.3 计算容量计算

### CPU

```text
CPU 核数 = 峰值吞吐(MB/s) / 单核处理能力(MB/s)
```

【估算：Kafka Broker 单核约处理 10-15MB/s；NATS 单核约处理 50-100MB/s】

### 内存

```text
内存(GB) = 页缓存需求 + JVM 堆内存 + 系统开销
页缓存需求 ≈ 活跃分区数据量（通常为日吞吐量的 10%-20%）
```

### 计算容量示例

| 系统 | 峰值吞吐 | 单核能力 | 推荐 CPU | 推荐内存 |
| ------ | ---------- | ---------- | ---------- | ---------- |
| Kafka | 100MB/s | 10MB/s | 10 核 × 3 节点 | 32GB/节点 |
| NATS | 100MB/s | 80MB/s | 4 核 × 3 节点 | 16GB/节点 |
| RabbitMQ | 50MB/s | 20MB/s | 4 核 × 3 节点 | 16GB/节点 |

## 3.20.4 网络带宽计算

### 公式

```text
入站带宽 = 消息速率 × 消息大小
复制带宽 = 入站带宽 × (副本数 - 1)
总带宽   = 入站带宽 + 复制带宽 + 消费者拉取带宽
```

### 示例

```text
入站带宽 = 100,000 msg/s × 1KB = 100MB/s
复制带宽 = 100MB/s × (3 - 1) = 200MB/s
消费者拉取带宽 ≈ 100MB/s
总带宽   = 400MB/s = 3.2Gbps
```

建议网络带宽预留 30% 余量，因此选择 10Gbps 网卡。

## 3.20.5 节点与分区规划

### Kafka 节点与分区

```text
Broker 数 = ceil(峰值吞吐 / 单节点吞吐)
分区数    = max(生产者并发数, 消费者并发数) 并向上取整为 Broker 数倍
```

### 分区数决策表

| 场景 | 推荐分区数 | 说明 |
| ------ | ------------ | ------ |
| 低吞吐（<1k msg/s） | 3-6 | 避免过度分区 |
| 中吞吐（1k-50k msg/s） | 6-24 | 按消费者并发扩展 |
| 高吞吐（>50k msg/s） | 24-96 | 需评估 broker 与磁盘能力 |

### NATS 节点规划

```conf
# nats-server.conf
max_connections: 10000
max_mem_store: 2GB
max_file_store: 10GB

cluster {
  name: "nats-cluster"
  port: 6222
  routes = [
    nats://nats-server-2:6222
    nats://nats-server-3:6222
  ]
}
```

## 3.20.6 各系统容量要点

| 系统 | 容量瓶颈 | 关键参数 | 监控重点 |
| ------ | ---------- | ---------- | ---------- |
| **Kafka** | 磁盘 IO、网络、页缓存 | `num.io.threads`, `log.flush.interval.ms` | `UnderReplicatedPartitions`, `LogEndOffset` |
| **NATS** | 内存、连接数 | `max_connections`, `max_mem_store` | `connections`, `slow_consumers` |
| **RabbitMQ** | 内存、队列长度 | `vm_memory_high_watermark`, `disk_free_limit` | `messages_ready`, `memory` |
| **Pulsar** | BookKeeper IO、ZooKeeper | `managedLedgerMaxEntriesPerLedger` | `storageSize`, `backlog` |

## 3.20.7 容量规划工具与脚本

### 使用容量规划脚本

```bash
# 运行容量规划计算
./scripts/capacity-plan.sh

# 检查当前容量使用情况
./scripts/capacity-check.sh all
```

### 容量配置模板

```properties
# config-templates/capacity-plan-config.properties
capacity.plan.storage.message.size.bytes=1024
capacity.plan.storage.message.count.per.day=1000000
capacity.plan.storage.retention.days=7
capacity.plan.storage.replication.factor=3
capacity.plan.storage.reserve.percentage=30

capacity.plan.scale.horizontal.node.count=3
capacity.plan.scale.horizontal.node.capacity.mbps=50
```

## 3.20.8 容量规划检查清单

- [ ] 已收集峰值消息速率、平均消息大小、保留时长、副本数
- [ ] 存储容量已按 `总存储 = 日存储 × 保留天数 × 峰值倍数` 计算，并预留 30%
- [ ] CPU 核数按单节点处理能力估算，未超过 80% 利用率目标
- [ ] 网络带宽已包含入站、副本同步、消费拉取三部分，预留 30%
- [ ] Kafka 分区数为 Broker 数整数倍，避免数据倾斜
- [ ] NATS `max_connections` 与 `max_mem_store` 已按峰值配置
- [ ] RabbitMQ `vm_memory_high_watermark` 已设置（建议 ≤0.6）
- [ ] `./scripts/capacity-check.sh all` 已执行，当前使用率在规划阈值内
- [ ] 已配置容量告警：存储 >80%、CPU >80%、内存 >80% 触发
