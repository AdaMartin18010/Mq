## 3.22.1 测试准备

### 硬件环境要求

| 组件 | 最低要求 | 推荐配置 |
| ------ | ---------- | ---------- |
| **CPU** | 8 核 | 16 核以上 |
| **内存** | 16GB | 32GB 以上 |
| **磁盘** | SSD | NVMe，独立数据盘 |
| **网络** | 1Gbps | 10Gbps，延迟 <1ms |

### 软件环境检查

```bash
# 系统参数优化
sysctl -w net.core.rmem_max=134217728
sysctl -w net.core.wmem_max=134217728
sysctl -w vm.swappiness=1

# 磁盘调度器检查
cat /sys/block/sda/queue/scheduler
```

## 3.22.2 测试场景设计

| 场景 | 目标 | 消息大小 | 速率/时长 | 关键指标 |
| ------ | ------ | ---------- | ----------- | ---------- |
| **吞吐量测试** | 最大可持续吞吐 | 1KB/4KB/16KB | 逐步加压，10min | records/sec、MB/sec |
| **延迟测试** | P50/P95/P99 延迟 | 1KB | 固定 10k msg/s，5min | 端到端延迟 |
| **压力测试** | 系统极限与稳定性 | 1KB | 2 倍峰值，30min | 错误率、资源使用 |
| **疲劳测试** | 长期稳定性 | 1KB | 24h | 内存泄漏、Lag 增长 |

## 3.22.3 测试环境调优

参考 `config-templates/performance-tune-config.properties`：

```properties

performance.tune.producer.batch.size=32768
performance.tune.producer.linger.ms=10
performance.tune.producer.compression.type=snappy
performance.tune.producer.acks=1

performance.tune.consumer.max.poll.records=500
performance.tune.consumer.prefetch.count=100

performance.tune.network.socket.receive.buffer.bytes=102400
```

## 3.22.4 Kafka 性能测试

### 测试命令

```bash
# 1. 创建测试 Topic
kafka-topics.sh --create --topic perf-test \
  --bootstrap-server localhost:9092 \
  --partitions 6 --replication-factor 3

# 2. Producer 压测
kafka-producer-perf-test.sh \
  --topic perf-test \
  --num-records 10000000 \
  --record-size 1024 \
  --throughput -1 \
  --producer-props bootstrap.servers=localhost:9092 \
    acks=all batch.size=32768 linger.ms=10 compression.type=snappy

# 3. Consumer 压测
kafka-consumer-perf-test.sh \
  --topic perf-test \
  --messages 10000000 \
  --threads 6 \
  --bootstrap-server localhost:9092 \
  --group perf-consumer-group
```

### Kafka 关键指标

| 指标 | 健康阈值 | 采集命令 |
| ------ | ---------- | ---------- |
| **吞吐** | ≥目标值 | kafka-producer-perf-test.sh 输出 |
| **P99 延迟** | ≤100ms | kafka-consumer-perf-test.sh 输出 |
| **CPU** | ≤80% | top / Prometheus |
| **磁盘 IO 等待** | ≤20% | iostat -x 1 |

## 3.22.5 NATS 性能测试

### 测试命令

```bash
# 安装 nats-bench
go install github.com/nats-io/nats.go/examples/nats-bench@latest

# 基准测试：1 发布者、1 订阅者、100 万条 1KB 消息
nats-bench -s nats://localhost:4222 \
  -np 1 -ns 1 \
  -n 1000000 -ms 1024 -r 100000

# 高并发连接测试
nats-bench -s nats://localhost:4222 \
  -np 10 -ns 10 \
  -n 10000000 -ms 128 -r 100000
```

### NATS 关键指标

| 指标 | 健康阈值 | 采集命令 |
| ------ | ---------- | ---------- |
| **吞吐** | ≥目标值 | nats-bench 输出 |
| **P99 延迟** | ≤1ms | nats-bench 输出 |
| **连接数** | ≤max_connections 的 80% | curl /varz |
| **内存** | ≤物理内存 70% | curl /varz |

## 3.22.6 RabbitMQ 性能测试

### 测试命令

```bash
# 使用 rabbitmq-perf-test
rabbitmq-perf-test -x 1 -y 1 \
  -u "amqp://user:pass@localhost:5672/%2fperf" \
  -s 1024 -r 10000 -z 600

# 多队列多消费者压测
rabbitmq-perf-test -x 4 -y 4 \
  -q 1000 \
  -u "amqp://user:pass@localhost:5672/%2fperf" \
  -s 1024 -r 50000 -z 600
```

### RabbitMQ 关键指标

| 指标 | 健康阈值 | 采集命令 |
| ------ | ---------- | ---------- |

| **内存水印** | ≤0.6 | rabbitmqctl status |
| **磁盘告警** | 未触发 | rabbitmqctl status |

## 3.22.7 测试结果分析

### 性能瓶颈定位

```bash
# 生成性能报告
./scripts/performance-report.sh all perf-report-$(date +%Y%m%d).txt

# 查看实时指标
./scripts/metrics.sh
```

### 瓶颈分析表

| 现象 | 根因 | 优化方向 |
| ------ | ------ | ---------- |
| CPU 100%，吞吐未达标 | 序列化/压缩开销大 | 换二进制序列化、lz4 压缩 |
| 磁盘 IO 等待高 | 刷盘或随机 IO 瓶颈 | 用 NVMe、调大 log.flush.interval.ms |
| P99 延迟突刺 | GC 或 ISR 收缩 | 调 JVM、增大 replica.lag.time.max.ms |
| 消费 Lag 持续增长 | 消费能力不足 | 增加 Consumer、调整 max.poll.records |

## 3.22.8 性能测试检查清单

- [ ] 测试环境与生产环境硬件规格一致或按等比缩放
- [ ] 测试前已执行 `./scripts/performance-tune.sh` 应用调优参数
- [ ] Topic/Queue/Stream 分区数与生产一致
- [ ] 测试数据量 ≥ 生产峰值 2 倍，持续时间 ≥10min
- [ ] 已记录 P50/P95/P99 延迟、吞吐、错误率、资源使用
- [ ] 测试过程中监控大盘已截图，异常点已标注
- [ ] 性能报告已保存至 `/var/mq/test-reports/`
- [ ] 未达标项已给出优化方案并复测通过
