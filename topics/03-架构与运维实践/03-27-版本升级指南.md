## 3.27.1 升级准备

### 升级前准备

1. **版本调研**
   - 阅读目标版本的 Release Notes
   - 识别 Breaking Changes 与废弃参数
   - 评估客户端与插件兼容性

2. **环境准备**
   - 备份数据目录与配置文件
   - 在测试环境完成端到端验证
   - 准备回滚方案（保留旧版本二进制与数据快照）

3. **升级计划**
   - 确定升级时间窗口
   - 制定逐节点升级顺序
   - 明确验证方案与回滚触发条件

使用项目脚本 [`topics/scripts/upgrade-check.sh`](../scripts/upgrade-check.sh) 快速采集当前版本：

```bash
bash topics/scripts/upgrade-check.sh all
```

## 3.27.2 Kafka 升级

### 滚动升级步骤

```bash
# 1. 确认当前版本与协议版本
kafka-broker-api-versions.sh --bootstrap-server localhost:9092

# 2. 逐台停止 Broker
./kafka-server-stop.sh

# 3. 替换新版本二进制，保留 config/server.properties 与 log.dirs

# 4. 更新配置（重点关注 inter.broker.protocol.version、log.message.format.version）

# 5. 启动 Broker
./kafka-server-start.sh -daemon config/server.properties

# 6. 验证该节点加入集群且 URP=0
kafka-broker-api-versions.sh --bootstrap-server localhost:9092
kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group my-group

# 7. 全部节点升级完成后，再提升协议版本
```

### 升级注意事项

- **版本兼容性**：Kafka 支持逐版本滚动升级，跨大版本需先升级到中间版本
- **协议版本**：升级后先保持 `inter.broker.protocol.version` 为旧版本，全部节点升级完成后再提升
- **数据迁移**：若涉及存储格式变更，需监控 UnderReplicatedPartitions 与 ISR 状态

## 3.27.3 NATS 升级

### 版本现状与硬约束

- **当前版本**：2.15（2026-09-17）为 Latest；2.14（2026-04-30）仍在 Maintained；2.12/2.11 已 EOL，终版分别为 v2.12.15、v2.11.17。
- **支持策略**：官方仅同时维护最新小版本与其前一小版本；新版本发布后最旧线停止补丁。
- **升级约束**：EOL 版本不再接收补丁，生产环境应尽快迁出；滚动升级前用 `-c nats-server.conf --check` 校验配置。

### 升级步骤

```bash
# 1. 备份配置文件
cp nats-server.conf nats-server.conf.bak

# 2. 查看当前版本
nats-server -v

# 3. 替换新版本二进制

# 4. 检查配置兼容性（重点：JetStream 存储目录、cluster 路由配置）
./nats-server -c nats-server.conf --check

# 5. 逐个节点滚动重启
pkill nats-server
./nats-server -c nats-server.conf -D

# 6. 验证集群状态与 JetStream 元数据
curl http://localhost:8222/varz | grep version
curl http://localhost:8222/jsz
```

### 升级注意事项

- **配置兼容性**：检查配置文件格式是否变更
- **集群升级**：逐个节点升级，确保路由连接恢复后再升级下一台
- **JetStream**：升级前备份 `$JS_STORE_DIR`，检查流与消费者状态

## 3.27.4 RabbitMQ 升级

### 版本现状与硬约束

- **强制跳板**：3.13.x、4.0.x、4.1.x 必须先升级到 4.2.x，才能继续滚动升级到 4.3.x/4.4.x。
- **支持周期**：4.2.x 社区支持已于 2026-07-31 结束；4.3.x 社区支持至 2027-01-31；4.4.0（2026-10-20）社区支持至 2027-07-31。
- **Erlang 要求**：4.3.7+/4.4.0+ 最低 Erlang 27.0（Erlang 26 已 EOL），升级前必须核对 [which-erlang](https://www.rabbitmq.com/docs/which-erlang)。

### 升级步骤

```bash
# 1. 导出定义与备份数据
rabbitmqctl export_definitions definitions.json
rabbitmqctl stop_app

# 2. 升级 Erlang/OTP（如需）
erl -eval 'erlang:display(erlang:system_info(otp_release)), halt().' -noshell

# 3. 安装新版本 RabbitMQ

# 4. 启动节点并等待 Mnesia 表迁移
rabbitmq-server -detached

# 5. 验证版本与集群状态
rabbitmqctl version
rabbitmqctl cluster_status
rabbitmqctl list_queues name messages
```

### 升级注意事项

- **Erlang 版本**：RabbitMQ 对 Erlang/OTP 版本有严格要求，升级前核对兼容性矩阵
- **插件兼容性**：检查所有插件是否支持目标版本
- **集群升级**：建议先升级镜像队列副本节点，再升级主节点

## 3.27.5 Redpanda 升级

### 版本现状与硬约束

- **CalVer 版本**：当前最新线为 v26.2（2026-07 发布，支持至 2027-07-28）；v26.1 与 v25.3 仍在支持窗口内。
- **发版渠道**：v26.2.2 之后 GitHub Releases 不再更新，补丁与 Release Notes 见 [docs.redpanda.com](https://docs.redpanda.com/streaming/current/reference/releases/)。
- **破坏性变更**：v25.3 对 Iceberg topic 引入 schema 破坏性变更（`redpanda.timestamp`/`redpanda.headers.key` 类型调整、Avro union/enum 映射变化），使用 Iceberg topic 的集群升级前必须按 [迁移指南](https://docs.redpanda.com/streaming/current/upgrade/iceberg-schema-changes-and-migration-guide/) 评估。

### 升级步骤

```bash
# 1. 备份数据目录与配置文件
cp -r /var/lib/redpanda /var/lib/redpanda.bak
cp /etc/redpanda/redpanda.yaml /etc/redpanda/redpanda.yaml.bak

# 2. 逐节点滚动升级（或按运维编排执行）
rpk cluster upgrade status

# 3. 验证集群健康
rpk cluster health
rpk topic list
```

### 升级注意事项

- **版本跳跃**：Redpanda 支持跨一个特性版本的滚动升级，跨多个大版本需分阶段。
- **License**：企业特性升级前确认 license 有效期。
- **回滚**：未 finalized 的升级可在限定窗口内回滚，升级前阅读 [Upgrade Redpanda](https://docs.redpanda.com/streaming/current/upgrade/)。

## 3.27.6 升级检查清单

### 升级前

- [ ] 已阅读目标版本 Release Notes 与 Breaking Changes
- [ ] 已备份数据目录、配置文件与元数据
- [ ] 已在测试环境完成升级演练
- [ ] 已准备回滚方案（旧版本二进制 + 数据快照）
- [ ] 已通知相关团队并确定维护窗口
- [ ] 已确认客户端 SDK 与插件兼容目标版本

### 升级中

- [ ] 按滚动升级顺序逐节点执行
- [ ] 每升级一个节点后检查集群状态与 URP/lag
- [ ] 监控 CPU/内存/磁盘与网络指标
- [ ] 记录升级时间与异常现象
- [ ] 达到回滚触发条件时立即停止并回滚

### 升级后

- [ ] 功能验证：生产、消费、管理界面正常
- [ ] 性能验证：吞吐与延迟达到升级前基线
- [ ] 监控告警链路正常
- [ ] 更新文档与配置版本号
- [ ] 清理临时备份（保留最近 2 个版本快照）

## 3.27.7 版本兼容性矩阵

| 系统 | 推荐升级路径 | 是否支持滚动升级 | 关键依赖检查 | 回滚复杂度 |
| ------ | ------------- | ----------------- | ------------- | ----------- |
| **Kafka** | 逐小版本升级，跨大版本需中间版本 | 是 | `inter.broker.protocol.version`、`log.message.format.version` | 中（需回退协议版本） |
| **NATS** | 直接替换二进制滚动重启 | 是 | JetStream 存储目录、cluster 路由 | 低（无状态或 JetStream 快照） |
| **RabbitMQ** | 先升级 Erlang/OTP，再升级 RabbitMQ | 是（建议） | Erlang 版本、插件版本、Mnesia 表格式 | 高（涉及 Mnesia 升级） |
| **Redpanda** | CalVer 逐版本升级，跨多个特性版本需分阶段 | 是 | Iceberg topic schema、license 有效期 | 中（unfinalized 升级可回滚） |

> **注意**：具体版本号与 Breaking Changes 以各系统官方发布说明为准。本指南提供通用框架，专项版本升级行动项见后续批次文档。
