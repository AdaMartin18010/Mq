## 3.16.1 安全加固维度矩阵

安全加固覆盖传输层、认证层、授权层、审计层与网络层五个维度：

| 安全维度 | Kafka | NATS | RabbitMQ | MQTT |
| ---------- | ------- | ------ | ---------- | ------ |
| **传输加密** | SSL/SASL_SSL | TLS | TLS/SSL | TLS |
| **认证机制** | SASL/PLAIN、SCRAM、OAuth | Token、NKey、用户名密码 | PLAIN、LDAP、OAuth | 用户名密码、X.509 |
| **授权机制** | ACL | 用户权限/账户 | vhost + 标签 + ACL | ACL 文件 |
| **审计日志** | 授权日志 + 操作日志 | 服务器日志 | rabbitmq_event_exchange | 连接日志 |
| **网络隔离** | 监听器绑定 + ACL IP | 白名单/Leaf 节点 | 监听器 + 防火墙 | 监听端口隔离 |

## 3.16.2 Kafka 安全加固

参考 `config-templates/security-enhanced-config.properties` 与 `config-templates/kafka-server.properties.template`。

### 1. 启用 SASL/SCRAM 认证

```properties
# server.properties
listeners=SASL_SSL://:9092
security.inter.broker.protocol=SASL_SSL
sasl.mechanism.inter.broker.protocol=SCRAM-SHA-512
sasl.enabled.mechanisms=SCRAM-SHA-512,PLAIN

# 初始化 SCRAM 用户
kafka-configs.sh --zookeeper localhost:2181 --alter \
  --add-config 'SCRAM-SHA-512=[password=change-me]' \
  --entity-type users --entity-name admin
```

### 2. 启用 TLS 加密

```properties
ssl.keystore.location=/etc/kafka/ssl/kafka.server.keystore.jks
ssl.keystore.password=${KAFKA_SSL_KEYSTORE_PASSWORD}
ssl.truststore.location=/etc/kafka/ssl/kafka.server.truststore.jks
ssl.truststore.password=${KAFKA_SSL_TRUSTSTORE_PASSWORD}
ssl.client.auth=required
```

### 3. 配置 ACL 授权

```bash
# 禁止默认无 ACL 时放行
allow.everyone.if.no.acl.found=false

# 仅允许 producer 用户写入 orders topic
kafka-acls.sh --bootstrap-server localhost:9092 \
  --command-config admin-client.conf \
  --add --allow-principal User:producer \
  --operation Write --topic orders
```

## 3.16.3 NATS 安全加固

参考 `config-templates/nats-server.conf.template`。

### 1. 启用 TLS 与账户隔离

```conf
# nats-server.conf
tls {
  cert_file: "/etc/nats/ssl/server.crt"
  key_file: "/etc/nats/ssl/server.key"
  ca_file: "/etc/nats/ssl/ca.crt"
  verify_and_map: true
}

authorization {
  users = [
    {user: "pub-client",  password: "$2a$11$...", permissions: {publish: ["orders.>", "events.>"], subscribe: {deny: ["sys.>", "$SYS.>"]}}}
    {user: "sub-client",  password: "$2a$11$...", permissions: {subscribe: ["orders.>"], publish: {deny: [">"]}}}
  ]
}
```

### 2. 系统账户与审计

```conf
system_account: SYS
accounts {
  APP: {users: [{user: app, password: pass}]}
  SYS: {users: [{user: sys, password: pass}]}
}
```

## 3.16.4 RabbitMQ 安全加固

参考 `config-templates/rabbitmq.conf.template` 与 `config-templates/security-enhanced-config.properties`。

### 1. 启用 TLS 与禁用默认用户

```conf
# rabbitmq.conf
listeners.ssl.default = 5671
ssl_options.cacertfile = /etc/rabbitmq/ssl/ca_certificate.pem
ssl_options.certfile   = /etc/rabbitmq/ssl/server_certificate.pem
ssl_options.keyfile    = /etc/rabbitmq/ssl/server_key.pem
ssl_options.verify     = verify_peer
ssl_options.fail_if_no_peer_cert = true

loopback_users.guest = false
default_user = admin
default_pass = ${RABBITMQ_DEFAULT_PASS}
```

### 2. 用户与 vhost 权限最小化

```bash
# 创建业务用户并限制 vhost
rabbitmqctl add_user order_svc "$(openssl rand -base64 32)"
rabbitmqctl set_permissions -p /orders order_svc "^orders\\." "^orders\\." "^orders\\."
rabbitmqctl set_user_tags order_svc ''

# 检查权限
rabbitmqctl list_users
rabbitmqctl list_permissions -p /orders
```

## 3.16.5 MQTT 安全加固

参考 `config-templates/mqtt-broker-config.conf`（若存在）或通用 Mosquitto/EMQX 配置。

```conf
# mosquitto.conf
listener 8883
protocol mqtt
cafile /etc/mosquitto/ca_certificates/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile /etc/mosquitto/certs/server.key
require_certificate false
use_identity_as_username false

password_file /etc/mosquitto/passwd
allow_anonymous false

acl_file /etc/mosquitto/acl
```

ACL 示例：

```text
# ACL 文件
user device001
topic read sensors/device001/+
topic write sensors/device001/+

user backend001
topic read sensors/+/+
topic write commands/+
```

## 3.16.6 网络安全与访问控制

### 防火墙规则示例

```bash
# Kafka Broker 仅允许指定网段访问 9092
iptables -A INPUT -p tcp --dport 9092 -s 10.0.0.0/8 -j ACCEPT
iptables -A INPUT -p tcp --dport 9092 -j DROP

# NATS 监控端口 8222 仅允许监控节点
iptables -A INPUT -p tcp --dport 8222 -s 10.0.1.10/32 -j ACCEPT
iptables -A INPUT -p tcp --dport 8222 -j DROP
```

### 网络隔离原则

| 区域 | 允许访问端口 | 禁止访问 |
| ------ | -------------- | ---------- |
| 生产内网 | Kafka 9092、RabbitMQ 5671、NATS 4222 | 管理端口对外暴露 |
| 管理区 | Kafka 9999(JMX)、RabbitMQ 15672、NATS 8222 | 直接访问业务端口 |
| 公网 | TLS 终结网关端口 | 直接连接 Broker/Server |

## 3.16.7 安全审计与监控

### 审计脚本

```bash
# 运行安全审计脚本
```

```yaml
# prometheus alert rules 示例

    severity: warning

  for: 5m
  labels:
    severity: critical
```

## 3.16.8 加固检查清单

### 传输与认证

- [ ] Kafka `security.inter.broker.protocol` 设置为 `SASL_SSL` 或 `SSL`
- [ ] Kafka SASL 机制启用 SCRAM-SHA-512 或更强机制，禁用 PLAIN 明文（测试环境除外）
- [ ] NATS `tls {}` 已配置且 `verify_and_map` 按需启用
- [ ] RabbitMQ `listeners.ssl.default` 已启用且 TCP 明文端口已关闭或受控
- [ ] MQTT `allow_anonymous false` 且 `password_file` 已配置

### 授权与审计

- [ ] Kafka `authorizer.class.name` 已设置，`allow.everyone.if.no.acl.found=false`
- [ ] RabbitMQ 默认 guest 用户已删除或禁用，`loopback_users.guest = false`
- [ ] 所有业务用户按最小权限原则配置 vhost/topic/queue 权限
- [ ] 审计日志已开启，保留天数 ≥ 90 天（`audit.retention.days=90`）
- [ ] `./scripts/security-check.sh all` 执行通过，无高危未启用项

### 网络与运维

- [ ] 管理端口（Kafka JMX 9999、RabbitMQ 15672、NATS 8222）未暴露至公网
- [ ] TLS 证书有效期剩余 ≥ 30 天，自动轮转已配置
- [ ] 密钥存储于 Vault/KMS，未硬编码在配置文件中
- [ ] 安全补丁策略：高危 CVE 在官方发布后 14 天内评估修复
