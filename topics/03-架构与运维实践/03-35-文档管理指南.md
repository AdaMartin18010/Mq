## 3.35.1 文档分类与命名

按文档用途分为四类，每类对应不同的维护者与审阅要求：

| 文档类型 | 示例 | 维护者 | 审阅周期 |
| ---------- | ------ | -------- | ---------- |
| 设计文档 | 02 系列选型设计、架构决策记录 | 架构师 | 每次变更 |
| 运维文档 | 03 系列操作指南、检查清单 | SRE/运维 | 每月 |
| 用户文档 | API 说明、SDK 示例、最佳实践 | 开发者体验 | 每季度 |
| 元文档 | INDEX、STATUS、ROADMAP、CHANGELOG | 项目治理 | 每批次 |

命名规则遵循 `XX-YY-主题名.md`，章节编号为 `X.YY.Z`。新增文档前先在 INDEX.md 登记，避免重复。

## 3.35.2 版本控制与 Git 工作流

所有文档纳入 Git 管理，使用语义化提交信息。

```bash
# 1. 创建文档分支
git checkout -b docs/03-35-compliance-update

# 2. 提交遵循 Conventional Commits 风格
git add topics/03-架构与运维实践/03-33-合规性指南.md
git commit -m "docs(03-33): 增加 GDPR/HIPAA 落地检查清单与脚本引用"

# 3. 打标签标记里程碑版本
git tag -a docs-v1.3.0 -m "完成 03-32~38 运维指南加厚"
```

### 文档版本号规则

| 版本变化 | 触发条件 | 示例 |
| ---------- | ---------- | ------ |
| 主版本 +1 | 目录结构或命名规则重构 | 1.x → 2.0 |
| 次版本 +1 | 新增整篇文档或章节 | 1.2 → 1.3 |
| 修订号 +1 | 错别字、数据更新、链接修复 | 1.2.1 → 1.2.2 |

## 3.35.3 文档更新流程

文档更新应按以下流程执行：

1. **需求识别**：通过用户反馈、审计发现、版本升级、法规变化识别更新需求。
2. **影响评估**：确认受影响的文档清单、链接链路与元数据（INDEX、STATUS、ROADMAP）。
3. **内容编写**：遵循 AGENTS.md 密度与置信度规范，引用 `config-templates/` 与 `scripts/` 中的真实配置与命令。
4. **质量检查**：执行 `scripts/doc-self-check.sh` 与 `scripts/documentation-check.sh`。
5. **审阅发布**：提交 PR/MR，经至少一人审阅后合并，同步更新 `最后更新` 日期。
6. **通知同步**：在 CHANGELOG.md 中登记变更，必要时通知相关团队。

## 3.35.4 文档质量检查

### 自检脚本

```bash
cd E:/_src/Mq/topics

# 快速自检：禁用表述、死链、定位声明、代码块语言、最后更新日期
bash scripts/doc-self-check.sh quick

# 全量自检：额外执行骨架风险抽样与外链巡检
bash scripts/doc-self-check.sh full
```

### documentation-check 脚本

```bash
# 检查必要元文档、主题目录、脚本与配置模板 README
bash scripts/documentation-check.sh
```

输出示例：

### 质量检查维度

| 维度 | 检查项 | 通过标准 |
| ------ | -------- | ---------- |
| 内容 | 准确性、完整性、时效性 | 无事实错误、无空泛条目 |
| 结构 | 目录一致、章节编号、链接可达 | 目录与实际章节一致、无死链 |
| 格式 | 代码块语言、表格对齐、标题层级 | 所有代码块标注语言 |
| 规范 | 定位声明、最后更新、置信口径 | 02/03 系列头部含定位声明 |

## 3.35.5 文档归档与废弃

文档超过有效期、被合并或下线后，应进入归档或废弃流程，避免活文档与死文档混排。

### 归档规则

| 状态 | 处理方式 | 索引标记 |
| ------ | ---------- | ---------- |
| 活跃 | 正常维护，列入 INDEX.md 活跃区 | 无 |
| 归档 | 移动到 `archive/` 子目录或标注 `**状态**: 已归档` | `状态：归档` |
| 废弃 | 保留只读、删除交叉链接、重定向到新文档 | `状态：已废弃` |

### 归档脚本示例

```bash
# 将过期文档移入归档目录，并更新 INDEX.md
ARCHIVE_DIR="topics/archive/$(date +%Y-%m)"
mkdir -p "$ARCHIVE_DIR"
git mv topics/03-架构与运维实践/03-old-guide.md "$ARCHIVE_DIR/"
sed -i '/03-old-guide/d' topics/INDEX.md
git add topics/INDEX.md "$ARCHIVE_DIR"
git commit -m "docs: 归档 03-old-guide，更新索引"
```

## 3.35.6 自动化文档检查

建议将文档检查集成到 CI 流程：

```yaml
# .github/workflows/docs-lint.yml 示例
name: docs-lint
on: [push, pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: doc self check
        run: bash topics/scripts/doc-self-check.sh quick
      - name: documentation completeness check
        run: bash topics/scripts/documentation-check.sh
```
