## 3.37.1 CI/CD 流程总览

消息队列系统的 CI/CD 流程分为五个阶段：

| 阶段 | 关键动作 | 失败处理 |
| ------ | ---------- | ---------- |
| 代码提交 | PR/MR 创建、代码审查、静态扫描 | 阻断合并 |
| 构建 | 编译、单元测试、镜像打包 | 通知提交人 |
| 集成测试 | 启动消息队列服务、跑端到端用例 | 保留日志、禁止晋级 |
| 部署 | 蓝绿/金丝雀/滚动发布 | 自动或手工回滚 |
| 验证 | 健康检查、性能基线、告警静默 | 触发回滚 |

## 3.37.2 自动化测试阶段

### 测试分层

```bash
# 1. 单元测试（快速反馈，<5 分钟）
./mvnw test -Dtest='*UnitTest'

# 2. 集成测试（依赖 Docker Compose 启动 Kafka/NATS/RabbitMQ）
docker-compose -f topics/config-templates/docker-compose-kafka.yml up -d
./mvnw test -Dtest='*IntegrationTest'
docker-compose -f topics/config-templates/docker-compose-kafka.yml down

# 3. 端到端测试（模拟生产流量）
./scripts/benchmark.sh --topic test-e2e --messages 100000
```

### 测试通过标准

| 测试类型 | 目标 | 失败阈值 |
| ---------- | ------ | ---------- |
| 单元测试 | 覆盖率与核心逻辑 | 覆盖率 <60% 或任何失败阻断 |
| 集成测试 | 协议兼容与配置正确 | 任何失败阻断 |
| 性能测试 | 吞吐与延迟基线 | 延迟 P99 超基线 20% 阻断【估算】 |
| 混沌测试 | 故障恢复能力 | 未按预期自愈阻断 |

## 3.37.3 镜像构建与制品管理

### Dockerfile 示例

```dockerfile
FROM eclipse-temurin:17-jre
COPY build/libs/mq-app.jar /app.jar
COPY topics/config-templates/kafka-consumer-config.properties /etc/mq/
USER 1001
EXPOSE 8080
ENTRYPOINT ["java", "-Djava.security.egd=file:/dev/./urandom", "-jar", "/app.jar"]
```

### 镜像安全扫描

```bash
# 使用 Trivy 扫描镜像漏洞
trivy image --severity HIGH,CRITICAL myrepo/mq-app:${CI_COMMIT_SHA}

# 镜像签名（cosign）
cosign sign --key cosign.key myrepo/mq-app:${CI_COMMIT_SHA}
```

## 3.37.4 部署策略

### 蓝绿部署

```bash
# 1. 部署绿色环境
kubectl apply -f k8s/green/

# 2. 等待绿色环境 Ready
kubectl rollout status deployment/mq-app-green --timeout=300s

# 3. 切换 Service 流量到绿色
kubectl patch service mq-app -p '{"spec":{"selector":{"version":"green"}}}'

# 4. 保留蓝色环境 10 分钟，确认无误后删除
sleep 600
kubectl delete -f k8s/blue/
```

### 金丝雀部署

```bash
# 1. 发布 10% 副本到金丝雀
kubectl apply -f k8s/canary-10.yaml

# 2. 监控 5 分钟关键指标
# 错误率 <0.1%、P99 延迟 <基线、消费 Lag 未持续增长

# 3. 逐步放大到 50%、100%
kubectl apply -f k8s/canary-50.yaml
kubectl apply -f k8s/canary-100.yaml
```

### 部署策略对比

| 策略 | 停机时间 | 回滚速度 | 资源占用 | 适用场景 |
| ------ | ---------- | ---------- | ---------- | ---------- |
| 蓝绿 | 零 | 秒级切换 | 2x | 关键发布、快速回滚 |
| 金丝雀 | 零 | 分钟级 | 1.1x~1.5x | 风险中等、需要观察 |
| 滚动更新 | 接近零 | 分钟级 | 1x | 常规补丁、兼容性好 |

## 3.37.5 自动化部署配置

参考 `config-templates/automation-config.properties`：

```properties
# CI/CD 集成配置
automation.cicd.enabled=true
automation.cicd.tool=gitlab_ci
automation.cicd.gitlab_ci.enabled=true
automation.cicd.gitlab_ci.pipeline.file=.gitlab-ci.yml

# 监控自动化
automation.monitoring.enabled=true
automation.monitoring.prometheus.enabled=true
automation.monitoring.grafana.enabled=true
automation.monitoring.auto.alert.enabled=true
automation.monitoring.auto.diagnosis.enabled=true

# 扩缩容自动化
automation.scaling.enabled=true
automation.scaling.strategy=hpa
automation.scaling.hpa.min.replicas=2
automation.scaling.hpa.max.replicas=10
automation.scaling.hpa.cpu.target.utilization=80
```

## 3.37.6 CI/CD 检查清单

### CI 阶段

- [ ] 代码已提交 PR/MR，并通过至少一名审阅人审批。
- [ ] 静态代码扫描无 HIGH/CRITICAL 漏洞。
- [ ] 单元测试通过，覆盖率 ≥60%【估算】。
- [ ] 集成测试通过，消息队列服务由 `docker-compose-*.yml` 启动。
- [ ] 镜像构建成功并完成漏洞扫描（HIGH/CRITICAL 已修复或评估）。
- [ ] 镜像已签名并推送至制品仓库。

### CD 阶段

- [ ] 已选择部署策略（蓝绿/金丝雀/滚动更新）并完成环境准备。
- [ ] 已验证配置参数与 `config-templates/` 中的模板一致。
- [ ] 已执行 `scripts/ci-cd-check.sh` 确认部署脚本与 K8s 配置存在。
- [ ] 部署过程中健康检查通过（HTTP/TCP 探针、消息生产消费探活）。
- [ ] 金丝雀/蓝绿阶段监控指标正常：错误率 <0.1%、P99 延迟未超基线 20%【估算】。

### 部署后

- [ ] 已验证核心业务消息流转正常。
- [ ] 已检查消费者组 Lag 未持续增长。
- [ ] 已确认告警规则生效且无异常告警风暴。
- [ ] 已保留回滚脚本与上一版本镜像标签，可在 5 分钟内回滚【估算】。
- [ ] 已在 CHANGELOG.md 登记本次发布。
