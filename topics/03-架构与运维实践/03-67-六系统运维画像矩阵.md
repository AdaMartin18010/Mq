## 3.67.1 应用系统特征

| 维度 | Kafka | RabbitMQ | NATS | Pulsar | RocketMQ | Redis Stream |
| ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| 部署拓扑 | 控制层（KRaft controller / 旧 ZK）+ 无状态 broker + 独立磁盘 | Erlang 节点对等多活，无专门控制节点；队列镜像/仲裁复制 | 单二进制 server，可水平扩展为 cluster / super-cluster / leaf | Broker 无状态 + BookKeeper 存储节点 + ZooKeeper/Oxia 元数据 | NameServer（轻量注册）+ Broker + Proxy（5.x） | Redis 主从/哨兵/集群 + Stream 作为数据类型 |
| 元数据依赖 | KRaft 内嵌元数据（推荐）或外部 ZooKeeper | Mnesia 内置（schema 数据库） | 无外部元数据存储；JetStream 元数据内嵌 | ZooKeeper / Oxia 元数据存储 | NameServer 承担路由元数据 | 无外部元数据；槽/分片由集群协议维护 |
| 存储模型 | 分区日志顺序追加，segment 文件 + 页缓存强依赖 | 队列索引 + 消息体，流/仲裁队列使用 Raft 日志 | JetStream stream：文件或内存存储，单节点或复制组 | 分层存储：Ledger（BookKeeper）+ 可选 offload 到 S3/Tiered Storage | CommitLog 顺序写 + ConsumeQueue 索引 | 基于 Redis 内存/持久化，Stream 条目保存在主数据结构中 |
| 协议面 | Kafka Protocol（TCP 9092） | AMQP 0-9-1 / AMQP 1.0 / MQTT / STOMP | NATS Protocol / MQTT / WebSocket | Pulsar Binary Protocol / Kafka Protocol 兼容 | Remoting + gRPC（Proxy）/ OpenMessaging | Redis RESP + Stream 命令子集 |

**Kafka**：典型 3-controller KRaft 集群 + N broker。控制器负责元数据与分区 leader 选举，broker 负责读写。【论证】Kafka 自 3.3 起 KRaft 生产可用，4.x 将移除 ZooKeeper 支持。运维注意：broker 磁盘必须按 topic/partition 规划，`log.dirs` 建议多盘独立挂载以分散 I/O。

**RabbitMQ**：节点间通过 Erlang 分布式链路形成集群。队列可选择 classic、quorum、stream 三种类型，镜像队列已逐步退出。无独立控制器，集群状态通过 Mnesia 同步。运维注意：节点名（`-name`）一旦确定不可更改；quorum queue 与 stream queue 对网络分区有明确多数派语义。

**NATS**：同一个 `nats-server` 二进制按配置切换 core-NATS、JetStream、MQTT 网关。节点间通过 routes/gateways 互联，拓扑从单节点到全球 super-cluster 平滑扩展。运维注意：JetStream 集群依赖 RAFT，扩缩容需保证多数派在线；leaf node 适合边缘/混合云场景。

**Pulsar**：计算存储分离。Broker 无状态，可快速替换；BookKeeper 负责持久化 ledger；ZooKeeper/Oxia 保存 tenant/namespace/topic 元数据。运维注意：bookie 磁盘需独立 journal 与 ledger 目录；namespace bundle 自动 unload 是常见扩缩容信号。

**RocketMQ**：NameServer 轻量无状态，启动顺序先于 Broker；Broker 向 NameServer 注册 topic 路由；5.x Proxy 提供客户端接入层。部署顺序为 NameServer → Broker → Proxy。运维注意：消费进度存储在 Broker，Broker 切换需关注进度回退；5.x Local 模式 Proxy 与 Broker 同进程。

**Redis Stream**：不是独立消息队列，而是 Redis 数据类型。高可用依赖 Redis Sentinel 或 Cluster；Stream 消费组通过 `XREADGROUP` 实现拉模式。运维注意：所有 Stream 命令在主线程执行，消息体大或消费组多会拉高主线程 CPU；持久化 fork 会造成内存尖峰。

## 3.67.2 配置面画像

| 维度 | Kafka | RabbitMQ | NATS | Pulsar | RocketMQ | Redis Stream |
| ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| 主配置载体 | `server.properties`（模板：`kafka-server.properties.template`） | `rabbitmq.conf`（模板：`rabbitmq.conf.template`） | `nats.conf`（模板：`nats-server.conf.template`） | `broker.conf`（模板：`pulsar-broker-config.conf`） | `broker.conf` / `namesrv.conf` | `redis.conf`（模板：`redis-stream-config.conf`） |
| 热更新能力 | 部分 broker 配置自 1.1 起支持动态更新（Dynamic Update Mode），无需重启 broker；默认 topic 级配置也可热更新 | 多数参数需重启；运行时参数/策略/policy 可通过 HTTP API/`rabbitmqctl` 修改并持久化 | 支持 `nats-server --signal reload` 或 SIGHUP 重载配置，不断连接 | 所有 broker 配置存储在 ZooKeeper，可通过 `pulsar-admin brokers update-dynamic-config` 热更新 | 多数参数需重启 Broker；NameServer 路由信息运行时可变 | `CONFIG SET` 可运行时修改大量参数；部分启动参数仍需重启 |
| 关键配置类（日志） | `log4j2.properties`（4.x 迁移到 Log4j2）；动态日志级别无需重启 | `log.file.level` / `log.console.level`；支持运行时调整 | `logfile`、`log_size_limit`、`debug` | `broker.conf` 中 `logLevel`；BookKeeper 独立日志配置 | `broker.log` 与 logback 配置 | `loglevel`、`logfile`；慢查询日志 `slowlog-log-slower-than` |
| 关键配置类（副本） | `default.replication.factor`、`min.insync.replicas`、`offsets.topic.replication.factor` | `cluster_partition_handling`、`quorum_queue.max_in_memory_length` | `jetstream.max_memory_store`、`jetstream.max_file_store`、stream `replicas` | `managedLedgerDefaultEnsembleSize`、`managedLedgerDefaultWriteQuorum`、`managedLedgerDefaultAckQuorum` | `brokerRole`（SYNC_MASTER/ASYNC_MASTER/SLAVE）、`flushDiskType` | `min-replicas-to-write`（Cluster 模式）、`appendonly` 持久化 |
| 关键配置类（保留） | `log.retention.hours/bytes`、`log.cleanup.policy`（delete/compact） | `queue-master-locator`、`max-length`、`max-age`、`stream.retention` | stream `Retention`（Limits/Interest/WorkQueue）、`MaxMsgs`/`MaxBytes`/`MaxAge` | `retentionSizeInMB`、`retentionTimeInMinutes`、`ttlDurationDefaultInSeconds` | `fileReservedTime`、`deleteWhen`、`diskMaxUsedSpaceRatio` | stream 无自动 TTL，需应用侧 `XDEL` 或 `MAXLEN` 截断 |
| 关键配置类（限流） | `quota.producer.default`、`num.network.threads`、`num.io.threads` | `vm_memory_high_watermark`、`disk_free_limit`、`credit_flow_default_credit` | `max_connections`、`max_subscriptions`、`max_payload`、`jetstream.max_outstanding_catchup` | `brokerPublisherThrottlingTickTimeMillis`、`dispatchThrottlingRatePerTopicInMsg` | `sendMessageThreadPoolNums`、`pullMessageThreadPoolNums`、`waitTimeMillsInSendQueue` | `maxclients`、`maxmemory`、`client-output-buffer-limit` |

**Kafka**：核心模板 `kafka-server.properties.template`，客户端参数见 `kafka-producer-config.properties` 与 `kafka-consumer-config.properties`。动态配置通过 `--bootstrap-server` 与 `kafka-configs.sh` 下发，参数表中的 Dynamic Update Mode 列指示是否可热更新。常用动态参数包括 `log.retention.ms`、`num.io.threads`、`leader.replication.throttled.rate` 等。

**RabbitMQ**：模板 `rabbitmq.conf.template` 与 `rabbitmq-client-config.properties`。运行时策略（policy/parameter）变更生效快，但 `rabbitmq.conf` 中多数内核参数需重启。建议用 `rabbitmqadmin definitions export` 定期导出 JSON 作为 schema 备份，并在新集群通过 `load_definitions` 导入。

**NATS**：模板 `nats-server.conf.template` 与 `nats-client-config.conf`。修改配置后执行 `nats-server --signal reload` 或发送 `SIGHUP` 即可生效，无需断连。注意：某些 TLS 证书路径变更可能需要重连才能生效。

**Pulsar**：模板 `pulsar-broker-config.conf` 与 `pulsar-client-config.properties`。broker 动态配置存储在 ZooKeeper，使用 `pulsar-admin brokers update-dynamic-config --config key --value val` 更新。BookKeeper 配置大多需重启 bookie，不属于 broker 动态配置范围。

**RocketMQ**：项目 config-templates 暂无 RocketMQ 专属模板，可复用通用模板 `performance-tune-config.properties`、`monitor-config.properties`、`rate-limit-config.properties`、`capacity-plan-config.properties` 进行参数映射。生产环境需维护 `broker.conf` 与 `namesrv.conf` 两份文件；客户端参数可参考 `mqtt-client-config.properties` 中限流与重试语义做类比映射。

**Redis Stream**：模板 `redis-stream-config.conf` 与 `redis-stream-client-config.properties`。`CONFIG SET maxmemory`、`maxmemory-policy`、`appendonly` 等可在线调整；`io-threads` 调整需重启生效。建议将 `CONFIG SET` 变更同步回 `redis.conf`，否则重启后丢失。

### 参数变更纪律

1. **变更前**：在 `config-templates/` 对应模板中预演参数值，确认是否属于热更新范围；RocketMQ 与 RabbitMQ 多数内核参数需重启，须规划维护窗口。
2. **变更中**：Kafka/Pulsar/NATS/Redis 优先使用热更新命令，避免全集群滚动；记录旧值、新值、变更人与业务理由。
3. **变更后**：核对 exporter/监控面板是否反映新值；对需要重启生效的参数，在重启后执行一次 `diff` 校验，确保运行配置与文件配置一致。

```bash
# Kafka 动态配置示例（per-broker）
kafka-configs.sh --bootstrap-server localhost:9092 --entity-type brokers --entity-default --alter --add-config log.retention.hours=48

# Pulsar 动态配置示例
pulsar-admin brokers update-dynamic-config --config brokerPublisherThrottlingTickTimeMillis --value 100

# Redis 运行时配置示例
redis-cli CONFIG SET maxmemory-policy allkeys-lru
```

## 3.67.3 运行行为画像

| 维度 | Kafka | RabbitMQ | NATS | Pulsar | RocketMQ | Redis Stream |
| ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| 正常稳态日志特征 | `[KafkaServer id=1] started`；定期输出 `Log flush scheduler` 与 `cleaner` 进度；controller 日志可见 `ControllerEventManager` | `[info] <0.x.0> Server startup complete`；统计日志 `Statistics database started`；定期 GC/内存报告 | `[INF] Server is ready`；JetStream 输出 `JetStream cluster` 与 RAFT 状态；/healthz 可读 | `Broker service url` 就绪；BookKeeper `BookieShell` 启动完成；元数据同步日志 | Broker 日志输出 `The broker boot success..`；NameServer 输出 `The Name Server boot success..` | `Ready to accept connections`；RDB/AOF 加载日志；持久化 fork 子进程日志 |
| 核心指标特征 | `kafka_server_brokertopicmetrics_messagesinpersec_rate`、`kafka_network_request_metrics_*`、`kafka_log_log_size` | `rabbitmq_queue_messages`、`rabbitmq_node_mem_used`、`rabbitmq_node_disk_free`、erlang 进程数 | `nats_server_cpu`、`nats_server_mem`、`nats_varz_subscriptions`、`jetstream_total_messages` | `pulsar_broker_msg_*`、`pulsar_storage_*`、`bookkeeper_*`、`pulsar_topics_count` | `rocketmq_broker_tps`/`rocketmq_broker_qps`、`rocketmq_consumer_lag` | `redis_memory_used_*`、`redis_keyspace_hits`、`redis_connected_clients`、`redis_slowlog_*` |
| 扩缩容动作 | 水平扩 broker → 触发分区重分配（`kafka-reassign-partitions.sh`）；无状态 broker 可快速加入 | 扩节点加入集群 → 队列镜像/仲裁重新平衡；流队列可迁移 | 扩节点加入 cluster → JetStream 副本自动重平衡；leaf node 可作为边缘扩容 | 扩 broker 无状态；扩 bookie 增加 ledger 容量；namespace bundle 自动/手动 unload | 扩 Broker 后 topic 队列可迁移；扩 NameServer 无状态；扩 Proxy 提供接入层 | 垂直扩容（内存/CPU）或 Redis Cluster 水平扩分片；Stream 分片随 key 槽迁移 |
| 升级路径风格 | 滚动重启；升级后需调 `inter.broker.protocol.version` 与 `log.message.format.version`，再二次滚动开启新特性 | 滚动升级；需先升级次要版本、启用 feature flag；跨大版本建议蓝绿迁移 | 滚动升级；JetStream 集群需保证 RAFT 多数派在线；版本差需兼容 | 滚动升级 broker → bookie → ZooKeeper；注意 advertised listener 解析与 readiness 探针配合 | NameServer 可先升级；Broker 滚动；Proxy 可独立升级；5.x 注意 Local/Cluster 模式兼容 | 滚动升级 Redis 节点；大版本升级注意 RDB/AOF 格式与命令兼容性 |

**Kafka**：KRaft 模式下，controller 与 broker 可合并或分离。扩容后分区不会自动均衡，必须显式执行重分配脚本。升级是典型的两段式：先换代码不改协议版本，再改协议版本二次滚动。日常巡检重点：ISR 收缩、under-replicated partitions、log cleaner 落后。

**RabbitMQ**：集群扩展性受 Mnesia 元数据同步限制，通常建议节点数 ≤ 7。队列类型选择对扩缩容影响大：quorum queue 比 classic mirrored queue 更适合跨节点迁移。日常巡检重点：memory/disk alarm、queue leader 分布、Erlang process 数。

**NATS**：JetStream 集群基于 RAFT，元数据与流数据在节点间复制。扩缩容对客户端透明，但需关注 `max_memory_store` 与 `max_file_store` 总量。日常巡检重点：`/jsz` 中 stream/consumer 状态、RAFT 视图、磁盘使用量是否接近 store limit。

**Pulsar**：broker 真正无状态，替换最快。存储容量由 BookKeeper 集群决定，扩 bookie 后由自动恢复管理器（autorecovery）逐步平衡 ledger。日常巡检重点：namespace bundle 分布、bookie 读写延迟、offload 任务状态。

**RocketMQ**：NameServer 全内存无状态，可多活部署。Broker 主从同步/异步复制模式在配置中显式声明；消费进度存储在 Broker。日常巡检重点：Broker 注册状态、ConsumeQueue 构建进度、consumer lag 分布。

**Redis Stream**：Stream 命令在 Redis 单线程主循环中执行，超高并发写入会占用主线程；可配合 `io-threads` 分担网络 I/O，但命令执行仍串行。日常巡检重点：`used_memory` 与 `maxmemory`、慢查询、持久化 fork 耗时。

### 升级路径速查

| 系统 | 推荐升级方式 | 关键前置检查 | 回退窗口 |
| ------ | ------ | ------ | ------ |
| Kafka | 滚动重启，两段式协议版本升级 | 备份 `server.properties`、确认 ISR≥2、检查 Log4j2 配置（4.x） | 低：协议版本升级后不可逆 |
| RabbitMQ | 滚动升级，先 minor 后 major | 导出 definitions、关闭所有 deprecated feature、备份 Mnesia | 中：可在节点级回滚 |
| NATS | 滚动升级，保持 RAFT 多数派 | 检查 JetStream stream 副本分布、快照状态 | 高：单节点可快速回退 |
| Pulsar | broker → bookie → ZK/Oxia 顺序滚动 | 检查 bundle unload、ledger 复制因子、topic 路由 | 中：broker 无状态可替换 |
| RocketMQ | NameServer → Broker → Proxy 滚动 | 备份 topic/订阅关系、检查主从同步延迟 | 中：Broker 主从可切换 |
| Redis Stream | 滚动升级节点，大版本注意持久化格式 | 执行 `BGSAVE`、检查 AOF/RDB 兼容性、验证复制偏移 | 中：主从切换可回退 |

## 3.67.4 运维交接速查

新接手任一系统时，按以下三步建立上下文：

1. **读配置、找模板**：定位主配置文件与项目模板（`config-templates/kafka-server.properties.template`、`rabbitmq.conf.template`、`nats-server.conf.template`、`pulsar-broker-config.conf`、`redis-stream-config.conf`；RocketMQ 直接读 `conf/broker.conf` 与 `conf/namesrv.conf`）。确认副本因子、保留策略、限流参数、监控端口四项。
2. **看拓扑、对节点**：画出控制节点/元数据/存储/代理四层的物理部署图；核对每个节点的版本、角色、监听地址、磁盘挂载点；验证 exporter 与告警规则已覆盖黄金指标。
3. **跑基线、留预案**：在非高峰时段执行一次滚动重启/leader 切换演练，记录正常启动时间与指标基线；对照 [03-68 系统运行行为档案](./03-68-系统运行行为档案.md) 确认磁盘满、网络抖动、副本失联三类故障的默认行为与升级路径。

```bash
# 快速核对脚本示例（以 Kafka 为例，其他系统替换命令即可）
kafka-broker-api-versions.sh --bootstrap-server localhost:9092 > broker-versions.txt
kafka-configs.sh --bootstrap-server localhost:9092 --describe --entity-type brokers > broker-configs.txt
kafka-topics.sh --bootstrap-server localhost:9092 --describe > topic-replicas.txt
```

- [ ] 已定位主配置文件及 `config-templates/` 中对应模板，副本因子、保留策略、限流参数已复核

## 3.67.6 常见交接误区

1. **把 Kafka broker 当无状态随意重启**：broker 虽无业务状态，但承载分区 leader 与副本同步；盲目重启会触发 controller failover 与 rebalance，需在低峰执行并关注 under-replicated partitions。
2. **认为 RabbitMQ 所有参数都能热更新**：只有 policy/parameter 与部分运行时设置可热更新，`rabbitmq.conf` 中内核参数（如 `vm_memory_high_watermark`）修改后必须重启节点。
3. **忽略 NATS JetStream 的 store limit**：未设置 `MaxBytes`/`MaxMsgs`/`MaxAge` 的 stream 会持续增长，直到磁盘满导致 server 异常；生产环境必须显式设置保留策略。
4. **把 Pulsar broker 与 bookie 混为一谈**：broker 无状态可快速替换，bookie 承载持久化数据；扩 bookie 后 ledger 平衡由 autorecovery 异步完成，不能立即看到容量变化。
5. **RocketMQ NameServer 多活配置遗漏**：NameServer 本身无状态，但客户端必须配置所有 NameServer 地址；只配一个会在该节点故障时影响路由发现。
6. **Redis Stream 不设置 `MAXLEN` 或主动清理**：Stream 不会自动过期，数据无限增长会耗尽 `maxmemory`；需应用层 `XDEL` 或 `XTRIM` 控制长度。
7. **把模板默认值直接复制到生产**：`config-templates/` 中的模板是起点而非终点；副本因子、保留期、内存水位必须按实际容量与合规要求重新标定。
8. **忽视客户端配置与 broker 配置的联动**：例如 Kafka `acks=all` 必须与 `min.insync.replicas` 配合；Redis Stream `XREADGROUP BLOCK` 超时与消费端重连策略必须一致。
