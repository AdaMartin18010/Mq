## 3.12.1 AWS消息队列服务

### Amazon SQS

**特点**：

- ✅ 完全托管，无需维护服务器
- ✅ 标准队列提供近似无限吞吐，FIFO队列保证顺序
- ✅ 按需付费，按请求数计费

**适用场景**：

- 任务队列与微服务异步解耦
- 事件驱动Lambda触发器
- 需要至少一次语义的工作队列

**当前现状**（核实至2026-11）：AWS SQS提供标准队列与FIFO两种模式；FIFO队列支持消息组级别的顺序与去重。标准队列默认提供至少一次投递，FIFO支持按消息组去重。官方定价按API请求与传出数据计费，无最低消费。
来源：[Amazon SQS 官方文档](https://docs.aws.amazon.com/sqs/)

**CLI快速核验队列深度**：

```bash
aws sqs get-queue-attributes \
  --queue-url https://sqs.<region>.amazonaws.com/<account>/<queue-name> \
  --attribute-names ApproximateNumberOfMessages \
  --query 'Attributes.ApproximateNumberOfMessages'
```

### Amazon SNS

**特点**：

- ✅ 发布-订阅模式，支持多协议推送
- ✅ 与SQS、Lambda、HTTP/S、Email、SMS集成
- ✅ 支持消息过滤与消息属性路由

**适用场景**：

- 事件通知与广播
- 多终端推送
- 与SQS组合实现扇出（Fan-out）

### Amazon Kinesis

**特点**：

- ✅ 实时数据流，支持Kinesis Data Streams与Data Firehose
- ✅ 高吞吐量，按Shard计费
- ✅ 数据保留默认24小时，最长365天

**适用场景**：

- 实时分析
- 日志聚合
- 事件流处理

### Amazon MSK

**特点**：

- ✅ 托管Apache Kafka，支持 **Provisioned / Serverless / Express** 三类集群
- ✅ Provisioned 可选 Standard 与 Express 两种 Broker；Express 将计算与弹性存储分离，缩短扩缩容与恢复时间
- ✅ 兼容 Kafka 协议，MSK Connect / AWS Glue Schema Registry 可复用开源生态

**适用场景**：

- 已有 Kafka 工作负载上云
- 需要 Kafka 协议兼容的流处理
- 希望 offload 集群运维的团队

**当前现状**（核实至2026-11）：

- MSK Provisioned 2026-08 起支持集群级自定义域名（Custom Domain Names），ZK 与 KRaft 模式均可用，配置在扩缩容后保留。
- 2026-02 起 Provisioned 集群新增 `CreateTopic` / `UpdateTopic` / `DeleteTopic` API，Kafka 3.6+ 可直接通过 AWS CLI/SDK/CloudFormation 管理 Topic。
- MSK Express Brokers 可将 Kafka Topic 原生投递至 S3 对象或 S3 Tables（Apache Iceberg），无需维护 Kafka Connect 集群。

来源：

- [Amazon MSK Developer Guide](https://docs.aws.amazon.com/msk/)
- [AWS What's New – MSK Custom Domain Names](https://aws.amazon.com/about-aws/whats-new/)
- [Classmethod – Amazon MSK New Features & Updates 2026/08](https://dev.classmethod.jp/en/articles/cm-news-analytics-202609/)
- [Bits Lovers – MSK Express to S3 and Iceberg](https://www.bitslovers.com/amazon-msk-express-s3-iceberg-streaming-tables/)

## 3.12.2 Azure消息队列服务

### Azure Service Bus

**特点**：

- ✅ 企业级消息队列，支持队列、主题/订阅
- ✅ 支持事务、会话、重复检测、死信队列
- ✅ 提供Basic/Standard/Premium三层计费

**适用场景**：

- 企业应用集成
- 微服务通信
- 工作流编排

**当前现状**（核实至2026-11）：Premium层提供专用资源与JMS 2.0支持；Standard层按操作数计费，Basic仅支持队列。官方文档建议生产使用Premium以获得可预测延迟。
来源：[Microsoft Learn - Service Bus Premium](https://learn.microsoft.com/en-us/azure/service-bus-messaging/service-bus-premium-messaging)、[Azure Service Bus 定价](https://azure.microsoft.com/en-us/pricing/details/service-bus/)

### Azure Event Hubs

**特点**：

- ✅ 高吞吐量事件流，Kafka协议兼容
- ✅ Standard按Throughput Unit（TU）计费，Premium/Dedicated按Processing Unit/Capacity Unit
- ✅ 支持Capture自动落盘到Blob/ADLS

**适用场景**：

- 实时分析
- 日志聚合
- IoT数据流

**当前现状**（核实至2026-11）：Standard命名空间最多购买40 TU；Premium提供更高吞吐与更低延迟；Dedicated最小部署规模为8 Capacity Unit（CU）。
来源：[Microsoft Learn - Event Hubs Quotas](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-quotas)、[Microsoft Learn - Event Hubs Premium](https://learn.microsoft.com/en-us/azure/event-hubs/event-hubs-premium-overview)

## 3.12.3 Google Cloud消息队列服务

### Cloud Pub/Sub

**特点**：

- ✅ 全球分布式发布-订阅
- ✅ 自动扩展，支持Push/Pull两种投递模式
- ✅ 与BigQuery、Dataflow、Cloud Functions原生集成

**适用场景**：

- 事件驱动架构
- 实时数据流
- 系统解耦

**当前现状**（核实至2026-11）：Pub/Sub 默认提供至少一次投递； ordering keys 可实现同一key内的有序。单项目默认最多10,000个订阅。定价按发布/投递消息量与传出流量计费。
来源：[Google Cloud Pub/Sub Quotas](https://cloud.google.com/pubsub/quotas)、[Stack Overflow - Pub/Sub 订阅限制](https://stackoverflow.com/questions/48473990/limitation-of-google-cloud-pubsub-subscriptions-per-project)

## 3.12.4 Confluent Cloud与第三方托管Kafka

**Confluent Cloud**:

- ✅ 由Kafka创始团队运营，提供Serverless与Dedicated集群
- ✅ 内置Schema Registry、ksqlDB、Flink集成
- ✅ 99.99% SLA（Dedicated集群），企业级支持

**当前现状**（核实至2026-11）：Confluent Cloud 2024年订阅收入持续增长，提供Basic/Standard/Enterprise/Governance等套餐。定价基于CKU（Confluent Kafka Unit）、存储、网络与附加组件。
来源：[Confluent 官方定价](https://www.confluent.io/pricing/)、[Confluent Cloud vs Amazon MSK](https://www.confluent.io/compare/confluent-cloud-vs-amazon-msk/)

**其他托管选项**：

- **Aiven for Apache Kafka**：多云托管，支持Kafka、MQTT、InfluxDB等组合
- **Redpanda Cloud**：兼容Kafka API，无ZooKeeper/KRaft，低延迟
- **StreamNative Cloud**：基于Apache Pulsar，支持Kafka on Pulsar协议兼容

## 3.12.5 云服务对比矩阵

| 服务 | 类型 | 计费模式 | 吞吐量级 | 延迟 | 核心协议/API |
| ------ | ------ | ---------- | ---------- | ------ | ------------- |
| **AWS SQS** | 托管队列 | 按请求数+数据传出 | 近似无限（标准队列） | < 1秒 | AWS SQS API |
| **AWS SNS** | 发布订阅 | 按请求数+数据传出 | 高 | < 100ms | AWS SNS API |
| **AWS Kinesis** | 流处理 | 按Shard小时+数据 | 100万+ TPS/Shard | < 1秒 | Kinesis API |
| **AWS MSK** | 托管Kafka | Provisioned按实例/Serverless按吞吐 | 100万+ TPS | 5-100ms | Kafka Protocol |
| **Azure Service Bus** | 队列/主题 | Basic/Standard/Premium分层 | 高 | < 100ms | AMQP/JMS/REST |
| **Azure Event Hubs** | 事件流 | TU/PU/CU | 100万+ TPS | < 1秒 | AMQP/Kafka Protocol |
| **GCP Pub/Sub** | 发布订阅 | 按消息量+数据传出 | 高（自动扩展） | < 100ms | gRPC/REST |
| **Confluent Cloud** | 托管Kafka | CKU+存储+网络 | 100万+ TPS | 5-100ms | Kafka Protocol |

## 3.12.6 部署与选型检查清单

以下清单用于云消息服务选型与上线前核验。

- [ ] **合规与地域**：目标Region支持所需服务，且满足数据驻留要求
- [ ] **网络隔离**：已配置VPC/VNet/Private Service Connect或PrivateLink，避免公网暴露
- [ ] **认证授权**：已启用IAM/RBAC最小权限，避免使用长期Access Key
- [ ] **容量基线**：已根据峰值吞吐与保留周期选择Tier/Shard/TU/PU/CKU数量
- [ ] **监控接入**：已配置CloudWatch/Azure Monitor/Google Cloud Monitoring/Confluent Cloud Metrics
- [ ] **告警阈值**：已设置消费延迟、错误率、磁盘/存储使用率等关键告警
- [ ] **灾备策略**：已配置跨区冗余、备份或异地复制方案
- [ ] **成本预算**：已设置预算告警，避免按量计费导致的费用失控

**CLI示例：获取Azure Event Hubs命名空间消费组Lag**:

```bash
az eventhubs eventhub consumer-group show \
  --resource-group <rg> \
  --namespace-name <ns> \
  --eventhub-name <hub> \
  --name <consumer-group>
```

**CLI示例：清点GCP Pub/Sub主题与订阅**:

```bash
gcloud pubsub topics list --filter="name~'<prefix>'"
gcloud pubsub subscriptions list --format="table(name,topic,ackDeadlineSeconds)"
```

## 3.12.7 成本与容量决策表

| 决策维度 | AWS MSK Provisioned | Azure Event Hubs Premium | GCP Pub/Sub | Confluent Cloud Dedicated |
| ---------- | --------------------- | -------------------------- | ------------- | --------------------------- |
| **最小容量单元** | kafka.t3.small / 1 broker | 1 Processing Unit (PU) | 无固定单元，按量 | 1 CKU / eCKU |
| **吞吐扩展动作** | 增删 broker / 分区 | 增删 PU | 自动扩展 | 增删 CKU |
| **保留上限** | 按磁盘/分层存储 | Premium 90 天 | 默认 7 天，可延长 | 按套餐与存储 |
| **典型网络成本** | 数据传出 $0.05/GiB 起 | 数据传出另计 | 数据传出另计 | 数据传出另计 |
| **私有连接** | PrivateLink / VPC | Private Endpoint | Private Service Connect | Private Link |

> **成本基线**（【估算】）：轻量工作负载（<1 GiB/天）优先考虑 SQS / Pub/Sub / Service Bus Standard；日均 >100 GiB 的流式工作负载再对比 MSK / Event Hubs / Confluent 的预留容量折扣。

## 3.12.8 选型建议

**AWS环境**：

- 任务队列 → SQS
- 事件通知/扇出 → SNS + SQS
- 实时流 → Kinesis 或 MSK
- 已有Kafka生态 → MSK 或 Confluent Cloud on AWS

**Azure环境**：

- 企业集成/事务消息 → Service Bus Premium
- 实时流/大数据接入 → Event Hubs
- Kafka协议兼容 → Event Hubs for Apache Kafka

**GCP环境**：

- 事件驱动/云原生集成 → Pub/Sub
- 大数据管道 → Pub/Sub + Dataflow + BigQuery

**多云/混合环境**：

- 需要Kafka一致性体验 → Confluent Cloud
- 需要低延迟简化运维 → Redpanda Cloud
- 需要Pulsar多租户/地理复制 → StreamNative Cloud
