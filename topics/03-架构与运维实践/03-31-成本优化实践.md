## 3.31.1 成本分析

### 成本构成

1. **硬件成本**
   - 服务器实例费用
   - 存储（SSD/HDD/对象存储）费用
   - 网络带宽与流量费用

2. **运维成本**
   - 人力投入
   - 监控与告警工具费用
   - 备份与归档存储费用

3. **云服务成本**
   - 按量/预留/Spot 实例费用
   - 存储分层费用
   - 跨可用区/跨地域流量费用

### 成本分析命令

使用项目脚本 [`topics/scripts/cost-analysis.sh`](../scripts/cost-analysis.sh) 与 [`topics/scripts/resource-usage.sh`](../scripts/resource-usage.sh)：

```bash
# 资源使用概览
bash topics/scripts/resource-usage.sh

# 成本分析
bash topics/scripts/cost-analysis.sh
```

典型输出关注项：

```text
CPU 使用率: 45%（目标 60-80%）
内存使用率: 55%（目标 60-80%）
磁盘使用率: 62%（建议 < 75%）
预留实例覆盖率: 70%（建议 ≥ 80%）
```

## 3.31.2 资源优化

### 优化策略

1. **合理规划**
   - 按需扩容，避免过度配置
   - 定期评估实例规格是否匹配负载
   - 合并低利用率集群

2. **资源复用**
   - 共享存储与连接池
   - 批量操作减少资源消耗
   - 使用容器化提高部署密度

3. **自动扩缩容**
   - 根据负载自动调整实例数
   - Kubernetes HPA/VPA 或云厂商自动伸缩
   - 闲时缩容，忙时扩容

参考项目成本优化配置 [`topics/config-templates/cost-optimize-config.properties`](../config-templates/cost-optimize-config.properties)：

```properties
# 资源目标使用率
cost.optimize.resource.cpu.target.usage=0.8
cost.optimize.resource.memory.target.usage=0.8

# 自动扩缩容
cost.optimize.resource.auto.scale.enabled=true
cost.optimize.resource.auto.scale.min.instances=2
cost.optimize.resource.auto.scale.max.instances=10

# 云服务预留实例
cost.optimize.cloud.reserved.instances.enabled=true
cost.optimize.cloud.reserved.instances.term=1
```

## 3.31.3 存储优化

### 优化方法

1. **数据压缩**
   - 启用消息压缩（snappy/lz4/gzip）
   - 压缩比通常可达 30-70%【估算】
   - 在 CPU 与 IO 之间取舍

2. **数据清理**
   - 设置保留策略（Kafka `retention.ms`）
   - 定期清理过期数据
   - 归档冷数据到对象存储

3. **存储分层**
   - 热数据 SSD
   - 冷数据 HDD
   - 归档数据对象存储

| 存储类型 | 适用数据 | 成本等级 | 访问延迟 |
| --------- | --------- | --------- | --------- |
| SSD | 热数据、索引 | 高 | 低 |
| HDD | 冷数据、日志 | 中 | 中 |
| 对象存储 | 归档、备份 | 低 | 高 |

## 3.31.4 网络优化

### 优化策略

1. **减少传输**
   - 启用消息压缩
   - 批量发送与拉取
   - 本地缓存减少跨网络请求

2. **网络拓扑优化**
   - 同机房/同可用区部署，降低跨区流量
   - 使用专线或 VPC 对等连接
   - 合理规划生产者与消费者位置

## 3.31.5 成本优化检查清单

### 优化前

- [ ] 完成资源、存储、网络、运维四类成本拆解
- [ ] 识别 CPU/内存/磁盘使用率 < 30% 的低效资源
- [ ] 设定可量化的降本目标（如总成本降低 20%）

### 优化中

- [ ] 启用消息压缩（snappy/lz4）
- [ ] 配置数据保留与清理策略
- [ ] 实施存储分层（热 SSD/冷 HDD/归档对象存储）
- [ ] 启用自动扩缩容
- [ ] 评估预留实例或 Savings Plans

### 优化后

- [ ] 对比优化前后月度成本
- [ ] 验证性能指标未退化（P99 延迟、吞吐）
- [ ] 持续监控成本波动，设置成本异常告警
- [ ] 每季度复盘成本优化效果并更新目标

> **注意事项**：成本优化不得以牺牲可用性或数据可靠性为代价。关键数据保留周期、副本数、备份策略应在降本前经过风险评估。
>
> 建议将成本优化纳入季度 SRE 复盘议程，形成持续改进闭环。

使用项目脚本 [`topics/scripts/cost-optimize.sh`](../scripts/cost-optimize.sh) 执行成本优化检查：

```bash
bash topics/scripts/cost-optimize.sh
```
