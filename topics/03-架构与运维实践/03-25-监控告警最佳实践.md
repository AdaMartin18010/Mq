## 3.25.1 监控指标选择

### 核心指标

1. **性能指标**
   - 吞吐量（msg/s）
   - 延迟 P50/P95/P99
   - 错误率与请求失败率

2. **资源指标**
   - CPU 使用率
   - 内存使用率
   - 磁盘 IO 与剩余空间
   - 网络带宽与延迟

3. **业务指标**
   - 消息积压（lag/backlog）
   - 消费延迟
   - 连接数与订阅数

### Exporter 与采集配置

项目监控告警配置模板 [`topics/config-templates/monitor-alert-config.properties`](../config-templates/monitor-alert-config.properties) 定义了各系统 Exporter 与采集间隔：

```properties
# Prometheus 与 Alertmanager 地址
monitor.prometheus.url=http://localhost:9090
monitor.alertmanager.url=http://localhost:9093

# Exporter 配置
exporter.kafka.url=http://localhost:9308
exporter.kafka.scrape.interval.seconds=15
exporter.nats.url=http://localhost:7777
exporter.nats.scrape.interval.seconds=15
exporter.rabbitmq.url=http://localhost:9419
exporter.rabbitmq.scrape.interval.seconds=15
```

## 3.25.2 告警规则设计

### 告警阈值

| 指标 | 警告阈值 | 严重阈值 | 采集频率 | 备注 |
| ------ | --------- | --------- | -------- | ------ |
| **吞吐量下降** | >20% 环比下跌 | >50% 环比下跌 | 1 分钟 | 需排除业务低峰期 |
| **P99 延迟** | >1000 ms | >5000 ms | 1 分钟 | 按业务 SLO 调整 |
| **错误率** | >1% | >5% | 1 分钟 | 含生产/消费失败 |
| **CPU 使用率** | >80% | >90% | 30 秒 | 持续 5 分钟触发 |
| **磁盘使用率** | >75% | >85% | 1 分钟 | Kafka 需重点关注 |
| **消费积压** | >10000 | >100000 | 1 分钟 | 按消费能力评估 |

### 告警规则示例

参考项目 Prometheus 告警规则 [`topics/config-templates/prometheus-alert-rules.yml`](../config-templates/prometheus-alert-rules.yml)：

```yaml
# Kafka 严重告警
groups:
- name: kafka-critical
  rules:
  - alert: KafkaOfflinePartitions
    expr: sum(kafka_controller_offlinepartitionscount) > 0
    for: 1m
    labels: {severity: p0, system: kafka}
    annotations:
      summary: "Kafka 存在离线分区（数据不可读写）"
      runbook: "runbooks/kafka-offline-partitions.md"
  - alert: KafkaUnderReplicated
    expr: sum(kafka_server_replicamanager_underreplicatedpartitions) > 0
    for: 10m
    labels: {severity: p1, system: kafka}
    annotations:
      summary: "URP 持续 10 分钟未恢复"
      runbook: "runbooks/kafka-urp.md"

- name: rabbitmq
  rules:
  - alert: RabbitMQQueueBacklog
    expr: max by (queue) (rabbitmq_queue_messages_ready) > 50000
    for: 15m
    labels: {severity: p2, system: rabbitmq}
    annotations:
      summary: "队列积压超 5 万"
      runbook: "runbooks/rmq-backlog.md"
```

## 3.25.3 告警分级管理

### 告警级别

| 级别 | 触发条件 | 响应时效 | 通知渠道 | 升级策略 |
| ------ | --------- | --------- | --------- | --------- |
| **P0 - 严重** | 系统不可用、数据丢失风险 | 立即 | 电话 + 短信 + 钉钉 | 5 分钟未响应升级至主管 |
| **P1 - 重要** | 性能严重下降、影响用户体验 | 30 分钟内 | 短信 + 钉钉 | 30 分钟未处理升级 |
| **P2 - 一般** | 性能轻微下降、不影响核心功能 | 4 小时内 | 钉钉/邮件 | 次日例会跟进 |

## 3.25.4 监控仪表板设计

### 仪表板布局

1. **概览面板**
   - 系统状态总览
   - 关键指标汇总
   - 当前告警状态

2. **性能面板**
   - 吞吐量趋势
   - 延迟分布（P50/P95/P99）
   - 错误率趋势

3. **资源面板**
   - CPU/内存使用
   - 磁盘 IO 与空间
   - 网络流量

项目提供 Grafana 仪表板模板：

```json
{
  "dashboard": {
    "title": "MQ 统一监控",
    "tags": ["kafka", "nats", "rabbitmq"],
    "timezone": "Asia/Shanghai",
    "refresh": "30s"
  }
}
```

## 3.25.5 告警响应流程

### 响应步骤

1. **告警接收**
   - 多渠道通知（邮件/短信/钉钉）
   - 告警聚合与去重
   - 抑制非关键告警

2. **问题定位**
   - 查看监控数据
   - 检查系统日志
   - 复现问题

3. **问题处理**
   - 执行应急预案
   - 修复根因
   - 验证恢复

4. **事后总结**
   - 记录故障与处理过程
   - 优化告警规则
   - 更新 runbook

## 3.25.6 告警质量检查

每周执行告警质量检查脚本 [`topics/scripts/alert-quality-check.sh`](../scripts/alert-quality-check.sh)：

```bash
# 检查规则覆盖与静默状态
bash topics/scripts/alert-quality-check.sh --week
```

检查项包括：

- [ ] 所有告警规则均含 `runbook` 注解
- [ ] 不存在已到期未清除的 Alertmanager 静默
- [ ] P0 告警通知渠道包含电话/短信
- [ ] 告警阈值经过至少 2 周基线校准
- [ ] 每周告警信噪比 > 80%【估算】
- [ ] 消费积压、离线分区、节点宕机三类告警已启用
- [ ] Grafana 仪表板已导入并自动刷新
