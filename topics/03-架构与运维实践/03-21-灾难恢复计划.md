## 3.21.1 灾难场景分级

| 级别 | 场景 | 影响范围 | 典型恢复手段 |
| ------ | ------ | ---------- | -------------- |
| **L1** | 单节点/单 Broker 故障 | 部分分区/队列 | 自动故障转移 + 重启 |
| **L2** | 机架/可用区故障 | 多节点 | 跨机架副本/多 AZ 切换 |
| **L3** | 数据中心级灾难 | 整个集群 | 异地灾备切换 |
| **L4** | 数据损坏/勒索软件 | 数据不可信 | 从异地备份恢复 |

---

## 3.21.2 RTO/RPO 目标

| 系统 | RTO 目标 | RPO 目标 | 实现方式 |
| ------ | ---------- | ---------- | ---------- |
| **Kafka** | <1h | <5min | 多副本 + MirrorMaker 2 / 集群复制 |
| **NATS Core** | <30min | 可接受丢失 | 无状态重建 |
| **NATS JetStream** | <1h | <5min | Stream 复制 + 快照 |
| **RabbitMQ** | <1h | <10min | Quorum Queue + 定义备份 |
| **Pulsar** | <1h | 0（同步复制） | Geo-Replication |

## 3.21.3 备份策略

### 备份类型对比

| 备份类型 | 频率 | RPO | 恢复速度 | 存储成本 |
| ---------- | ------ | ----- | ---------- | ---------- |
| **全量备份** | 每周 | 高 | 快 | 高 |
| **增量备份** | 每日 | 中 | 中 | 中 |
| **实时复制** | 持续 | 低/0 | 最快 | 高 |
| **元数据快照** | 每小时 | 低 | 快 | 低 |

### 配置示例

```properties
# config-templates/disaster-recovery-config.properties
disaster.recovery.backup.enabled=true
disaster.recovery.backup.strategy=incremental
disaster.recovery.backup.frequency=hourly
disaster.recovery.backup.retention.days=30
disaster.recovery.backup.storage.type=remote
disaster.recovery.backup.storage.remote.host=backup-server
disaster.recovery.backup.storage.remote.path=/backup/mq
```

### 执行备份

```bash
# 全量备份所有系统
./scripts/backup-all.sh /backup/mq/$(date +%Y%m%d)

# 验证备份有效性
./scripts/backup-verify.sh /backup/mq/$(date +%Y%m%d)
```

## 3.21.4 Kafka 灾难恢复

### 恢复步骤

1. **评估损失**

   ```bash
   # 检查日志段是否可解析
   kafka-run-class.sh kafka.tools.DumpLogSegments \
     --files /var/lib/kafka-logs/topic-0/00000000000000000000.log \
     --print-data-log | head -100
   ```

2. **从备份恢复**

   ```bash
   # 恢复配置与数据
   ./scripts/restore-all.sh /backup/mq/20261118
   ```

3. **重建集群并验证**

   ```bash
   # 启动集群
   ./scripts/deploy-kafka.sh

   # 检查 Topic 与 ISR
   kafka-topics.sh --bootstrap-server localhost:9092 --list
   kafka-metadata-quorum.sh --bootstrap-server localhost:9092 describe --status
   ```

### Kafka 灾备检查清单

- [ ] `log.dirs` 数据已按备份恢复或从 MirrorMaker 2 消费重建
- [ ] `meta.properties` 与 `cluster.id` 一致
- [ ] 所有 Topic 分区 Leader 分配正常
- [ ] 消费者组位移已恢复或允许从最新/最早重放

## 3.21.5 NATS 灾难恢复

### 恢复步骤

```bash
# 1. 恢复配置文件
cp /backup/mq/20261118/nats-server.conf /etc/nats/nats-server.conf

# 2. 恢复 JetStream 存储数据（如有）
rsync -av /backup/mq/20261118/jetstream/ /data/jetstream/

# 3. 启动集群
./scripts/deploy-nats.sh

# 4. 验证
nats stream list
nats server report jetstream
```

### NATS 灾备检查清单

- [ ] `nats-server.conf` 已恢复，路由与 JetStream 配置正确
- [ ] JetStream 存储目录权限正确（通常为 nats:nats）
- [ ] 集群路由数等于节点数减 1
- [ ] Stream 副本状态正常，无 `LOST` 或 `CORRUPT`

## 3.21.6 RabbitMQ 灾难恢复

### 恢复步骤

```bash
# 1. 恢复定义文件
./scripts/restore-all.sh /backup/mq/20261118

# 或手动导入
rabbitmqctl import_definitions /backup/mq/20261118/rabbitmq_definitions.json

# 2. 加入集群
rabbitmqctl stop_app
rabbitmqctl join_cluster rabbit@node1
rabbitmqctl start_app

# 3. 验证
rabbitmqctl cluster_status
rabbitmqctl list_queues name type messages
```

### RabbitMQ 灾备检查清单

- [ ] `definitions.json` 已导入，vhost、用户、策略完整
- [ ] Quorum Queue 多数派节点可用，队列状态为 `running`
- [ ] Classic Queue 数据已从备份或 shovel 恢复
- [ ] 插件版本与 RabbitMQ 4.x 兼容

## 3.21.7 跨地域复制

### Kafka 跨地域复制

```bash
# MirrorMaker 2 示例
connect-mirror-maker.sh mm2.properties
```

```properties
# mm2.properties
clusters=source,target
source.bootstrap.servers=source-kafka:9092
target.bootstrap.servers=target-kafka:9092
source->target.enabled=true
source->target.topics=orders,events
checkpoints.topic.replication.factor=3
heartbeats.topic.replication.factor=3
```

### 跨地域复制 RPO 对比

| 复制模式 | RPO | 延迟 | 适用场景 |
| ---------- | ----- | ------ | ---------- |
| **同步复制** | 0 | 高（>10ms） | 金融交易 |
| **异步复制** | 秒级 | 低 | 日志、埋点 |
| **定时备份** | 小时级 | 无实时 | 归档、合规 |

## 3.21.8 恢复演练计划

| 演练类型 | 频率 | 内容 | 成功标准 |
| ---------- | ------ | ------ | ---------- |
| **备份恢复演练** | 每月 | 从备份恢复单个 Topic/Queue | 数据完整，RTO 达标 |
| **单节点故障演练** | 每月 | 停止一个节点并恢复 | 服务无中断 |
| **跨 AZ 切换演练** | 每季度 | 切换至灾备集群 | RPO 达标 |
| **全量灾备演练** | 每年 | 完整重建生产集群 | RTO/RPO 均达标 |

## 3.21.9 灾难恢复检查清单

### 备份与可用性

- [ ] 备份任务已按计划执行，最近 7 天备份均成功
- [ ] `./scripts/backup-verify.sh <backup_dir>` 验证通过
- [ ] 异地备份至少保留 2 个副本，跨可用区/区域
- [ ] 灾备集群资源已预留，可随时接管流量

### 恢复流程

- [ ] RTO/RPO 目标已书面化并获业务方确认
- [ ] 灾难切换 Runbook 已更新，含 DNS/负载均衡切换步骤
- [ ] 恢复脚本 `./scripts/restore-all.sh` 已在测试环境验证
- [ ] 关键联系人、厂商支持通道、Escalation 路径已记录

### 演练与审计

- [ ] 本年度至少完成 1 次全量灾备演练
- [ ] 演练报告已归档，未达标项已闭环
- [ ] `./scripts/disaster-recovery-check.sh` 每月执行，无告警
