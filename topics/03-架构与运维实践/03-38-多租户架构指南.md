## 3.38.1 多租户场景与隔离级别

多租户消息队列常见于 SaaS、云服务和大型企业内部共享平台。落地前需先选定隔离级别。

| 隔离级别 | 实现方式 | 安全等级 | 成本 | 适用场景 |
| ---------- | ---------- | ---------- | ------ | ---------- |
| 完全隔离 | 独立集群、独立网络、独立存储 | 最高 | 高 | 金融核心、强合规租户 |
| 逻辑隔离 | 共享集群，Topic/Subject/vhost 隔离 + ACL | 中高 | 中 | 普通 SaaS 客户 |
| 混合隔离 | 关键租户独立，普通租户共享 | 中高 | 中低 | 多层级 SaaS 平台 |

## 3.38.2 命名空间与配额策略

### 命名空间设计

统一命名规范可降低越权与误操作风险：

```text
<tenant>.<domain>.<event>
# 示例
acme.orders.created
globex.inventory.updated
```

Kafka 示例：

```text
<tenant>-<domain>-<event>
acme-orders-created
globex-inventory-updated
```

### 配额策略

| 资源类型 | 配额维度 | 建议默认值 | 超限处理 |
| ---------- | ---------- | ------------ | ---------- |
| 生产吞吐 | bytes/sec | 10 MB/s/租户【估算】 | 限流/告警 |
| 消费吞吐 | bytes/sec | 20 MB/s/租户【估算】 | 限流/告警 |
| 连接数 | connections | 100/租户【估算】 | 拒绝连接 |
| Topic 数 | count | 50/租户【估算】 | 审批后扩容 |
| 存储空间 | bytes | 100 GB/租户【估算】 | 拒绝写入或归档 |

## 3.38.3 Kafka 多租户落地

### Topic 与 ACL 隔离

```java
// Topic 命名隔离
String tenantTopic = "tenant-" + tenantId + "-orders";

// ACL 权限隔离：仅允许该租户用户读写自己的 Topic
AclBinding acl = new AclBinding(
    new ResourcePattern(ResourceType.TOPIC, "tenant-" + tenantId + "-*", PatternType.PREFIXED),
    new AccessControlEntry("User:" + tenantId, "*", AclOperation.ALL, AclPermissionType.ALLOW)
);
```

### 配额配置

```properties
# server.properties：为租户设置默认配额
quota.producer.default=10485760
quota.consumer.default=20971520
quota.window.size.seconds.client=1

# 动态为指定用户/客户端设置配额（推荐）
# kafka-configs.sh --bootstrap-server localhost:9092 \
#   --alter --add-config 'producer_byte_rate=10485760,consumer_byte_rate=20971520' \
#   --entity-type users --entity-name tenant-acme
```

### Kafka 多租户检查命令

```bash
# 查看租户配额
kafka-configs.sh --bootstrap-server localhost:9092 \
  --describe --entity-type users --entity-name tenant-acme

# 查看 Topic ACL
kafka-acls.sh --bootstrap-server localhost:9092 --topic 'tenant-acme-*' --list
```

## 3.38.4 NATS 多租户落地

### 账户与 Stream 隔离

```go
// Subject 命名隔离
tenantSubject := fmt.Sprintf("tenant.%s.orders", tenantID)

// 账户隔离（JetStream）
js.AddAccount("tenant1")
js.AddStream(&nats.StreamConfig{
    Name:     "tenant1-stream",
    Subjects: []string{"tenant.tenant1.*"},
    MaxMsgs:  1000000,
    MaxBytes: 10 * 1024 * 1024 * 1024, // 10 GB
})
```

### NATS 配置检查

```bash
# 检查账户与权限配置
grep -E "accounts|jetstream|authorization|max_subscriptions" nats-server.conf

# 检查账户列表（需 nats-cli）
nats --server nats://localhost:4222 server report accounts
```

## 3.38.5 RabbitMQ 多租户落地

### Virtual Host 隔离

```bash
# 为每个租户创建独立 vhost
rabbitmqctl add_vhost tenant-acme
rabbitmqctl add_vhost tenant-globex

# 创建租户用户并绑定到对应 vhost
rabbitmqctl add_user acme-user strong-password
rabbitmqctl set_permissions -p tenant-acme acme-user "^acme\\..*" "^acme\\..*" "^acme\\..*"

# 查看 vhost 与用户
rabbitmqctl list_vhosts
rabbitmqctl list_permissions -p tenant-acme
```

### RabbitMQ 配额

```bash
# 设置 vhost 最大连接数（RabbitMQ 3.8+）
rabbitmqctl set_vhost_limits -p tenant-acme '{"max-connections": 100}'

# 设置 vhost 最大队列数
rabbitmqctl set_vhost_limits -p tenant-acme '{"max-queues": 50}'
```

## 3.38.6 多租户监控与计费

### 关键监控指标

| 指标 | 用途 | 告警阈值 |
| ------ | ------ | ---------- |
| 租户消息生产速率 | 容量规划、计费 | 超配额 80% 告警 |
| 租户消息消费速率 | 容量规划、Lag 预警 | 持续低于生产速率 5 分钟 |
| 租户连接数 | 资源控制 | 超配额 90% 告警 |
| 租户存储占用 | 成本控制、扩容 | 超配额 80% 告警 |
| 租户认证失败次数 | 安全监控 | 5 分钟 ≥10 次 |

## 3.38.7 多租户检查清单

- [ ] 已根据业务与合规要求选择隔离级别（完全/逻辑/混合）。
- [ ] 已制定租户命名规范（Topic/Subject/vhost/队列）。
- [ ] Kafka：已配置租户级 ACL（PREFIXED/LITERAL），禁止跨租户访问。
- [ ] Kafka：已为租户设置生产/消费配额（`producer_byte_rate`、`consumer_byte_rate`）。
- [ ] NATS：已启用账户隔离或用户名/密码认证，Subject 按租户前缀隔离。
- [ ] NATS：已设置 JetStream Stream 的 `MaxMsgs`/`MaxBytes` 上限。
- [ ] RabbitMQ：已为每个租户创建独立 vhost，并配置用户权限。
- [ ] RabbitMQ：已设置 vhost 连接数/队列数上限。
- [ ] 已部署租户级监控指标与配额告警。
- [ ] 已建立租户操作审计日志，保留时间 ≥90 天【估算】。
- [ ] 已执行 `scripts/multi-tenant-check.sh` 并修复发现问题。
