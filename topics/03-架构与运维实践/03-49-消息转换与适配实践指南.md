## 3.49.1 转换适配落地场景

### 适用场景

1. **格式转换**：上游系统输出 JSON，下游分析平台要求 Avro/Protobuf；或遗留系统输出 XML，需要统一为 JSON 进入 Kafka。
2. **协议适配**：MQTT 设备接入后需写入 Kafka 持久化；Kafka 订单流需推送到 RabbitMQ 触发业务工作流。
3. **Schema 映射**：多团队 topic 字段命名、类型不一致，通过字段映射与 Schema Registry 统一版本管理。
4. **数据清洗与增强**：在转换过程中补齐时间戳、单位换算、敏感字段脱敏，并写入目标 topic。

## 3.49.2 格式转换配置

### JSON / XML / Protobuf / Avro 互转

在 `topics/config-templates/transform-config.properties` 中，格式转换由以下参数控制：

- `transform.format.enabled=true`：启用格式转换。
- `transform.format.from=json`：源格式，可选 `json`/`xml`/`protobuf`/`avro`。
- `transform.format.to=protobuf`：目标格式。
- `transform.format.schema.registry.url=http://localhost:8081`：Confluent Schema Registry 地址，用于 Avro/Protobuf schema 拉取与注册。

Kafka Connect 常见 Converter 配置示例：

```properties
# Source Connector：从数据库读取后统一转为 Avro
key.converter=io.confluent.connect.avro.AvroConverter
key.converter.schema.registry.url=http://localhost:8081
value.converter=io.confluent.connect.avro.AvroConverter
value.converter.schema.registry.url=http://localhost:8081

# Sink Connector：写入下游前由 Avro 转 JSON
value.converter=org.apache.kafka.connect.json.JsonConverter
value.converter.schemas.enable=false
```

### 编码转换

若源端为 GBK/ISO-8859-1，目标端要求 UTF-8，需在应用层或 SMT 中显式转码：

- Kafka Connect 可通过 `org.apache.kafka.connect.transforms.Cast` 转换字段类型，但编码转换通常需要自定义 SMT。
- RabbitMQ/NATS 应用层消费时，使用 `body.decode('utf-8')` 或 `bytes(data).decode('gbk')` 处理。
- 在模板中开启 `transform.content.data.cleaning.enabled=true`，并在清洗脚本中统一编码。

## 3.49.3 Kafka Connect 转换器配置

### 内置 SMT 配置

Kafka Connect 通过 `transforms` 链实现字段、路由、格式转换。常用 SMT 包括：

- `Cast`：字段类型转换，如将字符串金额转为 `float64`。
- `ReplaceField`：重命名或删除字段。
- `ValueToKey`：将 value 中某字段提取为 key。
- `Flatten`：嵌套 JSON 拍平。
- `RegexRouter`：按正则修改目标 topic 名。

示例：将 `orders` topic 中 `amount` 字段转为 double，并过滤掉 `internal_id`。

```json
{
  "name": "orders-transform-sink",
  "config": {
    "connector.class": "org.apache.kafka.connect.file.FileStreamSinkConnector",
    "topics": "orders",
    "transforms": "cast,replace",
    "transforms.cast.type": "org.apache.kafka.connect.transforms.Cast$Value",
    "transforms.cast.spec": "amount:float64",
    "transforms.replace.type": "org.apache.kafka.connect.transforms.ReplaceField$Value",
    "transforms.replace.blacklist": "internal_id"
  }
}
```

### 自定义 Converter 配置

当内置 SMT 无法满足时，开发自定义 `Transformation<T>` 或 `Converter` 类：

1. 实现 `org.apache.kafka.connect.transforms.Transformation` 接口。
2. 打包为 JAR 后放入 Kafka Connect 的 `plugin.path`。
3. 在 connector 配置中引用：
   - `"transforms.custom.type": "com.example.transforms.MyTransform"`
   - `"transforms.custom.param": "value"`
4. 重启 Connect worker：`bin/connect-distributed.sh config/connect-distributed.properties`。

## 3.49.4 协议适配配置

### Kafka 到 RabbitMQ 适配

使用 Kafka Connect 或自定义桥接将 Kafka topic 映射到 RabbitMQ exchange/routing key。参考模板参数：

- `adapter.type=kafka-to-rabbitmq`
- `adapter.source.type=kafka`、`adapter.source.brokers=localhost:9092`
- `adapter.target.type=rabbitmq`、`adapter.target.host=localhost`、`adapter.target.port=5672`

落地步骤：

1. 在 RabbitMQ 中创建 exchange：`amqp_exchange=orders`，类型 `topic` 或 `direct`。
2. 配置 routing key 映射文件 `/etc/mq/topic-mapping.json`，例如将 Kafka topic `orders.created` 映射为 RabbitMQ routing key `orders.created`。
3. 开启 `bridge.transform.enabled=true`，统一消息格式为 JSON。
4. 设置 `bridge.error.handling.strategy=dlq`，失败消息写入 `bridge-dlq`。

### NATS 到 Kafka 适配

NATS Core 或 JetStream 订阅消息后转发到 Kafka：

- `nats.transform.enabled=true`：启用 NATS 侧转换。
- `nats.transform.type=format`：格式转换，如 JSON 转 Avro。
- `nats.transform.format.from=json`、`nats.transform.format.to=protobuf`。
- `adapter.source.type=nats`、`adapter.target.type=kafka`。

落地注意：

1. NATS subject 支持通配符 `orders.*`，需在映射文件中展开为 Kafka topic `orders`。
2. JetStream 消费使用 `PullSubscribe` 并设置 `AckWait=30s`，转换失败时调用 `Msg.Nak()` 重试。
3. Kafka Producer 配置 `acks=all`、`retries=3`、`enable.idempotence=true`，保证跨协议投递不丢失。

下表对比 Kafka Connect 与自定义桥接在协议适配中的落地差异：

| 维度 | Kafka Connect + SMT | 自定义应用层桥接 |
|---|---|---|
| 配置方式 | connector JSON + transforms 链 | 代码 + 配置文件 |
| 协议范围 | Kafka 生态内源/_sink 为主 | 任意协议（MQTT/NATS/RabbitMQ） |
| 错误处理 | `errors.tolerance=all` + Dead Letter Queue | 自定义 retry + DLQ |
| 性能调优 | `tasks.max`、`batch.size` | 连接池、线程池、批量发送 |
| 运维成本 | 低（Connect 集群统一管理） | 高（需自研监控与升级） |

## 3.49.5 Schema 映射配置

### Schema Registry 映射

Confluent Schema Registry 用于管理 Avro/Protobuf/JSON Schema 版本：

1. 注册源 schema：
   ```bash
   curl -X POST -H "Content-Type: application/vnd.schemaregistry.v1+json" \
     --data '{"schema": "{\"type\":\"record\",\"name\":\"Order\",\"fields\":[{\"name\":\"order_id\",\"type\":\"string\"}]}"}' \
     http://localhost:8081/subjects/orders-value/versions
   ```
2. 注册目标 schema 并建立字段映射关系。
3. 在转换配置中指定 `transform.format.schema.registry.url=http://localhost:8081`。
4. 使用 `SchemaCompatibility.BACKWARD` 或 `FULL` 策略，确保消费端能读取新旧版本数据。

### 字段映射文件

`transform.content.field.mapping.enabled=true` 时，读取 `/etc/mq/field-mapping.json` 完成字段名、类型、默认值映射。示例文件：

```json
{
  "mappings": [
    {"from": "orderId", "to": "order_id", "type": "string"},
    {"from": "amt", "to": "amount", "type": "double", "default": 0.0},
    {"from": "createTime", "to": "created_at", "type": "timestamp", "format": "iso8601"}
  ],
  "remove": ["temp_flag"],
  "add": [
    {"name": "processed_at", "type": "timestamp", "value": "now()"}
  ]
}
```

## 3.49.6 转换适配检查清单

### 实施前

- [ ] 梳理源/目标格式：JSON、XML、Protobuf、Avro 及其版本。
- [ ] 确认是否需要 Schema Registry：`transform.format.schema.registry.url` 是否可达。
- [ ] 制定字段映射文件 `/etc/mq/field-mapping.json` 并评审字段类型与默认值。
- [ ] 选择转换路径：Kafka Connect SMT、Kafka Streams、NATS/RabbitMQ 应用层。

### 实施中

- [ ] Kafka Connect 已配置 `key.converter` 与 `value.converter`，Avro/Protobuf 指向 Schema Registry。
- [ ] SMT 链已验证：`transforms.cast.spec` 类型转换无精度丢失；`ReplaceField` 黑名单不误删关键字段。
- [ ] 协议适配参数已配置：`adapter.type`、`adapter.source.brokers`、`adapter.target.host/port`。
- [ ] 错误处理启用：`transform.error.handling.enabled=true`、`strategy=dlq`、`retry.max.attempts=3`、`retry.backoff.ms=1000`。
- [ ] 性能优化启用：`transform.optimization.cache.enabled=true`、`cache.size=10000`、`cache.ttl=300`；批量转换 `batch.size=100`。

### 实施后

- [ ] 运行 `topics/scripts/transform-test.sh kafka format` 验证格式转换。
- [ ] 校验目标 topic 消息 schema 与字段映射是否符合预期。
- [ ] 监控 `transform_count`、`transform_latency`、`transform_errors`，错误率低于 `transform.monitor.alert.error.threshold=0.01`。
- [ ] 压测转换吞吐，确认延迟低于 `transform.monitor.alert.latency.threshold=1000` ms。
- [ ] 检查 DLQ 中是否存在转换失败消息，分析失败原因并修复规则。
