## 3.23.1 预防策略

故障预防遵循 **“监控先行、容量预留、变更可控、自动恢复”** 四原则：

| 原则 | 落地动作 | 检查频率 |
| ------ | ---------- | ---------- |
| **监控先行** | 关键指标全覆盖，告警阈值合理 | 实时 |
| **容量预留** | CPU/内存/磁盘/连接数预留 ≥20% | 每周 |
| **变更可控** | 灰度发布、回滚方案、变更窗口 | 每次变更 |
| **自动恢复** | 健康检查 + 自动重启 + 通知 | 实时 |

## 3.23.2 监控预警体系

### 关键指标矩阵

| 指标类型 | Kafka | NATS | RabbitMQ | 告警阈值 |
| ---------- | ------- | ------ | ---------- | ---------- |
| **吞吐下降** | kafka_server_brokertopicmetrics_messagesinpersec_rate | nats_varz_in_msgs | message_stats.publish_details.rate | 较基线下降 >20% |
| **延迟** | kafka_consumer_lag_sum / 消费延迟 | nats_rtt | queue_message_stats.deliver_get | P99 >1000ms |
| **错误率** | kafka_network_request_errors | nats_slow_consumers | rabbitmq_connections | >1% |
| **资源使用** | process_cpu_seconds_total / mem | nats_varz_mem | rabbitmq_process_resident_memory_bytes | CPU/内存 >80% |
| **磁盘使用** | kafka_log_size_bytes / 总量 | jetstream_store_dir_used | disk_free | >80% 警告，>90% 紧急 |

### 告警规则示例

参考 `config-templates/monitor-alert-config.properties`：

```yaml
# prometheus alert rules
groups:
  - name: mq_prevention
    rules:
      - alert: KafkaConsumerLagGrowing
        expr: kafka_consumer_lag_sum > 100000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Kafka 消费 Lag 超过 10 万"

      - alert: NATSConnectionsHigh
        expr: nats_varz_connections > 8000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "NATS 连接数超过 8000"
```

### 监控检查脚本

```bash
# 检查监控告警系统
./scripts/monitor-alert-check.sh

# 检查告警规则是否触发
./scripts/alerts-check.sh all
```

## 3.23.3 容量管理

### 容量监控项

| 资源 | 监控命令/指标 | 预警阈值 | 紧急阈值 |
| ------ | --------------- | ---------- | ---------- |
| **磁盘** | `df -h` / `kafka_log_size_bytes` | 70% | 90% |
| **内存** | `free -h` / `nats_varz_mem` | 70% | 90% |
| **连接数** | `nats_varz_connections` | 70% of max | 90% of max |
| **队列积压** | `rabbitmqctl list_queues` | 10 万 | 100 万 |

### 容量检查脚本

```bash
# 容量检查
./scripts/capacity-check.sh all

# 自动扩缩容检查
./scripts/scale.sh status
```

## 3.23.4 变更管理

### 变更流程

```text
1. 变更申请
   └── 影响范围评估 + 回滚方案 + 窗口时间
2. 灰度验证
   └── 在 1 个 Broker/节点/Topic 上验证
3. 全量发布
   └── 滚动发布，每批次间隔 ≥5min
4. 变更后验证
   └── ./scripts/health-check-all.sh 通过
```

### 变更检查清单

- [ ] 变更内容已在测试环境验证
- [ ] 回滚命令与回滚时间已明确
- [ ] 变更窗口已通知业务方
- [ ] 灰度比例从 5% → 25% → 50% → 100% 递进
- [ ] 变更后 `./scripts/health-check-all.sh` 无异常
- [ ] 变更记录已归档至变更管理系统

## 3.23.5 日志与审计

### 关键日志

| 系统 | 日志路径 | 审计重点 |
| ------ | ---------- | ---------- |
| Kafka | `/var/log/kafka/server.log` | 授权拒绝、ISR 变化、Controller 切换 |
| NATS | `/var/log/nats/nats.log` | 认证失败、慢消费者、路由异常 |
| RabbitMQ | `/var/log/rabbitmq/` | 连接异常、队列告警、插件错误 |

### 日志巡检命令

```bash
# 检查 Kafka 异常
journalctl -u kafka | grep -i "error\|warn" | tail -50

# 检查 NATS 认证失败
grep -i "authentication failed" /var/log/nats/nats.log

# 检查 RabbitMQ 告警
rabbitmqctl status | grep -i "alarm"
```

## 3.23.6 自动化防护

### 自动恢复脚本

```bash
# 配置定时健康检查与自动恢复
crontab -e
*/5 * * * * /path/to/scripts/health-check-all.sh || /path/to/scripts/auto-recovery.sh all 3
```

### 自动化防护项

| 防护项 | 触发条件 | 动作 |
| -------- | ---------- | ------ |
| **Broker 自动重启** | 健康检查失败 3 次 | `./scripts/auto-recovery.sh kafka 3` |
| **磁盘清理** | 磁盘使用 >85% | `./scripts/cleanup-old-data.sh` |
| **连接限流** | 连接数 >90% | 触发 rate-limit 策略 |
| **Topic 自动扩展** | Lag >10 万持续 5min | 增加分区或消费者 |

## 3.23.7 故障预防检查清单

### 日常检查

- [ ] `./scripts/health-check-all.sh` 执行通过
- [ ] `./scripts/alerts-check.sh all` 无未处理告警
- [ ] 监控大盘无红色 Critical 告警 >5min
- [ ] 磁盘使用率 <80%，内存使用率 <80%
- [ ] 关键 Topic/Queue 消费 Lag < 阈值

### 定期检查

- [ ] 每周：执行 `./scripts/capacity-check.sh all`，容量趋势未超 70%
- [ ] 每月：审查告警规则，消除无效告警
- [ ] 每季度：执行故障恢复演练，RTO/RPO 达标
- [ ] 每半年：安全审计 `./scripts/security-audit.sh all`
- [ ] 每年：灾难恢复全量演练，DR 计划更新
