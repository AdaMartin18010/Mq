## 3.34.1 数据分类与分级

数据分类是数据治理的前提。建议按敏感度、业务域、合规要求三个维度打标签，并在 Topic/Stream 命名或元数据中体现。

| 敏感度级别 | 示例数据 | 治理要求 |
| ------------ | ---------- | ---------- |
| 公开（public） | 公告、公开配置 | 常规备份，允许广泛读取 |
| 内部（internal） | 业务事件、监控指标 | 认证读取，按角色授权 |
| 机密（confidential） | 订单明细、用户行为 | TLS 传输、字段脱敏、审计日志 |
| 受限（restricted） | 支付信息、医疗 PHI | 端到端加密、最小权限、合规留存 |

Topic 命名建议内嵌分类标识，例如：

```text
pub.config.system       # 公开配置
customer.orders.cn      # 内部订单事件（customer 域 + 业务子域）
conf.payment.events     # 机密支付事件
rest.health.records     # 受限健康记录
```

## 3.34.2 Schema 治理

使用 Schema Registry 集中管理消息 Schema，并设置兼容性策略，避免消费者因字段变更而中断。

### 注册与检查 Schema

```bash
# 1. 检查 Schema Registry 是否运行
curl -s http://localhost:8081/subjects | jq .

# 2. 注册新的 Avro Schema（向后兼容）
curl -X POST -H "Content-Type: application/vnd.schemaregistry.v1+json" \
  --data '{"schema": "{\"type\":\"record\",\"name\":\"Order\",\"fields\":[{\"name\":\"order_id\",\"type\":\"string\"},{\"name\":\"amount\",\"type\":\"double\"}]}"}' \
  http://localhost:8081/subjects/orders-value/versions

# 3. 查看某个 Subject 的兼容性配置
curl -s http://localhost:8081/config/orders-value
```

### Schema 兼容性策略

| 策略 | 含义 | 适用场景 |
| ------ | ------ | ---------- |
| BACKWARD | 新 Schema 可被旧数据消费 | 先升级消费者，再升级生产者（推荐默认） |
| FORWARD | 旧 Schema 可被新数据消费 | 先升级生产者，再升级消费者 |
| FULL | 同时满足 BACKWARD 与 FORWARD | 双向兼容要求高的场景 |
| NONE | 不校验兼容性 | 仅用于受控测试环境 |

## 3.34.3 数据生命周期管理

消息队列数据生命周期管理的核心是：保留时间、保留大小、归档策略、清理计划。

### Kafka 生命周期配置

```properties
# server.properties
log.retention.hours=168          # 7 天
log.retention.bytes=10737418240  # 10 GB 每分区
log.cleanup.policy=delete        # delete/compact
log.segment.bytes=1073741824     # 1 GB 每段
```

### 通用数据治理配置模板

参考 `config-templates/data-governance-config.properties`：

```properties
# 数据生命周期管理配置
data.governance.lifecycle.enabled=true
data.governance.lifecycle.retention.enabled=true
data.governance.lifecycle.retention.time.days=7
data.governance.lifecycle.retention.size.bytes=10737418240
data.governance.lifecycle.archiving.enabled=true
data.governance.lifecycle.archiving.strategy=tiering
data.governance.lifecycle.archiving.hot.storage.days=1
data.governance.lifecycle.archiving.cold.storage.days=30
data.governance.lifecycle.archiving.archive.storage.days=365
data.governance.lifecycle.cleanup.enabled=true
data.governance.lifecycle.cleanup.schedule=0 2 * * *
```

### 生命周期阶段对照

| 阶段 | 操作 | 检查项 |
| ------ | ------ | -------- |
| 创建 | Schema 校验、分类标记 | 必填字段、数据类型、分类标签 |
| 存储 | 落盘、副本同步、索引 | `min.insync.replicas`、磁盘水位 |
| 使用 | 授权消费、血缘追踪 | 消费者组 Lag、数据血缘记录 |
| 归档 | 冷热分层、压缩、转存对象存储 | 归档完整性校验 |
| 销毁 | TTL 到期删除、安全擦除 | 删除脚本执行记录、可恢复性验证 |

## 3.34.4 数据质量监控

数据质量通过完整性、准确性、一致性、时效性四个维度度量。

### 质量检查命令示例

```bash
# 检查 Kafka Topic 是否有空消息或异常大消息
kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic orders --from-beginning --max-messages 1000 \
  --property print.timestamp=true --property print.key=true | \
  awk -F'\t' '{if(length($0)==0) empty++; if(length($0)>10000) big++} \
    END{print "empty="empty " big="big}'

# 检查 Schema 注册完整性
curl -s http://localhost:8081/subjects | jq 'length'
```

### 数据质量指标与阈值

| 指标 | 定义 | 建议阈值 | 告警动作 |
| ------ | ------ | ---------- | ---------- |
| 完整性 | 必填字段非空比例 | ≥99.5%【估算】 | 触发清洗或拒绝写入 |
| 准确性 | Schema 校验通过率 | ≥99.9%【估算】 | 隔离异常消息到 DLQ |
| 一致性 | 跨系统关键字段一致率 | ≥99.9%【估算】 | 启动对账任务 |
| 时效性 | 端到端延迟 P99 | 按业务 SLA | 扩容或降级 |

## 3.34.5 数据安全与脱敏

数据安全控制包括传输加密、存储加密、字段脱敏、访问审计四类。

### 字段脱敏示例

```bash
# 示例：对日志中的手机号做中间四位掩码
python3 - <<'PY'
import json
payload = {"user_id": "u12345", "mobile": "13800138000", "amount": 199.99}
payload["mobile"] = payload["mobile"][:3] + "****" + payload["mobile"][-4:]
print(json.dumps(payload, ensure_ascii=False))
PY
```

### 数据分类与脱敏策略

| 数据类型 | 传输 | 存储 | 日志/测试 |
| ---------- | ------ | ------ | ----------- |
| 公开 | TLS 可选 | 不加密 | 明文 |
| 内部 | TLS | 磁盘加密 | 明文 |
| 机密 | TLS + mTLS | 加密 | 部分脱敏 |
| 受限 | TLS + mTLS + 端到端加密 | 加密 + 密钥托管 | 完全脱敏或哈希 |

## 3.34.6 自动化数据治理检查

项目提供两个脚本辅助落地：

```bash
cd E:/_src/Mq/topics

# 生成数据治理检查报告
bash scripts/data-governance.sh data-governance-report-2026-11.txt

# 检查 Schema 管理、数据质量、生命周期
bash scripts/data-governance-check.sh
```

`scripts/data-governance-check.sh` 会尝试连接本地 Schema Registry、输出保留策略与质量指标建议，适合纳入 CI 或定时任务。

## 3.34.7 数据治理检查清单

- [ ] 已制定数据分类分级标准，并在 Topic/Stream 命名或元数据中体现。
- [ ] 已部署 Schema Registry，核心 Topic 已注册 Schema。
- [ ] Schema 兼容性策略已设置（建议默认 BACKWARD）。
- [ ] 已配置数据保留策略（`log.retention.hours`、`retention.ms`、大小限制）。
- [ ] 已制定冷热归档策略与对象存储转存流程。
- [ ] 已配置定时清理任务，并留存执行日志。
- [ ] 机密/受限数据已启用传输加密与字段脱敏。
- [ ] 已建立数据质量指标（完整性、准确性、一致性、时效性）与告警阈值。
- [ ] 已执行 `scripts/data-governance-check.sh` 并修复发现问题。
- [ ] 已记录数据血缘（生产者、消费者、Schema、保留策略）。
- [ ] 已按季度复评分类标准与保留策略【估算】。
