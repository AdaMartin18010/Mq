## 3.50.1 桥接集成落地场景

### 适用场景

1. **Kafka-MQTT 桥接**：IoT 设备通过 MQTT 上报遥测数据，需要持久化到 Kafka 供实时分析；或 Kafka 下发控制指令到 MQTT broker，由设备订阅执行。
2. **MirrorMaker 跨集群复制**：同城双活、异地灾备、数据湖归档，需要将 topic 从源 Kafka 集群单向或双向同步到目标集群。
3. **跨系统集成**：已有 RabbitMQ 订单系统与新增 Kafka 大数据平台互通；NATS 微服务事件需写入 Kafka 做审计。
4. **混合云/多云**：本地 IDC 与云端 Kafka 之间通过桥接实现低耦合数据流动。

## 3.50.2 Kafka-MQTT 桥接配置

### EMQX 规则引擎桥接

EMQX 内置规则引擎可直接将 MQTT 消息转发到 Kafka，落地步骤如下：

1. 在 EMQX Dashboard 中创建 Kafka 数据桥接（Data Bridge）：
   - 类型：`Kafka Producer`
   - Bootstrap Servers：`localhost:9092`
   - Topic：`mqtt.messages`
   - 消息模板：保留 `clientid`、`topic`、`payload`、`timestamp`。
2. 创建规则（Rule）并绑定桥接：
   - SQL：`SELECT clientid, topic, payload, timestamp FROM "t/#"`
   - 动作：调用上面创建的 Kafka 数据桥接。
3. 配置 EMQX 参数以限制大消息：
   - `zone.external.max_packet_size=1048576`：单包 1 MB。
   - `zone.external.max_clientid_len=65535`：避免 clientid 过长。

### Kafka Connect MQTT Connector

若使用 Confluent/Kafka Connect 生态，可部署 `mqtt-source-connector`：

```json
{
  "name": "mqtt-source",
  "config": {
    "connector.class": "io.confluent.connect.mqtt.MqttSourceConnector",
    "kafka.topic": "mqtt.messages",
    "mqtt.server.uri": "tcp://localhost:1883",
    "mqtt.topics": "sensors/#",
    "mqtt.username": "bridge",
    "mqtt.password": "bridge-password",
    "tasks.max": "4",
    "key.converter": "org.apache.kafka.connect.storage.StringConverter",
    "value.converter": "org.apache.kafka.connect.json.JsonConverter",
    "value.converter.schemas.enable": "false"
  }
}
```

落地检查：

- MQTT QoS 与 Kafka `acks` 对应关系：QoS 1 建议 Kafka `acks=all`；QoS 0 可接受 `acks=1` 以换取更低延迟。
- 消息顺序：MQTT 主题到 Kafka topic 分区映射应保持 `clientid` 或设备 ID 作为 key，避免乱序。
- 连接保活：`mqtt.keepalive.interval=60`，MQTT broker 断线时触发 Kafka Producer 重连。

## 3.50.3 MirrorMaker 跨集群复制配置

### MirrorMaker 2 核心参数

MirrorMaker 2（MM2）是 Kafka 官方跨集群复制工具，通过 Connect 框架运行。关键配置如下：

- `source.cluster.alias=src`：源集群别名。
- `target.cluster.alias=dst`：目标集群别名。
- `src.bootstrap.servers=source-kafka:9092`：源集群地址。
- `dst.bootstrap.servers=target-kafka:9092`：目标集群地址。
- `topics=orders.*,payments.*`：需要复制的 topic 白名单，支持正则。
- `groups=.*`：同步 consumer group offset。
- `sync.topic.configs.enabled=true`：同步 topic 配置。
- `sync.topic.acls.enabled=false`：若使用 SASL/ACL，按需开启。
- `replication.factor=3`：目标集群副本因子。
- `refresh.topics.interval.seconds=60`：topic 列表刷新间隔。

示例 `mm2.properties`：

```properties
# MirrorMaker 2 配置
clusters=src,dst
src.bootstrap.servers=source-kafka:9092
dst.bootstrap.servers=target-kafka:9092
src->dst.enabled=true
src->dst.topics=orders.*,payments.*
src->dst.groups=order-consumer.*
replication.factor=3
num.streams=4
offset-syncs.topic.replication.factor=3
heartbeats.topic.replication.factor=3
checkpoints.topic.replication.factor=3
refresh.topics.interval.seconds=60
sync.topic.configs.enabled=true
sync.topic.acls.enabled=false
```

### 启动与检查

```bash
# 启动 MirrorMaker 2
bin/connect-mirror-maker.sh config/mm2.properties

# 检查目标集群是否已创建镜像 topic（前缀为 src.）
kafka-topics.sh --bootstrap-server target-kafka:9092 --list | grep src.

# 检查消费 lag
kafka-consumer-groups.sh --bootstrap-server target-kafka:9092 \
  --describe --group src->dst.mirror-checkpoint

# 检查复制延迟（checkpoint topic 中记录源/目标 offset 差值）
kafka-console-consumer.sh --bootstrap-server target-kafka:9092 \
  --topic src.checkpoints.internal --from-beginning
```

## 3.50.4 跨系统集成配置

### Kafka 到 RabbitMQ 集成

参考 `topics/config-templates/bridge-config.properties`：

- `bridge.kafka.rabbitmq.enabled=true`
- `bridge.kafka.rabbitmq.kafka.bootstrap.servers=localhost:9092`
- `bridge.kafka.rabbitmq.kafka.topics=orders,payments`
- `bridge.kafka.rabbitmq.rabbitmq.host=localhost`、`rabbitmq.port=5672`
- `bridge.kafka.rabbitmq.rabbitmq.exchange=orders`、`rabbitmq.routing.key=orders`
- `bridge.kafka.rabbitmq.transform.enabled=true`

落地步骤：

1. 在 RabbitMQ 创建 exchange `orders`（类型 `topic`）和 queue `orders-bridge`。
2. 配置 Kafka Connect RabbitMQ Sink Connector，或自研应用消费 Kafka 并发布到 RabbitMQ。
3. 启用 `bridge.reliability.ack.mode=all`，Kafka 消费提交 offset 前等待 RabbitMQ Publisher Confirm。
4. 开启 `bridge.error.handling.strategy=dlq`，失败消息写入 `bridge-dlq` topic。

### NATS 到 Kafka 集成

参考模板参数：

- `bridge.nats.kafka.enabled=true`
- `bridge.nats.kafka.nats.url=nats://localhost:4222`
- `bridge.nats.kafka.nats.subjects=orders.*`
- `bridge.nats.kafka.kafka.bootstrap.servers=localhost:9092`
- `bridge.nats.kafka.kafka.topics=orders`
- `bridge.nats.kafka.transform.enabled=true`

落地步骤：

1. NATS 侧使用 JetStream 消费组，配置 `DurableName=bridge-orders`、`AckPolicy=Explicit`。
2. 应用订阅 NATS subject，转换后写入 Kafka；Kafka Producer 设置 `acks=all`、`enable.idempotence=true`、`retries=3`。
3. 按业务 key（如 `order_id`）分区，保证同一订单顺序。
4. NATS Ack 在 Kafka send 回调成功后再调用，避免消息丢失。

下表对比 Kafka-MQTT 桥接、MirrorMaker 2 与跨系统桥接的适用场景：

| 桥接类型 | 典型工具 | 数据流向 | 关键可靠性参数 | 主要风险 |
|---|---|---|---|---|
| Kafka-MQTT | EMQX 规则引擎 / MQTT Connector | MQTT ↔ Kafka | MQTT QoS、Kafka `acks` | QoS 0 丢失、topic 分区乱序 |
| MirrorMaker 2 | `connect-mirror-maker.sh` | Kafka → Kafka | `replication.factor`、`num.streams` | 双向循环复制、offset 不同步 |
| Kafka-RabbitMQ | Kafka Connect / 自定义桥接 | Kafka → RabbitMQ | `ack.mode=all`、Publisher Confirm | 协议语义差异、ACK 时机 |
| NATS-Kafka | 自定义应用 / Kafka Connector | NATS → Kafka | JetStream Ack、Kafka idempotence | 消费进度与发送不一致 |

## 3.50.5 桥接可靠性调优

### 不丢失与顺序保证

1. 源端确认后再提交 offset：
   - Kafka Consumer 手动 commit，确保目标系统返回成功后再调用 `commitSync()`。
   - NATS JetStream 在 Kafka send 成功后调用 `msg.Ack()`。
2. 目标端幂等：
   - Kafka Producer 开启 `enable.idempotence=true`。
   - RabbitMQ 消费端使用唯一业务 key 去重。
3. 顺序保证：
   - 同一业务 key 映射到同一分区/队列。
   - MirrorMaker 2 保持源分区到目标分区的 1:1 映射。

### 错误处理与监控

- `bridge.error.handling.enabled=true`：启用错误处理。
- `bridge.error.handling.strategy=dlq`：失败消息进入死信队列。
- `bridge.error.handling.retry.max.attempts=3`、`bridge.error.handling.retry.backoff.ms=1000`：3 次重试，间隔 1 秒。
- 监控指标：`bridge_count`、`bridge_latency`、`bridge_errors`、`bridge_throughput`；错误率超过 `bridge.monitor.alert.error.threshold=0.01` 触发告警。
- 连接池：`bridge.optimization.connection.pool.size=10`、线程池 `thread.pool.size=5`。
- 压缩：`bridge.optimization.compression.enabled=true`、`compression.type=snappy`。

## 3.50.6 桥接集成检查清单

### 实施前

- [ ] 明确桥接方向：单向/双向、实时/近实时、全量/增量。
- [ ] 梳理 topic/Subject/Queue/Exchange 映射关系，形成 `/etc/mq/bridge-field-mapping.json`。
- [ ] 确认源/目标系统版本与协议兼容性：Kafka 版本、MQTT QoS、RabbitMQ exchange 类型、NATS JetStream 是否启用。
- [ ] 设定性能目标：吞吐（msg/s）、端到端延迟（ms）、允许错误率（<1%）。

### 实施中

- [ ] Kafka-MQTT 桥接：EMQX 规则 SQL 或 MQTT Connector 已配置 `mqtt.server.uri`、`kafka.topic`、QoS。
- [ ] MirrorMaker 2：`mm2.properties` 中 `clusters`、`bootstrap.servers`、`topics`、`groups`、`replication.factor` 已核对。
- [ ] 跨系统桥接：`bridge-config.properties` 中源/目标地址、exchange/queue/topic、transform、error handling 已启用。
- [ ] 可靠性参数：`bridge.reliability.ack.mode=all`、`bridge.reliability.idempotency.enabled=true`。
- [ ] 性能参数：`bridge.batch.size=100`、`bridge.batch.timeout.ms=1000`、连接池 10、线程池 5。

### 实施后

- [ ] 运行 `topics/scripts/bridge-test.sh kafka-rabbitmq` 验证桥接连通性。
- [ ] 验证 MQTT 设备上报一条消息后，Kafka `mqtt.messages` topic 能消费到对应记录。
- [ ] 验证 MirrorMaker 2 目标集群存在 `src.{topic}` 且 offset 持续同步。
- [ ] 监控 `bridge_count`、`bridge_latency`、`bridge_errors`，错误率低于 `bridge.monitor.alert.error.threshold=0.01`，延迟低于 `bridge.monitor.alert.latency.threshold=1000` ms。
- [ ] 模拟目标系统故障，确认消息进入 DLQ 且恢复后可重放。
- [ ] 定期检查连接池、线程池、消费 lag，必要时扩容 `tasks.max` 或 `num.streams`。
