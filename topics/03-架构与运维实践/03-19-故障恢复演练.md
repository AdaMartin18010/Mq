| 级别 | 场景 | 预期 RTO | 预期 RPO | 演练频率 |
| ------ | ------ | ---------- | ---------- | ---------- |
| **P0** | 单 Broker/单节点故障 | <5min | 0 | 每月 |

| **P3** | 数据中心级灾难 | <4h | <1h | 每年 |

## 3.19.3 Kafka Broker 故障演练

### 演练目标

验证单 Broker 故障时，分区 Leader 自动切换、消费者无感知、ISR 恢复符合预期。

### 演练脚本

```bash
# 1. 记录演练前状态
kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic test-topic > /tmp/kafka-before.log

# 2. 模拟 Broker 2 故障
pkill -f "kafka.Kafka.*broker.id=2"

# 3. 观察影响（预期：UnderReplicatedPartitions 短暂 >0）
watch -n 2 'kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic test-topic | grep Isr'

# 4. 恢复 Broker 2
./scripts/restart.sh kafka 2

# 5. 验证 ISR 恢复
kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic test-topic > /tmp/kafka-after.log
diff /tmp/kafka-before.log /tmp/kafka-after.log
```

### 演练检查项

- [ ] `UnderReplicatedPartitions` 在 60 秒内恢复为 0
- [ ] 消费者 Lag 增长 <20%
- [ ] 生产者发送成功率保持 >99.9%
- [ ] 恢复后 ISR 与演练前一致

## 3.19.4 NATS Server 故障演练

### 演练脚本

```bash
# 1. 记录当前路由与连接数
curl -s http://localhost:8222/varz | grep -E '"routes"|"connections"' > /tmp/nats-before.log

# 2. 停止一个 Server 节点
pkill -f "nats-server.*server_name=nats-server-2"

# 3. 检查客户端自动重连与路由收敛
watch -n 2 'curl -s http://localhost:8222/varz | grep -E '"'"'routes'"'"'|"'"'connections'"'"''

# 4. 恢复节点
./scripts/restart.sh nats 2

# 5. 验证集群路由恢复
curl -s http://localhost:8222/varz | grep -E '"routes"|"connections"' > /tmp/nats-after.log
```

### 演练检查项

- [ ] 客户端重连时间 <5 秒
- [ ] 消息无丢失（JetStream 场景下）
- [ ] 集群路由数在节点恢复后回到预期值
- [ ] `SlowConsumers` 指标未增长

## 3.19.5 RabbitMQ 节点故障演练

### 演练脚本

```bash
# 1. 记录队列状态
rabbitmqctl list_queues name messages messages_ready messages_unacknowledged > /tmp/rabbitmq-before.log

# 2. 停止一个节点
docker stop rabbitmq-node-2

# 3. 检查 quorum queue 状态
rabbitmqctl quorum_status queue_name

# 4. 恢复节点
docker start rabbitmq-node-2
rabbitmqctl cluster_status

# 5. 验证队列消息一致性
rabbitmqctl list_queues name messages messages_ready messages_unacknowledged > /tmp/rabbitmq-after.log
diff /tmp/rabbitmq-before.log /tmp/rabbitmq-after.log
```

### 演练检查项

- [ ] quorum queue 在多数派存活时可继续服务
- [ ] 节点恢复后自动加入集群
- [ ] 消息总量与演练前一致
- [ ] 无 `DOWN` 状态队列持续 >5min

## 3.19.6 网络分区演练

使用 `chaos-test.sh` 进行故障注入：

```bash
# 模拟 Kafka 网络分区（100ms 延迟）
./scripts/chaos-test.sh kafka network

# 模拟 NATS 节点间网络延迟
./scripts/chaos-test.sh nats network

# 模拟 RabbitMQ 节点隔离
./scripts/chaos-test.sh rabbitmq node
```

### 网络分区观察指标

| 系统 | 关键指标 | 健康阈值 |
| ------ | ---------- | ---------- |
| Kafka | `ActiveControllerCount` | ==1 |
| Kafka | `PartitionCount` | 无异常增长 |
| NATS | `routes` | 等于节点数-1 |
| RabbitMQ | `cluster_partition_handling` | 按策略（pause_minority/autoheal）生效 |
