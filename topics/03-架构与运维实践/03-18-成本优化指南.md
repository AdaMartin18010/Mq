## 3.18.1 成本构成分析

消息队列总拥有成本（TCO）通常由四部分组成【估算】：

| 成本项 | 占比范围 | 优化杠杆 |
| -------- | ---------- | ---------- |
| **计算资源** | 30%-50% | 实例规格、预留实例、自动扩缩容 |
| **存储资源** | 25%-45% | 压缩、分层、保留策略 |
| **网络流量** | 10%-20% | 同区部署、批量、压缩 |
| **运维人力** | 10%-20% | 自动化、监控、标准化 |

## 3.18.2 资源成本优化

### 1. 合理设置 CPU/内存 利用率目标

参考 `config-templates/cost-optimize-config.properties`：

```properties
# 目标利用率设置为 80%，避免过度预留
cost.optimize.resource.cpu.target.usage=0.8
cost.optimize.resource.memory.target.usage=0.8

# 自动扩缩容边界
cost.optimize.resource.auto.scale.min.instances=2
cost.optimize.resource.auto.scale.max.instances=10
```

### 2. 实例类型选择建议

| 负载特征 | 推荐实例类型 | 理由 |
| ---------- | -------------- | ------ |
| 高吞吐 Kafka | 计算优化型 + 本地 SSD | CPU 与磁盘 IO 并重 |
| 高并发 NATS | 内存优化型 | 连接状态占用内存 |
| 低延迟 RabbitMQ | 计算优化型 + 高速磁盘 | 队列索引随机 IO |
| 归档/低频 | 通用型 + 对象存储 | 成本最低 |

### 3. 资源使用检查命令

```bash
# 查看资源使用报告
./scripts/resource-usage.sh

# 成本分析脚本
./scripts/cost-analysis.sh cost_report_$(date +%Y%m%d).txt
```

## 3.18.3 存储成本优化

### 1. 启用压缩与保留策略

```properties
# Kafka 压缩与保留
compression.type=snappy
log.retention.hours=168
log.retention.bytes=107374182400
log.segment.bytes=1073741824
log.cleanup.policy=delete
```

### 2. 分层存储

```properties
# 成本优化配置模板
cost.optimize.storage.tiering.enabled=true
cost.optimize.storage.tiering.hot.storage=ssd
cost.optimize.storage.tiering.cold.storage=hdd
cost.optimize.storage.tiering.archive.storage=object_storage
```

### 3. 定期清理过期数据

```bash
# 清理旧日志与快照（按保留策略）
./scripts/cleanup-old-data.sh kafka --days 7

# 检查磁盘使用
./scripts/storage-check.sh
```

### 存储成本对比

| 策略 | 存储节省估算 | 适用场景 |
| ------ | -------------- | ---------- |
| **snappy/lz4 压缩** | 30%-50% | 文本/JSON 消息 |
| **zstd 压缩** | 40%-70% | 日志类高可压数据 |
| **7 天保留** | 固定上限 | 事件流、埋点 |
| **分层存储** | 50%-70% | 审计、合规归档 |

## 3.18.4 网络成本优化

### 1. 批量与压缩

```properties
# Kafka Producer 批量参数
batch.size=32768
linger.ms=10
compression.type=snappy

# NATS 批量发布（客户端侧）
# 推荐每批次 ≥100 条或达到 32KB 再发送
```

### 2. 同可用区部署

| 部署方式 | 跨区流量 | 可用性 | 成本 |
| ---------- | ---------- | -------- | ------ |
| 单 AZ | 0 | 低 | 最低 |
| 多 AZ 同区域 | 仅副本同步 | 中 | 中 |
| 跨区域 | 高 | 高 | 最高 |

### 3. 网络成本检查

```bash
# 查看网络流量统计
./scripts/metrics.sh network

# 对比生产与消费流量，排查异常重传
```

## 3.18.5 云服务成本优化

### 1. 预留/承诺折扣

| 云厂商 | 折扣产品 | 折扣幅度【估算】 | 适用场景 |
| -------- | ---------- | ---------------- | ---------- |
| **AWS** | Reserved Instances / Savings Plans | 30%-50% | 基线负载 |
| **Azure** | Reserved VM Instances | 30%-50% | 基线负载 |
| **GCP** | Committed Use Discounts (CUD) | 20%-45% | 基线负载 |
| **AWS/GCP** | Spot / Preemptible | 60%-90% | 非关键测试/批处理 |

### 2. 自动暂停与扩缩容

```yaml
# KEDA 扩缩容示例（参考 config-templates/keda-scaledobject-kafka.yaml）
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: kafka-consumer-scaler
spec:
  scaleTargetRef:
    name: kafka-consumer
  triggers:
    - type: kafka
      metadata:
        bootstrapServers: kafka:9092
        consumerGroup: order-group
        topic: orders
        lagThreshold: "1000"
  minReplicaCount: 2
  maxReplicaCount: 20
```

## 3.18.6 成本监控与告警

### 1. 成本监控脚本

```bash
# 运行成本优化检查
./scripts/cost-optimize.sh

# 生成成本分析报告
./scripts/cost-analysis.sh
```

### 2. 成本告警规则

```yaml
# prometheus alert rules
- alert: MQCostSpike
  expr: |
    (
      sum(cloud_cost_per_hour) /
      avg_over_time(sum(cloud_cost_per_hour)[7d:1h])
    ) > 1.2
  for: 1h
  labels:
    severity: warning
  annotations:
    summary: "消息队列小时成本较 7 日均值增长 >20%"

- alert: MQStorageCostHigh
  expr: kafka_log_size_bytes > 109951162777600  # 100TB
  for: 1h
  labels:
    severity: warning
  annotations:
    summary: "Kafka 存储总量超过 100TB"
```

## 3.18.7 成本优化检查清单

### 资源与计算

- [ ] CPU 日均利用率 ≥50% 且 ≤80%；低于 30% 考虑降配
- [ ] 内存日均利用率 ≥50% 且 ≤80%
- [ ] 已启用自动扩缩容，最小副本 ≥2，最大副本 ≤业务上限
- [ ] 生产环境已购买预留实例/承诺折扣，覆盖基线负载
- [ ] 非关键任务使用 Spot/抢占式实例

### 存储与网络

- [ ] Kafka `compression.type` 已设置为 snappy/lz4/zstd
- [ ] 日志保留策略已配置，`log.retention.hours` 或 `log.retention.bytes` 生效
- [ ] 分层存储已启用，冷数据已迁移至 HDD/对象存储
- [ ] Producer `batch.size` ≥16KB，`linger.ms` ≥5ms
- [ ] 跨 AZ/跨区域流量已审计，非必要流量已收敛

### 运维与监控

- [ ] `./scripts/cost-optimize.sh` 每周执行一次
- [ ] 成本告警阈值已设置：小时成本波动 >20% 触发告警
- [ ] 成本分析报告已归档，按月复盘优化效果
- [ ] 已建立成本归属标签（team/business/topic）
