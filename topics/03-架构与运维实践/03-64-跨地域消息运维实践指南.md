## 3.64.1 需求与前置条件

- 已按 02-51 选定模式（A 单元化 / B 地理复制 / C CRDT / D 服务多活）——本指南按模式给操作
- 前置：跨区网络（专线/VPN）带宽与延迟实测（复制吞吐 = 生产速率 × 副本区数）【论证】
- 合规前置：含 PII 的 topic 是否允许出区（02-50）——未过审的 topic 禁入复制集

## 3.64.2 地理复制落地（按系统）

**Pulsar geo-replication（模式 B）**：

```bash
# 集群间互配（两个集群的 broker 配置互指）
pulsar-admin clusters create cluster-b --url http://pulsar-b:8080 --broker-url pulsar://pulsar-b:6650
# namespace 级启用双向复制
pulsar-admin namespaces set-clusters my-tenant/my-ns --clusters cluster-a,cluster-b
# 验证：A 区生产，B 区 subscription backlog 收敛
pulsar-admin topics stats persistent://my-tenant/my-ns/orders | grep -A3 replication
```

**Kafka MirrorMaker 2（单向灾备，禁双向同 topic）**：

```bash
# mm2 配置要点：单向 topic 映射（源→目标带前缀），禁止同 topic 双向
clusters = a, b
a->b.emit.heartbeats = true        # 心跳检测复制链路
a->b.topics = orders.*
# 校验：目标集群消费位点滞后（ OffsetSync ）
kafka-consumer-groups.sh --describe --group mm2-a-b --bootstrap-server <b>
```

**NATS Supercluster（模式 D）**：

```bash
# gateway 互通配置后，验证跨区路由与 JetStream 灾备复制状态
nats server report jetstream --cluster
nats stream info ORDERS --json | jq '.cluster.leader, .cluster.replicas[].name'
```

**Redis（模式 C，商业版）**：Active-Active 数据库创建由控制台/API 完成；社区版替代=单向主从+手工提升（降级为模式主备）。

## 3.64.3 跨区健康监测

核心指标【论证】：

| 指标 | 告警阈值（起点【估算】） | 含义 |
| ------ | -------------------------- | ------ |
| 复制滞后（replication lag / offset-sync gap） | > 60s | 灾难时数据丢失窗口 |
| 跨区链路带宽利用率 | > 70% | 复制跟不上生产的前兆 |
| 分区/区健康 | 任一区心跳丢失 | 区域级故障（触发 3.64.4） |
| 双向环回计数 | > 0 | 配置事故，立即处理 |

接入方式：1.33 监测体系按区建 Prometheus 联邦或远程写；Pulsar 用 `pulsar_replication_*` 指标；MM2 用其内建心跳+OffsetSync 指标【论证】。

## 3.64.4 演练与切换

- **季度演练**：按 TEST-04 混沌模式注入区域故障（断网关/停集群），验证：流量切换（模式 A 的路由层）、复制自愈、RTO/RPO 实测记录【论证】。
- **切换决策表**：单区只读降级（保留写入主区）→ 区域丢失（提升幸存区为主）——每步含数据一致性校验命令（分区对账：两侧消息计数/哈希抽样比对）【论证】。
- 演练记录入 TEST-05 建档；RPO 实测超 SLO 开韧性缺陷单。

## 3.64.5 验证方法

- 复制正确性：A 区发 10,000 条带唯一 ID，B 区计数+抽样哈希一致（容忍异步延迟）
- 环回免疫：模式 A 注入"误配置双向"测试流量，验证去重机制拦截（计数不翻倍）
- 切换演练：RTO/RPO 实测写入批次报告

## 3.64.7 补充操作件

**跨区网络预检（复制上线前）**：

```bash
# 带宽：实测复制吞吐 vs 生产峰值×副本区数
iperf3 -c <对端区节点> -t 30
# 延迟：RTT 决定同步复制可行性（>40ms 基本否决同步）
ping -c 100 <对端区节点> | tail -1
```

**演练注入细节（对照 TEST-04 混沌用例）**：

| 演练动作 | 注入方式 | 观测点 |
|----------|----------|--------|
| 区域隔离 | 断网关路由/安全组拒流 | 流量切换时延、复制告警 |
| 集群宕机 | 停 B 区全部 broker | A 区生产不受影响、B 恢复后对账 |
| 链路劣化 | tc qdisc 加 200ms 延迟 | 复制滞后曲线、业务可感知度 |

**数据对账脚本（切换后必跑）**：

```bash
# 两侧消息计数+抽样哈希比对（容忍异步窗口内差值）
A=$(kafka-run-class kafka.tools.GetOffsetShell --broker-list <a:9092> --topic orders | awk -F: '{s+=$3}END{print s}')# 演练计划模板（季度）见 TEST-04 TC-CLU 系列；此处登记区域级场景
# 场景：region-b 整体不可达 30 分钟
# 注入：安全组拒流 region-a ↔ region-b
# 预期：生产切 region-a；复制滞后告警；恢复后对账 diff≈0
A=$(kafka-run-class kafka.tools.GetOffsetShell --broker-list <a:9092> --topic orders | awk -F: '{s+=$3}END{print s}')
B=$(kafka-run-class kafka.tools.GetOffsetShell --broker-list <b:9092> --topic orders.a | awk -F: '{s+=$3}END{print s}')
echo "A=$A B=$B diff=$((A-B))（窗口期内应≈0）"
```

## 3.64.8 常见问答（FAQ）

| 问题 | 回答口径 |
| ------ | ---------- |
| "geo-replication 是同步还是异步" | 异步（Pulsar 语义）；宣传"同步"的多活方案需警惕【论证】 |
| "RPO 能做到 0 吗" | 异步复制下 RPO=复制滞后窗口（秒-分钟级）；要 RPO=0 须单元化单主+故障分区拒写（02-51） |
| "MM2 双向会环回吗" | 同 topic 双向必环回；用 topic 前缀隔离或改单元化【论证】 |
| "跨区带宽怎么估" | 生产速率×副本区数×放大系数(1.3)【估算】，压测复核 |
| "演练会影响生产吗" | 用独立命名空间/影子 topic；区域级注入选低峰窗口并通告 |

## 3.64.10 跨区链路容量规划速查

| 生产速率 | 双区复制带宽需求（×1.3 系数）【估算】 | RTT 建议上限 |
| ---------- | ---------------------------------------- | -------------- |
| 10 MB/s | ≥26 MBps | <50ms |
| 100 MB/s | ≥260 MBps | <50ms |
| 1 GB/s | ≥2.6 GBps（专线级） | <20ms |

低于下限的链路：复制持续落后→RPO 劣化→告警常态化；扩容判据见 1.33 饱和度信号。

## 3.64.11 术语速查

| 术语 | 含义 |
| ------ | ------ |
| geo-replication | 地理复制（异步跨区复制） |
| RPO/RTO | 恢复点/时间目标（跨区场景按复制滞后实测） |
| 环回（loop） | 消息跨区复制后回流 originating 区 |
| 提升（promote） | 幸存区接管主区角色（先对账后切） |
| 主区表 | 模式 A 的分片→主区映射（路由层核心状态） |
