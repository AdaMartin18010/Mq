## 3.33.1 合规框架与职责

消息队列合规性落地需同时满足组织内部安全策略与外部法规要求。常见外部框架包括：

- **等保 2.0**：身份鉴别、访问控制、安全审计、数据完整性/保密性、剩余信息保护。
- **GDPR**：数据最小化、存储限制、删除权、可携带权、处理记录与同意管理。
- **HIPAA**：访问控制、审计控制、完整性、传输安全、入侵检测。
- **PCI DSS**：持卡人数据环境隔离、强加密、访问控制、日志监控、漏洞管理。
- **SOC 2**：安全性、可用性、处理完整性、保密性、隐私性控制。

运维团队负责：

1. 配置并维护加密、认证、授权、审计等技术控制措施。
2. 按保留策略管理日志与消息数据生命周期。
3. 定期执行合规检查并留存证据。
4. 配合合规团队完成差距分析与整改。

## 3.33.2 数据保护落地配置

### 传输与存储加密配置

参考项目模板 `config-templates/security-enhanced-config.properties`：

```properties
# Kafka：强制 SASL_SSL，禁用明文监听
kafka.security.protocol=SASL_SSL
kafka.sasl.mechanism=SCRAM-SHA-512
kafka.ssl.keystore.location=/etc/mq/certs/kafka.keystore.jks
kafka.ssl.keystore.password=${KAFKA_KEYSTORE_PASSWORD}
kafka.authorizer.class.name=kafka.security.authorizer.AclAuthorizer
kafka.allow.everyone.if.no.acl.found=false

# 通用加密与密钥轮换
security.encryption.enabled=true
security.encryption.algorithm=AES-256-GCM
security.encryption.key.rotation.enabled=true
security.encryption.key.rotation.interval=90d
```

### 敏感数据脱敏示例

```bash
# Kafka 生产者侧对敏感字段做哈希/截断后入队
# 示例：信用卡号保留前 6 后 4，中间掩码
python3 - <<'PY'
import hashlib, json
payload = {"card_number": "4111111111111111", "name": "张三"}
masked = payload["card_number"][:6] + "*"*6 + payload["card_number"][-4:]
print(json.dumps({"card_hash": hashlib.sha256(payload["card_number"].encode()).hexdigest()[:16],
                  "card_masked": masked, "name": payload["name"]}))
PY
```

## 3.33.3 审计日志留存

### Kafka 开启审计日志

```properties
# server.properties：开启 authorizer 日志
authorizer.class.name=kafka.security.authorizer.AclAuthorizer
super.users=User:admin
# 日志保留策略（示例：保留 90 天）
log.retention.hours=2160
```

### 通用审计配置

```properties
# config-templates/security-enhanced-config.properties 节选
audit.enabled=true
audit.log.file=/var/log/mq-audit.log
audit.log.level=INFO
audit.events=login,logout,read,write,delete,config_change
audit.retention.days=90
```

### 日志留存要求对照

| 框架/标准 | 日志类型 | 建议最短留存期 | 关键检查点 |
| ----------- | ---------- | ---------------- | ------------ |
| 等保 2.0 | 安全审计日志 | ≥180 天【估算】 | 集中存储、防篡改、可追溯 |
| GDPR | 处理活动记录 | 按业务/法规要求 | 处理目的、数据主体权利操作 |
| HIPAA | 访问/审计日志 | ≥6 年【估算】 | 谁在何时访问了 PHI |
| PCI DSS | 持卡人环境日志 | ≥1 年，关键 3 个月在线【估算】 | 完整性保护、时间同步 |
| SOC 2 | 控制执行证据 | ≥1 年【估算】 | 与信任服务原则对应 |

## 3.33.4 认证与授权检查

### Kafka 认证授权检查命令

```bash
# 检查 SCRAM 用户
kafka-configs.sh --bootstrap-server localhost:9092 --describe \
  --entity-type users --all

# 检查 ACL 是否按最小权限配置
kafka-acls.sh --bootstrap-server localhost:9092 --list

# 验证是否禁用明文 SASL_PLAINTEXT
grep "^listeners" $KAFKA_HOME/config/server.properties
```

### NATS 认证授权检查

```bash
# 检查 nats-server.conf 中 authorization 或 accounts 块
grep -E "authorization|accounts|users|permissions" nats-server.conf

# 使用 nats-cli 验证用户权限（以只读用户为例）
nats --server nats://localhost:4222 --user readonly --password xxx pub test "hello"
# 预期：权限拒绝
```

### RabbitMQ 认证授权检查

```bash
# 检查用户、vhost、权限
rabbitmqctl list_users
rabbitmqctl list_vhosts
rabbitmqctl list_permissions -p /

# 检查默认 guest 是否仍在使用
rabbitmqctl list_users | grep -E "guest|\[administrator\]"
```

## 3.33.5 自动化合规检查

项目提供 `scripts/compliance-check.sh`，可一次性检查 GDPR、HIPAA、PCI DSS 三个维度：

```bash
cd E:/_src/Mq/topics

# 全部检查
bash scripts/compliance-check.sh all compliance-report-2026-11.txt

# 仅 GDPR
bash scripts/compliance-check.sh gdpr gdpr-report.txt

# 仅 HIPAA
bash scripts/compliance-check.sh hipaa hipaa-report.txt

# 仅 PCI DSS
bash scripts/compliance-check.sh pci pci-report.txt
```

## 3.33.6 各标准落地对照

| 合规要求 | 技术控制 | 配置/命令示例 | 证据物 |
| ---------- | ---------- | --------------- | -------- |
| 身份鉴别 | SASL/SCRAM、LDAP、mTLS | `sasl.enabled.mechanisms=SCRAM-SHA-512` | 配置截图、用户清单 |
| 访问控制 | ACL/RBAC/vhost 隔离 | `kafka-acls.sh --list` | ACL 列表、权限矩阵 |
| 传输保密 | TLS 1.2+、证书校验 | `security.protocol=SASL_SSL` | 证书信息、抓包验证 |
| 存储保密 | 磁盘加密、字段加密 | `security.encryption.algorithm=AES-256-GCM` | 加密策略文档 |
| 审计追溯 | 操作日志、集中留存 | `audit.enabled=true` | 审计日志样本 |
| 数据删除 | TTL、日志清理、主题删除 | `log.retention.hours=2160` | 清理脚本执行记录 |
| 漏洞管理 | 版本基线、补丁窗口 | `kafka-broker-api-versions.sh` | CVE 扫描报告 |

## 3.33.7 合规检查清单

- [ ] 已明确适用合规框架（等保/GDPR/HIPAA/PCI DSS/SOC 2 等）。
- [ ] 已建立消息队列版本基线，CVE 扫描按季度执行【估算】。
- [ ] Kafka/NATS/RabbitMQ 已启用 TLS/SSL，且禁用明文回退。
- [ ] 已配置认证机制（SCRAM-SHA-512、LDAP、用户名/密码、Token 等）。
- [ ] 已配置 ACL/RBAC/vhost 隔离，遵循最小权限原则。
- [ ] 已启用审计日志，日志集中收集并满足对应框架的留存期要求。
- [ ] 已设置数据保留/删除策略（`log.retention.hours`、`retention.ms` 等）。
- [ ] 敏感字段已脱敏或加密，密钥管理符合组织策略。
- [ ] 已执行 `scripts/compliance-check.sh all` 并保存报告。
- [ ] 高/中风险合规差距已创建整改工单，明确责任人与完成时间。
- [ ] 整改完成后已复测并通过合规检查脚本验证。
