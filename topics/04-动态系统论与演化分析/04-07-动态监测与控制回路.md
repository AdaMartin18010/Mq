## 4.07.1 控制回路的形式化骨架

负反馈控制的最小骨架【定理】：

```text
设定点 r（SLO，如 lag<10万） ──▶ 比较器 ──▶ 控制器 ──▶ 执行器 ──▶ 被控对象（消息管道）
                     ▲                                      │
                     └────────── 传感器（监测）◀─────────────┘
                          延迟 Δ、噪声 n 必然存在
```

消息系统实例化【论证】：r=消费延迟 SLO；传感器=prometheus lag 查询（采样间隔即 Δ）；控制器=KEDA/HPA 规则或运维决策；执行器=副本扩缩/限流开关；被控对象=producer-broker-consumer 链路。**Δ 与 n 决定控制质量**：采样 30s + lag 抖动大时，激进控制必振荡（§4.07.4）。

## 4.07.2 三类控制机制谱系

| 类别 | 机制 | 消息系统实例 | 控制律 | 风险 |
| ---- | ---- | ---- | ---- | ---- |
| 开环补偿 | 无反馈的预设干预 | 定时批量重投、固定窗口限流 | 静态 | 扰动适应差（04-03 重试放大即开环失稳例） |
| 闭环反馈 | 误差驱动 | KEDA 按 lag 扩 consumer；自适应限流（02-37） | 比例/阈值 | 振荡（Δ 过大） |
| 前馈控制 | 扰动预测提前动作 | 大促前预热扩容、基于上游流量的提前分区扩容 | 模型驱动 | 模型失配 |

实现谱系对照【论证】：

| 系统 | 内置控制机制 | 外部控制挂点 |
| ---- | ---- | ---- |
| Kafka | 配额（quota 动态限流=闭环雏形）、分区自动再平衡（最低优先分配）、KIP-932 share 自动分发 | KEDA/kafka-autoscaler、 Cruise Control（再平衡控制律） |
| RabbitMQ | per-consumer QoS（信用=流控回路）、队列长度报警 | KEDA rabbitmq scaler、HA 队列成员调整 |
| NATS JetStream | 流限额/maxAckPending 硬边界、消费者自动重投 | KEDA nats scaler |
| Pulsar | 负载均衡器（模块化负载管理器=持续控制回路）、namespace 隔离 | Pulsar Functions auto-scaling |
| Redis | 无内置 | 应用侧 XPENDING 监控+自定义 |

## 4.07.3 监测设计：控制的上游

控制质量上限由监测质量决定【论证】：

1. **指标选择**：控制用指标须"快而糙"（lag 采样 15-30s 够），诊断用指标"全而细"——混用会导致控制器被噪声驱动；
2. **死区（deadband）**：lag 抖动 ±20%【估算】内不动作，防微小误差触发执行器（执行器本身有成本：扩缩容冷启动 30-90s）；
3. **多传感器融合**：lag + 消费速率 + 错误率三信号表决（2/3 同意才动作），单信号误报是生产事故常见源【论证】；
4. **控制日志**：每次控制动作记录（时间/触发信号/动作/结果）——04-06 RTO 趋势表与 TEST-15 DYN-A3 的数据源。

## 4.07.4 稳定性陷阱与振荡防控

经典失稳模式【定理级机理+论证级实例】：

| 模式 | 机理 | 消息系统实例 | 防控 |
| ---- | ---- | ---- | ---- |
| 延迟振荡 | Δ > 系统响应时间时负反馈变正反馈 | 扩容 60s 才生效，30s 采样+激进 P 控制→越扩越乱 | 控制周期 ≥3×执行器响应时间【估算】 |
| 多控制器冲突 | 两个控制器无协调 | HPA 扩副本 + KEDA 同指标同时动作 | 单指标单控制器原则；分维度（CPU vs lag） |
| 积分饱和 | 长期误差累积导致动作过度 | lag 积压一周，I 项累积→一次性扩 10 倍 | 积分限幅/分段重置 |
| 冷启动雪崩 | 执行器动作引发新扰动 | 批量扩容同时拉全量快照 | 分批滚动+预热 |

02-49 的缩容判据（缩容比扩容保守 2-3 倍【估算】）即防抖工程经验的形式化。
