# K4 引用审计链规范（KB-REF）（批次 139）

> **地位**：K1 §2/§6 的执行细则——agent 对客回答的知识引用必须可回放。责任追溯的依据。

## 1. 引用三元组与日志

agent（含本库 MCP 消费者、外部 agent）基于本库给出对客结论时，必须记录：

```json
{
  "kb_ref_id": "kbref-20261118-001",
  "timestamp": "2026-11-18T12:00:00+08:00",
  "agent": "<agent 标识>",
  "conclusion": "<对客结论一句话>",
  "refs": [
    {"doc": "topics/01-基础概念与对比分析/01-63-....md", "section": "1.63.6", "commit": "feb1b08", "confidence": "论证", "ev": "[EV:TC-SEM-07@0de1407]"}
  ],
  "supersedes": null,
  "drift_flag": false
}
```

- 本库 MCP server：响应头强制携带 `X-KB-Version: <commit>`；tool 返回值内嵌 `kb_refs` 数组；
- 外部 agent：日志写各自审计存储，**格式遵循本文**（互联时按此对齐）；
- 存储：`results/kb-refs/`（本库 agent）按日聚合，保留 180 天。

## 2. 责任追溯流程

```text
对客结论出错 → 按 kb_ref_id 回放引用链
  → 引用合规且知识正确：agent 使用责任（引用错段落/过度泛化）
  → 引用合规但知识错误：知识责任 → 启动 K1 §4 冲突流程 + K3 退役/证伪处置
  → 引用不合规（无三元组/P4 裸奔）：agent 责任，反馈给 agent 提供方
```

## 3. 轻量执行约定

- 本库范围内：MCP v2（批次 136）实现响应头+kb_refs 注入；不写日志的调用视为"内部用"豁免对客条款；
- 最小合规：对客回答至少 1 个 refs 条目，禁止 P4（模型先验）裸引；
- 审计抽查：月度回顾抽 5 条 kb-refs 回放（TEST-06 并入）。
