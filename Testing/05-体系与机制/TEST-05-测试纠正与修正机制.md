## T.05.1 失败分类学

每个失败用例必须先分类再处置（禁止"重跑看看好了没"式消单）：

| 类别 | 特征 | 处置路径 | 责任方 |
| ------ | ------ | ---------- | -------- |
| P 产品缺陷 | 系统行为违反文档承诺（如 acks=all 丢消息） | 缺陷单 → 修复 → 补用例固化 | 系统维护者 |
| T 用例缺陷 | 断言错误/环境假设错误/时序脆弱 | 修用例 → 同批补评审 | 用例作者 |
| E 环境抖动 | 资源不足/时钟跳变/网络瞬断，复现率低 | 隔离观察 → 三次复现再定性 | 测试环境 owner |
| D 文档漂移 | 文档参数/命令与实测不符 | 双向修正（T.05.4） | 文档治理批次 |
| B 基准漂移 | 性能用例结果偏离历史基线 > 阈值 | 复核环境 → 更新基线并注明原因 | 性能 owner |

分类证据要求【论证】：P/T 类必须有最小复现步骤与日志摘录；E 类必须有资源监控截图/数据；D 类必须有"文档原文 vs 实测输出"对照；B 类必须有两轮以上复测数据。

五问判定流程（按序提问，先命中先归类）：

1. 同环境重跑 3 次结果是否一致？不一致 → E 候选。
2. 用例断言是否可能被合法实现击穿（时序窗口/批行为/重排）？是 → T 候选。
3. 按当前官方文档手工执行同一操作，结果是否与文档一致？不一致 → D 候选。
4. 性能类结果与基线偏差是否 > 阈值且环境复核无异常？是 → B 候选。
5. 以上全否且系统行为违反文档承诺 → P。

判定流程的设计意图【论证】：把"最便宜的解释"排在前面（环境问题最常见、文档漂移其次），避免一上来就怀疑产品——这与科学排查的"奥卡姆优先"一致，同时用证据要求防止草率定性。

## T.05.2 隔离与降级规则

- **隔离（quarantine）**：同一用例非环境原因连续失败 2 次 → 移入隔离区 `Testing/quarantine/`，主流程不再执行；隔离用例上限为主流程用例数的 10%【估算】，超限触发批次治理。
- **降级**：P0 门禁用例（TEST-01 T.01.5 表）不得隔离，只能修复或经批次负责人书面豁免（豁免附到期日）。
- **回收**：隔离用例修复后须连续通过 3 次才能回归主流程。

```bash
# 隔离登记（示意）
mkdir -p Testing/quarantine
cat > Testing/quarantine/TC-INT-05.md <<'EOF'
用例: TC-INT-05 重试风暴观测
隔离日期: 2026-11-17
类别: T（断言未考虑 linger.ms 批提交时序）
复现: 3/3
回归条件: 断言改为区间校验后连续 3 次通过
EOF
```

隔离区周检（每周五，10 分钟）：清点隔离用例数与账龄；账龄 > 30 天的用例强制二选一（修复回归 / 删除并记录删除理由），防止隔离区沦为"垃圾抽屉"。

## T.05.3 根因分析流程

五步法（时限见 T.05.6）：

1. **定格现场**：保留日志/指标/容器状态快照（失败发生后 10 分钟内固化证据）。
2. **时间线重建**：按"注入→观测→恢复"对齐各方时钟，标注每一跳的实测时延。
3. **假设枚举**：至少列出 3 个候选根因（含"用例自身错误"假设，防止只盯产品）。
4. **实验甄别**：每假设设计一个可证伪实验（最小改动、可回退）。
5. **结论固化**：结论写入用例文件的 `## 根因记录` 节，含证据链接。

根因记录模板：

```markdown
## 根因记录
- 日期: YYYY-MM-DD
- 分类: P/T/E/D/B（附判定证据链接）
- 时间线: 注入 T0 → 观测 T1 → 恢复 T2（各点实测时延）
- 候选假设: ≥3 个及各自的证伪实验结果
- 最终结论: 一句话 + 修复提交链接
- 防再发: 新增/加固的用例编号
```

## T.05.4 文档-测试同步修正

D 类（文档漂移）是知识库项目的特有风险，执行双向修正：

| 漂移方向 | 检测 | 修正 |
| ---------- | ------ | ------ |
| 文档 → 现实 | 用例按文档执行失败且定性 D 类 | 修文档并标最后更新；查同源其他文档（同参数名批量 grep） |
| 现实 → 文档 | 系统升级后原正确命令失效 | 同上，且检查 AI_Skill 派生技能漂移（doc-self-check.sh --skill-drift） |

双向修正的对照登记（每条 D 类修正必须填）：

| 日期 | 用例 | 文档原文（摘） | 实测输出（摘） | 修正方向 | 联动检查 |
|------|------|----------------|----------------|----------|----------|

联动规则：D 类修正必须同步检查 ① INDEX 登记 ② 置信标注是否仍成立 ③ 引用该文档的技能 references（AI_SKILL-02 AIS.02.5）。三处联动由 TEST-06 脚本部分自动化。

联动检查的快速手工命令：

```bash
# ① 该参数名在哪些文档出现（修正需全覆盖）
grep -rln "<参数名>" topics --include='*.md'
# ② INDEX 是否登记了被修正文档
grep "<文档基名>" topics/INDEX.md
# ③ 技能漂移（若 AI_Skills/skills/ 已建）
./topics/scripts/doc-self-check.sh --skill-drift
```

豁免流程（P0 门禁用例的隔离豁免）：豁免申请人书面说明风险与缓解措施 → 批次负责人批准并登记（豁免人/日期/到期日）→ 到期未修复自动恢复阻断。豁免登记附于批次报告，连续两次豁免同一用例视为流程失效，须回炉重审用例设计本身。

本机制的防退化原则：纠正机制本身也受腐蚀——用例长期不失败可能是用例变弱而非系统变好。每季度抽查 10% 用例做"突变测试"（故意注入已知缺陷，验证用例能抓到），抓不到即按 T 类修正用例。

与其他章节的接口：分类结论（T.05.1）是 TEST-06 自检 WARN 挂账的定性依据；隔离清单是 TEST-01 覆盖矩阵 ○ 格转化为 ● 格的输入；SLA 达成率纳入 PROJECT_STATUS 质量保证节的月度更新。

月度回顾输出样例（模板，按 T.05.6 清单填充）：

```text
# 测试纠正月度回顾（YYYY-MM）
分类分布: P=1 T=2 E=0 D=3 B=0（合计 6）
SLA 达成: 5/6（超时: D-03 文档修正，已升级至本批次）
隔离区: 2 例在区（账龄 12 天/25 天，均在阈值内）
回归新增: 1 条（TC-INT-07 事务可见性双向断言）
下月焦点: D 类集中清偿（3 例均为参数名漂移，同批修）
```

## T.05.5 回归防护

- 每个 P 类修复必须新增/加固至少 1 条用例，且该用例在修复提交前验证过"能抓到原 bug"（防"修复无效但测试绿"）。
- 用例库随仓库版本化，变更走评审（与文档同流程）。
- 每月运行一次全量历史失败用例回放（防"修复后又悄悄复发"）。

"能抓到原 bug"的验证方法（回归用例的准入门槛）：

| 步骤 | 动作 | 通过标准 |
| ------ | ------ | ---------- |
| 1 | 在修复前的代码/配置上跑新用例 | 必须 FAIL（抓得到） |
| 2 | 在修复后的代码/配置上跑新用例 | 必须 PASS |
| 3 | 两步都符合才允许随修复提交 | 缺一即退回 |

回归用例设计要点：断言失败信息必须能定位根因（禁止只断言"无异常"）；涉及时序的回归用例须固定种子/时钟；环境类根因（E 类）的回归优先固化为环境预检断言（如磁盘余量、端口占用），而非留给运行时发现。

分类分布统计模板（月度回顾用，数据取自隔离登记与根因记录）：

| 月份 | P | T | E | D | B | 合计 | SLA 达成率 | 最高频类别根治措施 |
| ------ | --- | --- | --- | --- | --- | ------ | ----------- | --------------------- |
| YYYY-MM | 0 | 0 | 0 | 0 | 0 | 0 | - | - |

统计口径：按"定性月份"计数而非发生月份；升级后的类别按最终类别计一次。

## T.05.6 修正 SLA

| 类别 | 定性时限 | 修复时限 | 说明 |
| ------ | ---------- | ---------- | ------ |
| P（严重：数据丢失/一致性破坏） | 24h | 7 天 | 期间禁用相关功能发布 |
| P（一般） | 3 天 | 30 天 | — |
| T / E | 3 天 | 14 天 | 超限自动升 P（流程债也是债） |
| D | 7 天 | 下个治理批次 | 与 CHANGELOG 批次节奏对齐 |
| B | 7 天 | 14 天 | 更新基线须双人复核 |

超时升级路径：超时 1 倍 → 批次负责人例会通报；超时 2 倍 → 升级项目负责人并暂停同类变更合并；P 严重类超时立即升级。

月度回顾清单（每月最后一个工作日，30 分钟）：

- [ ] 当月失败用例分类分布统计（P/T/E/D/B 各多少）
- [ ] SLA 达成率与超时项清单
- [ ] 隔离区账龄清点（>30 天项处置）
- [ ] D 类文档修正的三联动检查完成率
- [ ] 本月新增"能抓到原 bug"的回归用例数
- [ ] 下月焦点：最高频失败类别的一项根治措施

## T.05.7 检查清单
