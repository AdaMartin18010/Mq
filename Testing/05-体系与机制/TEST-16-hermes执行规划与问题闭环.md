## T.16.1 执行规划（时刻表/优先级/资源预算）

### 执行时刻表

| 触发 | 时刻（本地） | 范围 | 产物 |
| ---- | ---- | ---- | ---- |
| 每次提交 | pre-commit（秒级子集）+ CI E0 八步 | 静态门禁全量 | results/<date>/ + history log |
| nightly | 21:00（CI 03:17 已配，本地互补） | E1/E2 冒烟（mq-smoke 三系统）+ 任务包 dry-run | nightly-YYYY-MM-DD 包 |
| weekly | 周六 10:00 | E2 全量（weekly.yaml）+ 契约行为（Microcks --live 就绪后） | weekly 包 + summary |
| pre-release | 人工触发 | E3 关键集（pre-release.yaml） | 发布门禁报告 |
| 真实执行集中批 | 用户在场约定 | GAME DAY/TC-SEM --live/基准首跑 | failbundle + RTO 趋势 |
| 月末 | 每月末（hermes 生成，人审） | **L4 月度验收汇总**：`monthly-acceptance.py` 聚合 E0 history+nightly/weekly SUMMARY+registry 流转+用户门 → `results/acceptance-YYYY-MM.md`（批次197） | 周期覆盖率 ≥80% 判定；连续两月 <80% 升级人审 |

### 优先级与资源预算

| 级 | 用例族 | 时限要求 | 资源上限【估算】 |
| ---- | ---- | ---- | ---- |
| P0 门禁 | E0 八步、E2 冒烟 | 阻塞提交/夜间告警 | E0 ≤5min；冒烟 ≤25min |
| P1 周期 | weekly 全量、契约行为、语义样例 | 当周修复 | E2 ≤60min |
| P2 深度 | 混沌/GAME DAY/基准 | 随集中批 | 按场约定 |
| 隔离 | quarantined | 周会评审（TEST-13） | 0（不计入分母） |

降级顺序（资源不足时）：P2 让位 P1，P1 让位 P0；E3 缺席不阻断 E0-E2（T.09.4 口径）。

## T.16.2 问题闭环 SOP

```text
① 发现    执行失败 → 产物归档（failbundle，T.11.5）
② 初判    hermes-diagnose 打标签（容器/端口/积压/假阳性/镜像/磁盘）
③ 分类    TEST-05 五分类：P 产品 / E 环境 / D 文档 / T 用例 / B 基准
④ 分级    TEST-11 L0-L3：报告 / 可逆清理 / 配置修复 / 人工审批
⑤ 处置    按级执行；L3 走模板 B 审批单
⑥ 回归    同场景重跑 ≥1 次 + 关联用例集（drift 链）
⑦ 回流    案例入库（§T.16.4）→ 相应资产更新：
   assertions 增补 / registry 状态流转 / warn-ledger 登记 /
   doc 修正（走 L3） / 决策注册表补录
⑧ 关闭    history log 记一行闭环记录（时间/分类/动作/结论）
```

时限【论证】：P0 类 24h 内初判；P1 类当周；P2 随集中批。超两时限自动升级一级（报告对象升一级）。

## T.16.4 案例库回流

案例库 `Testing/05-体系与机制/cases/`（见同目录 README）：每个案例 = 现象→诊断→根因→处置→回流动作五段式，按 `YYYY-MM-<slug>.md` 命名。月度回顾（TEST-06）时做案例聚类（同根因 ≥2 例即提预防项）。案例同时是 04-04 混沌工程与 DYN-A2 断言标定的实证素材。
