# 02-payment-reconciliation 语义标注

| 维度 | 为什么需要 | 涉及消息 | 验收关注点 |
| ---- | ---- | ---- | ---- |
| 交付语义 | 支付指令不可丢 | PaymentInitiatedCmd | 重试同幂等键仅一次扣款（金额类幂等，最严等级） |
| 幂等去重 | 重复扣款=资损 | 全部 | 双层去重 + 对账兜底三件套（技术/业务/资金） |
| 持久化 | 资金事件须可回放审计 | 全部 | broker 重启后事件序列完整（T.14 持久化格） |
| 顺序性 | 状态推进依赖完成事件序 | PaymentCompletedEvent | 同 paymentId 单分区有序 |

**设计陷阱**：

1. 对账差错事件**不要**走自动 DLQ——资金差错需人工确认，通道隔离 + 显式 evidenceHash 是合规要求（02-50）。
2. accountRef 脱敏在**进入消息前**完成，broker 层不落明文（PII 最小化）。
